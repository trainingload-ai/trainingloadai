# Plans and Workouts

Trainingload.ai treats the plan as an active workspace, not a static PDF. A plan contains dated or relative workouts; each workout can carry machine-readable structure, human notes, expected load, execution status, and links to completed activities.

  Goal[Goal and constraints] --> Plan[Plan]

## Plan states

- **Draft** — editable plan under construction. Use it for review before execution.
- **Active** — current plan with a start date and daily execution context.
- **Paused** — temporarily stopped while preserving the plan and its history.
- **Completed** — intentionally finished plan.
- **Canceled** — plan ended without being completed as intended.

Read [Plan Lifecycle](/docs/planning/plan-lifecycle) before changing the state of a plan that already has completed activity links.

## Workout structure types

### Endurance

Endurance workouts contain warm-up, work, recovery, repeat, and related steps with time or distance prescriptions and optional targets such as zones, pace, speed, power, cadence, or heart rate.

Use the [manual workout editor guide](/docs/planning/manual-workout-editor) for in-app visual editing, the [Workout Editor & Builder](/workout-editor) to draft a public session, or the [Workout DSL](/docs/planning/workout-dsl) for compact text rules.

### Strength

Strength workouts contain exercises and set groups. Work can be prescribed by repetitions or time, with open load, fixed weight, percent of 1RM, bodyweight, effort, and rest where supported.

Use [Strength Workouts](/docs/planning/strength-workouts) for the visual workflow or [Strength Workout DSL](/docs/planning/strength-workout-dsl) for step-by-step Rules mode.

## Expected versus actual load

Expected load is calculated only when workout structure, thresholds, and target information provide enough signal. Actual load comes from the completed activity and configured load-source priority.

The two values answer different questions:

- Expected: “What stress did this plan intend?”
- Actual: “What stress did the completed session produce?”

Do not force an expected-load value by inventing a threshold or target. An explicit unknown is safer than false precision.
