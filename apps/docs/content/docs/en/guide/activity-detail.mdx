# Activity Detail

Use activity detail to understand one completed workout. It brings together the recorded activity, route, charts, sport-specific metrics, and available coach review. Start with the source and summary, investigate a specific effort, then compare the evidence with the workout's purpose.

[Open the 10 km race demo](https://demo.trainingload.ai/en/activities/17921623926005309429). It opens a real activity in a read-only demo account. You can inspect its tabs and charts. Saving changes requires your own account.

## Before you begin

- Import or record an activity and wait for processing to complete.
- Confirm the activity's sport and date. Check your unit system and relevant thresholds in your profile.
- Use an activity containing the data you want to examine. A heart-rate analysis needs heart-rate samples, power analysis needs power data, and the route needs GPS.
- To compare planned and completed training, identify the intended plan workout and its activity association.

An activity with summary values alone can still be reviewed, but it may have fewer charts. Available tabs depend on the sport and recorded data.

## 1. Open the activity and check its source

Open **Activities**, select a workout, and check its title, sport, start time, source, distance, and duration. You can also reach an activity from search, the map, calendar, or its linked plan workout.

If processing is still running, wait before judging missing charts. An activity can appear before every analysis is ready.

| Processing state | What to do |
| --- | --- |
| Analyzing | Wait for the activity to finish processing, then refresh. |
| Ready | Continue reviewing the available data. |
| Partial failed | Check which analysis is missing and use the completed portions. |
| Failed | Check the file and failure information before retrying or importing again. |

## 2. Choose the view for your question

On desktop Web, the analysis tabs sit below the route. Start in **Overview**, then open the tab that matches your question. On mobile, use the detail and chart views available for that sport. The synchronized Timeline described below is a desktop Web workflow.

| View | Use it to investigate | Data or scope |
| --- | --- | --- |
| Overview | Session summary, available data charts, weather, and sport-specific context | Fields depend on the activity. |
| Timeline | A point or a selected segment across synchronized charts and the route | Running or cycling with usable time-series data on desktop Web. |
| Laps | Compare recorded laps and their summary metrics | Available when the activity provides laps and the sport supports the view. |
| Best efforts | Find sustained efforts by distance or duration and examine their statistics | Availability depends on the sport and recorded streams. |
| Heart Rate | Cardiovascular response, zones, and supported derived metrics | Requires heart-rate data for the corresponding analysis. |
| Power | Power output, zones, and efficiency-related metrics | Requires the corresponding power data. Estimated power is labelled. |
| Pace | Pacing and pace-related analysis | Shown for supported running activities. |
| Running Dynamics | Recorded technique-related measurements | Running with the relevant sensor streams. |

Swimming and other sports have their own detail policies. A missing tab can reflect the sport or missing data rather than a processing failure.

## 3. Inspect an effort in context

To investigate a climb, surge, or interval, open **Timeline**. Locate a point to compare the readings, or select a range to examine its average, minimum, and maximum values alongside its route section.

Follow [Analyze a Workout with Timeline](/docs/guide/activity-timeline) for the complete selection workflow, chart configuration, and analysis segment editing.

Use **Laps** to compare the device's recorded laps. Use **Best efforts** when your question is about the strongest sustained work. In Best efforts, switch between distance and time where offered. **Edit columns** controls which available statistics appear and their order. Selecting an effort's first column or value locates its route section when location data is available.

## 4. Read intensity and training load

Check the available pace, heart-rate, and power analysis with the activity's sport and thresholds in mind. The load source matters when comparing sessions.

- Power-based load uses power and the applicable threshold.
- Running pace-based load depends on the available pace, terrain, and threshold context.
- Heart-rate-based load uses the available heart-rate record and profile settings.
- Other load methods can apply when those signals are unavailable.

Read [Training Load](/docs/metrics/training-load) for the supported concepts. Check [Profile, Thresholds, and Zones](/docs/guide/profile-thresholds-zones) when zones or intensity look implausible.

In supported heart-rate analysis, aerobic decoupling compares the output-to-heart-rate relationship across the activity. Use [Aerobic Decoupling](/docs/metrics/heart-rate/aerobic-decoupling) to check its conditions before interpreting Pw:Hr or Pa:Hr. A variable or interrupted workout needs different context from a steady effort.

## 5. Add route and plan context

Use the route to relate effort changes to terrain. Hills, stops, and environmental conditions can explain changes in pace or heart rate. Without GPS, use the remaining recorded evidence.

If the session belongs to a planned workout, check the association in the calendar or plan. Verify that it is the intended session before comparing planned content, completion, and load. Correct an incorrect association before requesting a plan review. Follow [Manage an Active Plan](/docs/guide/manage-active-plan) for the association workflow.

## 6. Read the coach review or ask a focused question

The **Coach review** section shows the available AI review state. If the page asks you to review data sharing, complete that choice before using AI with your own data. Processing or a review request can also still be pending. Use the displayed retry action when a request fails.

When continuing with AI Coach, include the activity and question. Useful starting points include whether the workout matched the planned intensity, what changed late in the session, and how the activity fits recent training. Verify the activity, date range, and evidence used in the answer before applying a proposed plan change.

See [AI Coach](/docs/guide/ai-coach) for the review and confirmation workflow.

## Verify your review

You should be able to identify the activity and its data source, explain the effort you inspected, and state which recorded signals support your conclusion. For planned training, check the linked workout. Write down any missing sensor data or uncertain interpretation before making the next training decision.

## Common questions

### Why are some charts or tabs missing?

Check processing status, sport, and sensor coverage. Summary-only files do not provide the same analysis as files with recorded samples. Desktop Web and native mobile also expose different detail workflows.

### Why does a value differ between views?

Check the unit, selected range, and calculation being displayed. Timeline's range statistics describe the full or selected range, while a cursor reading describes one sample. Recorded lap summaries and recalculated analysis segments can also use different inputs.

### Why is the route missing?

The file may lack GPS, privacy handling may remove location data, or the map request may have failed. Inspect the available charts and the map's error state separately.

### Can I edit the demo activity?

The public demo lets you inspect the example. Activity edits, saved analysis segments, and plan changes require an appropriate signed-in account.
