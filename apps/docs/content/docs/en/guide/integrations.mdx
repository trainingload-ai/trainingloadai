# Training App Integrations: Strava Garmin COROS Sync

Choose where to import your training records from, then decide whether you need ongoing sync or a one-time history import. This page covers Cloud connections; follow [Connect a platform](/docs/guide/connect-third-party-platforms) for the steps.

For self-hosting, use the separate [Intervals.icu settings](/docs/self-host/configuration#connect-intervalsicu) and [Garmin Personal API guide](/docs/self-host/garmin-personal-api), or upload activity files directly.

Provider availability and supported directions can change. Use the controls shown in the connection dialog as the final authority.

## Before you connect

- Sign in to the provider account that owns the training data you want to import.
- Decide which platform will be the primary source for each activity. Avoid forwarding the same workout through two connected services.
- Check whether you need a continuing connection, a one-time history import, or a file upload.
- Keep provider credentials and API keys available, but enter them only in the official connection dialog.
- Note the newest activity currently shown in Trainingload.ai so you can recognize the first successful import.

## Connect a provider

1. Select the provider card.
2. Read the requested data directions and settings.
3. Authorize through OAuth or enter the required API key.
4. Save synchronization preferences.
5. Run the initial sync when the dialog offers it.
6. Open Activities and verify the newest imported workout.

Never paste a provider API key into AI Coach, plan notes, or support screenshots. Use only the provider connection dialog. Stored secrets are not displayed back to the client.

## Initial sync versus automatic sync

An initial sync imports an eligible recent window or starts a historical job. Automatic sync handles future provider events. Some providers also expose a manual reconciliation action for missed notifications.

During a large import:

- Let the current batch finish before starting it again.
- Expect activities to become visible at different times as items process.
- Review duplicate detection instead of repeatedly reconnecting.
- Check source data when a sensor stream is missing.

## Garmin historical import

On the Garmin page, **OAuth** receives new activities and authorized health summaries. **File import** supplies older training records. These are separate actions; choose the one you need.

## How do planned workouts sync with Intervals.icu?

These are workouts scheduled on your calendar, not completed activity recordings. In the Intervals.icu connection settings, you can turn on **Import planned workouts** and **Export planned workouts** separately.

- **Import planned workouts** brings additions, edits, and deletions from Intervals.icu into Trainingload.ai.
- **Export planned workouts** sends additions, edits, and deletions from Trainingload.ai to Intervals.icu.

**With both directions on, deletions sync too.** If the other copy has not changed since the last sync, deleting one copy also deletes the other.

### What happens when I add, edit, or delete a workout?

This table assumes both directions are on:

| What you do | What happens on the other side |
| --- | --- |
| Add a workout in Trainingload.ai | A corresponding new workout appears in Intervals.icu. |
| Add a workout in Intervals.icu | A corresponding new workout appears in Trainingload.ai. |
| Change only the Trainingload.ai date, name, or prescription | The corresponding Intervals.icu workout is updated. |
| Change only the Intervals.icu date, name, or prescription | The corresponding Trainingload.ai workout is updated. |
| Delete a workout in Trainingload.ai | The Intervals.icu copy is deleted if it has not changed. If it has changed, the edited copy is kept. |
| Delete a workout in Intervals.icu | The Trainingload.ai copy is deleted if it has not changed. If it has changed, the edited copy is kept. |

### Which version wins if I edit both copies?

It depends on the direction currently being synchronized:

- Importing from Intervals.icu uses the Intervals.icu version.
- Exporting to Intervals.icu uses the Trainingload.ai version.

Daily automatic sync imports before exporting. If both copies have already been edited when that run starts, the Intervals.icu version takes priority.

To avoid overwriting an edit, finish editing on one side, allow it to sync, and then continue on the other side.

### Why is one copy still there after I delete the other?

The remaining copy was edited after the last sync. Those edits are kept, the two workouts stop updating each other, and sync does not immediately recreate the workout you deleted.

For example, you delete Sunday's run in Intervals.icu after moving its Trainingload.ai copy to Saturday. Trainingload.ai keeps the Saturday run; the deleted Intervals.icu workout does not reappear because of it.

If the system cannot confirm whether the other copy has changed, it keeps that copy rather than risk deleting it. Completed or skipped workouts, and workouts linked to an actual activity, also retain the history that needs to be kept.

### What if I delete a workout and create another with the same name?

The recreated workout is a new workout and syncs separately. Even matching names, dates, and prescriptions do not reconnect it to a deleted workout. Repeated notifications about the same workout do not create extra copies.

### Why hasn't the other side updated yet?

Both pages do not update instantly together. The system receives provider notifications and checks upcoming workouts periodically. Daily automatic checks cover yesterday through the next seven days in your time zone.

Moving a workout outside that date range does not by itself mean it was deleted: its current location is checked separately. A temporarily unavailable connection also does not cause the other copy to be deleted.

## Disconnecting

Disconnecting stops future synchronization and removes the active credential. It does not normally delete activities that were already imported. Delete an activity separately only after verifying that it is not the sole copy you want to keep.

## Verify the connection

- The provider card shows connected state where applicable.
- A manual sync returns a completed or queued result rather than an authorization error.
- Imported activities identify the expected source.
- Reopening the dialog shows the saved synchronization settings.

## Troubleshooting

### Authorization returns to a disconnected card

Confirm that you approved every requested permission and that the browser returned to the same Trainingload.ai account. Retry from the provider card rather than reusing an old authorization URL. For an API-key connection, replace an expired or revoked key in the dialog.

### The connection succeeds but no activity appears

Check the eligible date window and activity type shown by the provider. Run the available manual or initial sync once, then allow the import job to process. If the source is outside the supported window, export it as FIT, TCX, or GPX and use file upload.

### The same workout appears more than once

Identify the source shown on each activity. Keep one primary route—for example, direct COROS import or COROS forwarded through Strava—and disable the duplicate path before importing more history. Review the duplicate warning before deleting either copy.

### Heart rate, power, GPS, or strength details are missing

Open the workout in the source platform first. Trainingload.ai cannot import a stream the provider did not expose. If the source contains it, wait for processing to finish and then retry the provider's reconciliation action when available.

### A control described here is not shown

The connection dialog is authoritative for the current account, provider, and platform. Some actions depend on provider approval, subscription level, or rollout status.

## FAQ

### Which training app integrations does Trainingload.ai support?

Strava, Polar, COROS, Intervals.icu, Suunto, and Wahoo can stay connected. Garmin offers an OAuth connection for new data and file import for history. FIT, TCX, and GPX cover one-off files or unsupported watches.

### Strava integration or Garmin import?

Use Garmin OAuth for new Garmin workouts and history import for older records. If the same workouts also reach Strava, choose one primary import path to avoid duplicates.

### Can I enable two integrations for the same watch?

You can, but you should not import the same recording twice. Pick one primary route—for example COROS direct, not COROS plus Strava forwarding—before you run a large backfill.

### Where do I complete the connection?

On the web, click your avatar in the top-right corner, then scroll down to **Third Party Connections**. On mobile, open **Me → Menu → Data authorization**. Then follow [Connect Strava, Garmin, and COROS](/docs/guide/connect-third-party-platforms) for provider-specific steps.
