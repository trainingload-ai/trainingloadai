# Connect Training Data

Import a completed workout into Trainingload.ai, then check its date, source, and details. Choose a platform connection, file upload, or phone recording according to where the original record is saved.

[Browse activities in Demo](https://demo.trainingload.ai/en/activities). Importing files or authorizing a provider requires your own account. The upload screenshot uses a sample account in the real app.

## 1. Choose a source

| Route | When to use it | Verify afterwards |
| --- | --- | --- |
| Supported platform connection | A source platform stores the activities you want to import or synchronize | Its offered direction, date range and job result, then the imported activity. |
| Original FIT, TCX or GPX file | A specific workout, an archive, or a source without a usable connection | Per-file inspection and import-batch result. |
| Mobile recording | You record a workout with the Trainingload.ai app | The finished recording's synchronization and resulting activity. |

For provider capabilities and authorization, use [Platform Connection Options](/docs/guide/integrations) and [Connect Third-Party Platforms](/docs/guide/connect-third-party-platforms). Use the operations actually offered by your deployment and account. A one-time history import and ongoing synchronization are different capabilities.

## 2. Set one primary route for a known workout

Identify the date, sport and approximate duration of one source workout. If the same session passes from a device into several services, choose which route should supply it before starting a bulk backfill.

Keep the original recording available. A converted or summary-only file can contain different fields from the original FIT export. Activity import requires an activity recording; an all-day health-only export is a different data type.

## 3. Import through the chosen route

### File upload

1. Open **Activities** and choose its upload entry.
2. Select the original file and wait for the format inspection.
3. Check the detected format and any validation error. An extension alone does not establish the actual file format.
4. Continue with upload and inspect any duplicate prompt.
5. Follow the per-file results in the batch-progress dialog. Reopen the recent batch if you closed the dialog.

Use [Upload Activity Files](/docs/guide/upload-activity-files) for the complete inspection, duplicate and batch-state workflow.

### Platform synchronization

Open the platform's connection settings, read the offered data direction, complete authorization and run its initial import or synchronization when provided. Wait for that job's result, then locate the known workout in Activities.

Synchronization requirements and backfill ranges differ by provider. An account marked connected does not prove that the expected historical workout has already arrived. Enter credentials only in the platform's connection flow.

### Mobile recording

Finish and save the recording, then let the app synchronize it. Check recovery or pending-upload state before starting another recording of the same workout. Follow [Mobile Recording](/docs/guide/mobile-recording).

## 4. Distinguish import progress from activity analysis

| What you see | What to check |
| --- | --- |
| An import item is queued or being processed | Wait for its terminal result in the import batch. |
| Done or an activity link | Open the activity and inspect its own analysis state. |
| Skipped as a duplicate | Confirm which existing activity matched. |
| Partial failure | Identify which file or analysis failed and use the available results. |
| Failed | Read the item's error before retrying the original file or provider operation. |

An activity can appear before every chart or derived metric finishes. Missing sensor data, a processing request failure and an unsupported source file need different responses.

## 5. Verify the recorded activity

Check source, sport, local date, duration and distance. Then inspect only the measurements the recording actually contains.

| Source evidence | What it can support |
| --- | --- |
| GPS samples | A recorded route and location-based context. |
| Heart-rate samples | Heart-rate charts and supported derived analysis. |
| Power samples | Power charts and threshold-based analysis. Estimated power is labelled separately. |
| Usable time-series records | Detailed charts, timeline inspection and range statistics where supported. |

A source connection cannot supply measurements that were never recorded or shared. If an expected field is missing, compare the source platform and original file before repeating the import.

## 6. Connect the activity to daily use

Open [Activity Detail](/docs/guide/activity-detail) to review it. Use the calendar to check its local date and associate it with the intended planned workout. Then inspect [PMC](/docs/guide/pmc-forecast) using the relevant sport and available history.

Activity synchronization does not by itself mean that sleep, HRV or every all-day health measurement was imported. Check each available data category separately.

## Check the result

The known workout should appear once through the intended route, with a clear import and analysis result, the correct source and date, and sensor coverage you can explain. If it belongs to a planned session, confirm the link after checking its identity.

## Common questions

### A provider is connected but the activity is missing

Check its supported range, source account, operation result and activity-list filters. Use an offered manual synchronization once, then wait for the job before starting another import.

### The same workout appears twice

Compare source, start time, duration and recording coverage. Investigate duplicate forwarding before deleting a record, especially if one copy is linked to a plan.

### The chart is empty after import

Check activity processing and whether the source contains usable samples. Summary values alone do not provide every chart. Use the displayed retry action for an actual request failure.

### Will disconnecting remove my imported history?

Provider disconnection and activity deletion are separate operations. Read the connection dialog's effect before confirming, then check existing activities independently.
