# Garmin Personal API

Self-host supports connecting Garmin with a Personal API key. Import completed activities and optionally read sleep, HRV, resting heart rate, and other recovery data on your own instance.

This Personal API flow is Self-host only. The managed/closed-source product uses Garmin Developer API instead and does not run Personal API sync jobs.

## Connect your own account

1. Create a key in [Garmin Connect personal API settings](https://connect.garmin.com/app/settings/personalApiToken). Use the corresponding Garmin Connect site for a China-region account.
2. Open **Account → Third-party connections → Garmin → Connection settings**.
3. Choose the account region and check the IANA time zone used by Garmin, such as `Europe/London`.
4. Select activity imports, sleep and recovery reading, and automatic sync as required. Enter the key and connect.
5. Select **Sync now**. Empty dates mean the last 30 days; a historical range can also be selected.

Trainingload.ai does not need your Garmin password or browser cookies. The key goes only to your own Server and is encrypted in its database. Never post it in chat, issues or logs. Regions are not switched automatically.

Garmin displays a new key once. Keys can expire after 30, 90 or 180 days, or one year; replace expired or revoked keys. The Server exchanges the key for an access token lasting at most 24 hours. There is no OAuth refresh token. [Official FAQ](https://developer.garmin.com/gc-developer-program/personal/personal-faq/)

## Data and local behavior

| Data | Local behavior |
| --- | --- |
| Completed activities | Download original ZIP files, safely extract FIT/TCX/GPX, then use the existing activity import and deduplication pipeline |
| Sleep, HRV, resting heart rate and steps | Ingest recognized fields with explicit units; missing values stay missing |
| Weight, stress, oxygen and Body Battery | Preserve vendor meaning without replacing local ATL, CTL or TSB |
| Heart-rate zones, fitness age and hydration | Read by date through advanced tools; do not automatically change local athlete settings |
| Nutrition and menstrual data | Excluded from scheduled sync; advanced reading requires separate confirmation |

Empty data can reflect device support, missing records or upstream access. Field mappings still need real-account samples; mock tests do not prove support for every device.

Advanced reading covers the data types in Garmin's documented GET catalog. An activity's `workouts` endpoint describes training performed within that completed activity, not future-workout creation. [Official Swagger](https://developer.garmin.com/gc-developer-program/personal/swagger-docs/)

## History, progress and failures

- Automatic activity checks run approximately every 30 minutes; health checks approximately every 6 hours, when enabled.
- Dates use the account time zone. Absolute timestamps are stored in UTC; health date labels are not shifted again.
- Queued means the request was saved. An activity counts as imported only after download, parsing and local processing complete.
- Jobs survive page reloads and Server restarts. Rate-limited work waits; failures retain stable codes.
- Oversized, traversing, nested or ambiguous activity archives are rejected.
- An expired token is exchanged and a read retried at most once. Use **Replace key or reauthorize** if needed; provider failure does not sign you out of Trainingload.ai.
- Activity discovery uses the selected `startDate`–`endDate` window with offset pagination (up to 99 per page), not one calendar day per list call.
- FIT download uses `Accept: application/zip, application/x-zip-compressed, application/octet-stream`. Sending only `application/zip` yields HTTP 406.
- A new sync rechecks activity details and original files to update the same source. Removal requires complete pagination, two missing observations at least 30 minutes apart, and an explicit not-found response from activity details. Other sources remain intact.
- Health sources are retained independently. Explicit empty data updates the corresponding daily metric scope. Permission errors, not-found responses, unknown layouts and mismatched dates preserve existing values and report errors; other successfully read resources can still be imported.

A history request may span up to ten years. Duration depends on activity volume and provider limits. Discovered records are not the same as successfully imported activities.

## Read-only personal use

Garmin positions Personal API for access to your own data. This connector is for a single Owner's personal instance, not a commercial service collecting other users' keys. [Official introduction](https://developer.garmin.com/gc-developer-program/personal/personal-api/)

The documented personal API provides no workout-writing or webhook contract. Trainingload.ai does not use an unofficial account-login library to invent these capabilities.

## Disconnect and backups

Disconnecting removes the current credentials and stops future connector jobs while keeping imported records. Files already handed to the shared import pipeline may finish processing. Delete those records through activity or account data controls when required.

Backups contain encrypted credentials and require the original instance integration key on restore. Disconnecting cannot erase offline backups. No Garmin-specific host environment variable is added; do not put your personal key in a shared `.env.selfhost`.
