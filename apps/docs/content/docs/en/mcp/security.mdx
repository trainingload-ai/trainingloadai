# MCP security and privacy

When you connect TrainingLoad MCP, the AI client you authorize can read training summaries and answer questions. MCP is read-only: it cannot change activities, plans, competitions, profile values, or account settings.

## You choose the permissions

During connection, the client opens the TrainingLoad authorization page. Check the client name and requested data permissions before approving. You do not need to give the client your TrainingLoad password or an API key.

Each request checks the current account authorization. A client can read only the data you have authorized. Missing permissions, expired access, or a temporary service problem produces a corresponding error.

Health data needs the separate `health:read` permission, which is not included by default. You can revoke a client's access from your account.

## What the client can read

Tools return summaries needed for training questions, such as activity duration, training load, plan completion, and metric trends. Activity and plan queries are limited to records belonging to your authorized account.

MCP does not return email addresses, internal user IDs, precise GPS, raw sensor streams, third-party credentials, or complete FIT files. Lists and date ranges have limits, so a client may need several requests to read a longer training history.

## Activity notes are data, not instructions

Activity names, descriptions, workout names, and competition notes are treated as training records. The service cleans unsafe text and instructs clients not to follow commands or links embedded in those notes.

## How health data should be used

The health tool supplies a reduced daily wellness summary to support training analysis. It is not a medical diagnosis or a substitute for assessment by a qualified professional.

## Request limits and troubleshooting records

The service may limit requests that are too frequent or ask for too much data at once. The client should follow the error guidance, narrow the date range, or wait before retrying.

The service keeps troubleshooting information such as tool name, result status, error code, duration, and request ID. User and client identifiers are pseudonymized. These records do not contain access tokens or complete request or response contents.

## If you suspect unwanted access

Revoke the client's access from your TrainingLoad account, then report the concern through the website's support channel. Include the approximate time, client name, and request ID if one was shown. Do not send access tokens or complete health records.
