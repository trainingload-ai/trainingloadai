# 自托管还是云服务

Trainingload.ai 云服务和自托管解决的是不同的运维需求。两者的训练工作流可以相似，但安全、可用性、升级和恢复由谁负责，差别很大。

## 快速对比

| 问题           | 云服务                             | 自托管 v1                                                              |
| -------------- | ---------------------------------- | ---------------------------------------------------------------------- |
| 开始使用       | 注册账号后使用托管服务             | 准备受支持的宿主机，验证签名发行包并安装                               |
| 日常维护       | 由 Trainingload.ai 维护服务        | 由你监控宿主机并执行升级                                               |
| 结构化数据     | 存储在托管服务中                   | 存储在声明的数据目录内的 PostgreSQL 中                                 |
| 上传文件       | 使用托管存储                       | 保存在你声明的数据目录内                                               |
| AI             | 使用托管产品的配置和账号用量规则   | 默认关闭；Owner 提供供应商 API Key，并直接承担供应商费用               |
| 会员与 AI 积分 | 使用云端会员、积分余额和积分补充包 | 不启用 Trainingload.ai 会员计费或积分包；实际 API 用量由 AI 服务商结算 |
| AI 数据路径    | 由托管服务配置决定                 | 只有启用 BYOK AI 后，请求才会发送给所选供应商                          |
| 第三方能力     | 以托管产品和账号实际提供为准       | 仅支持用户自己的 Intervals.icu API Key；其他第三方同步和社交登录关闭   |
| Apple Watch    | 托管产品支持                       | v1 不支持；不会注册手表配对、首页快照和训练上传接口                    |
| 可用性         | 由 Trainingload.ai 运维            | 单实例部署，不内置高可用和自动故障转移                                 |
| 备份与恢复     | 由托管服务负责                     | 由你创建、转移、保留并演练可验证备份                                   |
| 升级           | 托管发布                           | 由你验证目标发行包、备份并执行受支持的升级流程                         |

## 适合选择云服务的情况

- 希望以最短路径开始使用；
- 不想维护 PostgreSQL、存储、TLS、监控和备份；
- 托管集成能力比控制宿主机更重要；
- 没有人能够持续负责升级和恢复演练。

## 适合选择自托管的情况

- 结构化数据和上传文件必须保存在自己控制的设备或磁盘；
- 能够维护受支持的宿主机并及时安装安全更新；
- 可以接受 v1 的单实例拓扑；
- 能把可验证备份保存到独立故障域，并定期测试恢复；
- 希望使用自己的 AI 供应商 API Key，或者完全关闭 AI。

## 必须理解的边界

自托管不会让外部 AI 供应商变成本地服务。Owner 启用 OpenAI、DeepSeek、OpenRouter、阿里云百炼或其他兼容 API 后，相关 AI 请求会离开本机，并按照该供应商的条款处理。

自托管 Server 使用独立的构建入口和 Dockerfile。发行镜像不包含 Trainingload.ai 云端使用的支付 Controller、Webhook、对账任务或 Creem/Waffo SDK；`BILLING_PROVIDER` 也不能在自托管镜像中重新开启这些能力。

Intervals.icu 也是显式的出站连接。每个用户可以在 Client 中填写自己的个人 API Key；活动、计划课、wellness 或运动设置只会按该用户启用的同步选项发送或读取。自托管不启用 Intervals.icu OAuth、webhook，也不提供 Strava、Polar、COROS、Suunto、Wahoo、Garmin 账号连接或社交登录。

原生 Apple Watch App 不在自托管 v1 的支持边界内。自托管 Server 不会初始化 Watch 设备凭据，也不会暴露手表配对、首页快照或训练上传接口。

自托管 v1 也不包含自动高可用、自动备份、自动升级或数据库零停机迁移。这些是实例管理员的责任，不是隐藏的后台服务。
