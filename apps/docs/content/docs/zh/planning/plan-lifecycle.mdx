# 计划生命周期

计划状态决定 Trainingload.ai 将一份日程视为尚在编排的草稿、当前训练上下文、暂时中止的安排，还是历史记录。

## 修改计划状态前

- 打开目标计划并核对名称、目标、日期和当前状态。
- 保存或放弃另一台设备上仍未完成的课程编辑。
- 结束或删除计划前，检查已完成、已跳过和已关联课程。
- 计划包含有意义历史时，优先修改生命周期状态而不是删除。

## 草稿

创建、导入或审核计划时使用草稿状态。草稿课程可以继续修改，也不会被当成运动员当前正在执行的日程。

激活前确认：

- 目标和日期范围。
- 开始日期与训练周的对应关系。
- 每周节奏及恢复间隔。
- 运动类型和训练结构。
- 依赖阈值的训练目标。
- 第一周是否符合运动员当前能力。

## 激活

激活后，计划会进入执行上下文，并用于每日视图、活动关联、预期负荷和智能教练复盘。

1. 打开计划详情。
2. 选择**激活**。
3. 按提示选择计划开始日期。
4. 检查计划中的相对日期如何映射到真实日历。
5. 确认激活。

**验证结果：**计划状态应显示为进行中，课程应出现在预期的日历日期。

## 暂停与恢复

当计划暂时不应指导每日训练，但仍需保留时选择暂停。常见原因包括生病、旅行、伤病评估或有意安排的休整。

暂停不会删除已经完成的活动或课程关联。恢复前检查剩余日期和负荷是否仍然合理；必要时直接调整计划，不要假装中断从未发生。

## 完成

训练周期按预期结束时完成计划。结束前回顾完成率、实际与预期负荷、关键活动关联，以及哪些经验需要带入下一个周期。

完成不同于取消：即使有部分课程被跳过，只要计划到达了有意设置的终点，也可以视为完成。

## 取消

计划不再继续执行，也不应表示为按原意完成时选择取消。如果原因会影响未来训练决策，应在计划或教练记录中保留上下文。

## 删除

删除比切换生命周期状态更具破坏性。只要计划属于有意义的训练历史，就优先使用完成或取消。只有误建或可以丢弃的草稿才应删除，并在确认框中核对目标记录。

## 单节课程的执行状态

进行中计划里的课程可以按工作流标记为完成、跳过或其他状态。关联真实活动是另一份独立证据：课程状态记录计划决策，活动关联记录哪次真实训练完成了这节课。

## 并发修改

计划更新带有版本检查。如果另一个设备或智能教练操作在当前页面加载后修改了计划，请刷新页面并核对新版本后再重试，避免旧页面静默覆盖更新的训练决策。

## 验证状态修改

- 计划详情显示预期的新状态。
- 当前计划、今日和日历页面反映同一执行状态。
- 原有课程完成状态和活动关联仍然保留。
- 暂停或取消后，计划不再指导当前执行，但历史没有被重写。
- 完成后的计划作为有意结束的训练阶段保留。
- 新激活计划的第一周映射到预期日历日期。

## 故障排查

- **无法激活：**补齐必填计划字段，检查日期范围，并确认是否有其他计划状态规则阻止激活。
- **课程出现在错误日期：**对照激活开始日期、计划相对日偏移、账号时区和日历日期。
- **当前计划不是预期记录：**返回计划列表比较状态，只激活真正要执行的计划。
- **暂停或恢复没有同步到其他页面：**刷新另一台设备上的今日、日历和计划详情。
- **更新提示版本冲突：**重新加载计划，并在最新版本上再次执行决定。
- **删除被阻止或风险过高：**需要保留历史时使用取消或完成；只删除确认框中明确指向的可丢弃草稿。
