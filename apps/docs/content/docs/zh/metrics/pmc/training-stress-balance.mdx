# 什么是状态（TSB）

训练压力平衡 **状态（TSB）** 是体能（CTL）与疲劳（ATL）的差值，用于表示模型化近期负荷相对较慢的长期负荷所处的位置。

“状态”是便于理解的界面标签，有些资料也称为“清新度”或 Form。TSB 不是传感器测量值，也不直接测量准备度、恢复、健康或表现。

## 状态（TSB）的数值来源

TSB 没有独立的活动负荷输入。Trainingload.ai 会先使用同一组每日负荷分别计算当日 CTL 和 ATL，再计算两者的差值：

- CTL 使用默认 42 天时间常数，反应较慢。
- ATL 使用默认 7 天时间常数，反应较快。
- 两者都依赖活动数据、阈值和负荷来源优先级，因此其中任一项重算都可能改变 TSB。
- TSB 与 CTL、ATL 使用相同的模型负荷尺度，不是百分比，也不是生理单位。

## 公式

Trainingload.ai 采用与 Intervals.icu 一致的当日值口径：

```text
TSB_today = CTL_today − ATL_today
```

例如，当日 CTL 为 50、ATL 为 65 时，TSB 为 `50 − 65 = −15`。

不同平台的日期口径不完全相同。Intervals.icu 使用当日 CTL 减去当日 ATL；TrainingPeaks 的公开说明使用昨日 Fitness 减去昨日 Fatigue 来表示今天的 Form。因此比较不同平台数值时，必须先确认公式、时间常数、负荷来源和日期口径一致，不能只比较同一日期显示的数字。

## 如何理解状态（TSB）

- **TSB 为负**：当日 ATL 高于 CTL，表示模型化近期负荷高于较慢的长期负荷水平。
- **TSB 接近零**：两条指数负荷曲线接近，不代表生理上的训练与恢复恰好平衡。
- **TSB 为正**：当日 ATL 低于 CTL，表示模型化近期负荷低于较慢的长期负荷水平。

负荷增加时，ATL 通常比 CTL 上升更快，TSB 因而下降；休息或减量时，ATL 通常比 CTL 衰减更快，TSB 因而上升。正负号描述的是负荷关系，不代表运动员感觉一定好或坏。

## 适合回答的问题

TSB 可以帮助回答：

- 模型化近期负荷高于还是低于长期趋势？
- 恢复周或减量是否按预期改变了两条负荷曲线的关系？
- 负荷构建期的变化是否能由计划和来源活动解释？
- 当前负荷关系是否与主观状态、表现趋势和课程完成质量一致？
- 与个人过去的可比较周期相比，当前处于怎样的负荷上下文？

TSB 无法单独回答：

- 运动员是否已经达到比赛或测试准备状态？
- 负值是否有效、安全或危险？
- 正值是否最佳，或是否代表训练不足？
- 需要休息几天，或下一节训练应当如何调整？
- 疼痛、生病或表现下降是否由训练负荷造成？

## 不要追逐通用 TSB 区间

“巅峰”“最佳训练”“高风险”等区间通常来自特定平台或教练经验，并不是跨运动项目、跨负荷算法和跨运动员都成立的生理阈值，也不是 Trainingload.ai 的安全保证。

对个人有用的范围取决于负荷计算方式、运动类型、训练历史、赛事要求、个体响应和数据质量。更可靠的做法是比较同一名运动员在口径一致的历史周期中，TSB 与实际表现、主观状态和课程完成质量之间的关系。

## 在构建期和减量期使用 TSB

在负荷构建期，TSB 下降可能完全符合计划。重点是确认下降来自预期课程，并继续检查训练完成质量、主观疲劳、睡眠、疼痛和生病信号。

在恢复周或赛前减量期，TSB 上升说明近期模型负荷下降得比长期负荷更快。它可以确认计划产生了预期的负荷方向，但不能证明疲劳已经消除，也不能证明运动员一定能在比赛日达到最佳表现。

做决策前，应同时查看[体能（CTL）](/zh/docs/metrics/pmc/chronic-training-load)、[疲劳（ATL）](/zh/docs/metrics/pmc/acute-training-load)、来源活动、表现趋势和主观状态。
