# 连接训练数据

Trainingload.ai 需要已完成训练，才能分析执行情况、训练负荷和恢复状态。你可以通过平台同步接入数据，也可以直接上传活动文件。

## 开始前

- 确定哪个平台作为新活动的主要来源。
- 除非准备处理重复活动，不要同时连接多个会转发同一设备活动的服务。
- 确认来源账号中存在预期训练和传感器字段。
- 使用文件导入时，保留未经修改的原始 GPX、TCX 或 FIT 文件。

## 选择导入方式

持续自动导入使用平台连接；历史归档、不支持的记录来源或单次重试使用文件上传。

各平台的连接和断开步骤见[连接第三方训练平台](/zh/docs/guide/connect-third-party-platforms)；通过[平台连接与活动导入](/zh/docs/guide/integrations)比较所有接入方式；文件操作见[上传活动文件](/zh/docs/guide/upload-activity-files)。

## 数据进入后会发生什么

导入的训练会经过一条处理流程：

1. **接收** 来源活动或文件。
2. **标准化** 成统一的活动格式。
3. **检查重复**，避免重复上传造成历史混乱。
4. **生成活动**，写入你的账号。
5. **构建分析数据**，用于图表、地图和指标。
6. **计算训练指标**，包括负荷、配速、功率、心率和 PMC 信号。

## 平台同步

如果你连接了支持的第三方平台，新活动可以自动进入 Trainingload.ai，不需要每次手动上传文件。

适合使用平台同步的场景：

- 你平时在其他平台记录训练。
- 希望近期活动自动出现在 Trainingload.ai。
- 希望智能教练和训练计划使用最新完成数据。

如果同步活动缺少某些数据，先检查原始平台。心率、功率、GPS、海拔缺失，通常来自原始设备、文件或授权权限。

## 文件上传

适合使用文件上传的场景：

- 你手上有 GPX / TCX / FIT 文件。
- 你想导入历史训练。
- 这次训练不是在已连接平台记录的。
- 你需要重试或测试某个特定活动。

具体步骤见：[上传活动文件](/zh/docs/guide/upload-activity-files)。

## 数据质量检查

为了获得更好的分析结果，活动文件最好包含：

- 准确的开始时间和时区。
- 距离和时长。
- 户外路线的 GPS 轨迹。
- 心率数据：用于心率区间、TRIMP、EF、有氧脱钩。
- 功率数据：用于 FTP、CP、NP、VI 和功率 TSS。
- 海拔数据：用于 GAP、NGP、路线分析和爬升上下文。

## 接入后的数据会用于哪里

处理完成后，训练数据会出现在：

- **活动**：列表、搜索、详情页、图表和地图。
- **概览**：概览卡片和趋势视图。
- **PMC**：CTL、ATL、TSB 等负荷指标。
- **训练计划**：实际活动可以关联回计划课次。
- **智能教练**：复盘可以引用真实完成训练。

日常活动管理见：[活动列表与搜索](/zh/docs/guide/activity-feed-search)。

## 连接 Suunto

打开 **账户 → 第三方连接 → Suunto**，点击 **使用 OAuth 连接**。在 Suunto 完成训练数据授权后，Trainingload.ai 会排队导入近期训练。后续新训练优先通过 Suunto 通知导入，并由定时同步进行补偿核对。

你可以随时回到 Suunto 设置弹框，手动同步、关闭自动同步、重新授权失效连接或断开账户。断开连接只会停止后续同步，不会删除已经导入的活动。

## 验证连接

- 连接卡片显示预期账号和已连接状态。
- 一条已知近期训练只在活动列表出现一次，并标记正确来源。
- 活动进入已就绪状态，或显示明确的处理失败原因。
- 活动详情包含来源实际提供的传感器数据。
- 断开连接或关闭自动同步不会删除已经导入的活动。

## 故障排查

- **授权后仍显示未连接**：从连接卡片重试，并确认来源账号已经授予训练数据访问权限。
- **没有活动进入系统**：执行支持的手动同步、扩大活动日期范围，并确认来源中存在符合条件的训练。
- **同一次训练出现两次**：删除活动或调整导入方式前，先确定哪些连接重复转发了它。
- **传感器字段缺失**：检查来源平台的原始活动；连接无法导入来源没有提供的数据。
- **连接已经失效**：重新授权，不要通过反复上传同一活动制造副本。
