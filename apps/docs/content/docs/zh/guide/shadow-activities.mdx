# 影子活动：为什么只有摘要？

**影子活动，是已经发现、但还没有取得完整记录的活动。** Trainingload.ai 先保留它的标题和开始时间，让你知道这次活动没有被遗漏，并显示下一步可以做什么。

影子活动还不是一条已完成导入的完整活动。我们不会根据摘要编造训练曲线或负荷结果；成功取得详细记录后，影子活动会被完整活动替代。已经导入的完整记录不会因为某次重新同步取不到数据而被清空。

目前主要有以下两种情况。

## 情况一：Intervals.icu 有活动信息，但不能提供原始文件

Intervals.icu 可以展示从 Strava 转入的活动摘要，但它的接口可能明确限制这类活动的原始文件。你能在 Intervals.icu 中看到这次活动，并不意味着 Trainingload.ai 能从它的接口取得完整记录。

这种情况下，Trainingload.ai 会尝试直接从 Strava 获取。按卡片上的提示连接 Strava、恢复授权或开启活动导入，然后等待同步完成。

如果 Strava 也没有提供所需数据，影子活动会继续保留。单纯重复同步 Intervals.icu 不能绕过它对原始文件的限制。

## 情况二：Strava 有活动详情，但取不到流数据

活动名称、总距离、总时长等详情，与每个时间点的 GPS、心率、功率或距离记录，是两类不同的数据。**有活动详情，不代表一定有可供导入的流数据。**

- **原本就没有逐点记录**：例如，在 Strava 手动填写距离和时长，没有上传设备记录。详情页可以存在，但反复同步不会生成缺失的记录。
- **暂时取不到记录**：例如，来源仍在处理，或详细数据接口暂时不可用。一次“未找到”不能证明活动已删除，也不能确定它永久没有流数据。

无法确认原因时，Trainingload.ai 会先进行有限次数重试；仍然取不到数据时，就保留影子活动，并提供“重新同步”。只有心率、功率或 GPS 中某一项缺失，并不一定会形成影子活动：只要仍有可用的活动时间序列，活动可以正常导入，只是部分分析不可用。

## 我该怎么做？

| 你看到的情况                         | 建议                                               |
| ------------------------------------ | -------------------------------------------------- |
| 提示连接来源、重新授权或开启来源导入 | 先完成对应设置，再等待同步或尝试重新同步。         |
| 活动刚上传，或来源平台仍在处理       | 等来源处理完成后，再同步一次。                     |
| 来源曾临时不可用，现在已经恢复       | 可以再同步一次，尝试取得完整记录。                 |
| 手动填写的活动，从未有逐点记录       | 不必反复同步，寻找设备或最初记录平台上的原始文件。 |
| 多次尝试后仍是影子活动               | 检查原始平台能否导出活动文件；需要时联系支持。     |

“重新同步”会再次向来源请求数据，并不保证来源已经能提供数据。无需先删除影子活动或已有完整活动，也不要反复解绑和绑定来尝试生成缺失记录。

## 我有原始文件

如果设备或最初记录平台仍能导出包含活动记录的 FIT、TCX 或 GPX 文件，可以使用[上传活动文件](/zh/docs/guide/upload-activity-files)。导入时留意重复提示，已有完整活动时先核对日期和内容。

## 仍然需要帮助

请提供活动日期、来源平台、界面提示，以及你是否能够从原始平台导出文件。不要发送访问令牌或密码。更多步骤见[故障排查](/zh/docs/guide/troubleshooting)。
