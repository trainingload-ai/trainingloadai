# 连接 Strava、Garmin 与 COROS：同步训练分步指南

本页是**连接 Strava**、导入 Garmin 历史、以及 COROS、Polar、Suunto、Wahoo、Intervals.icu 的操作说明：去哪里授权、保留哪些同步选项、怎样证明第一条训练已经进来。多数平台用 OAuth；Intervals.icu 也支持 API Key；Garmin 是一次性历史导入，不是长期在线连接。

## 开始前

- 登录真正保存目标训练的平台账号。
- 为每条设备训练只选一个主要导入路径。例如，不要同时通过 COROS 直连和 Strava 转发导入同一条 COROS 记录。
- 记住 Trainingload.ai 当前最新的一条活动，便于识别首次导入结果。
- 先决定个人资料、区间、活动导出和计划课程分别以哪个平台为准。
- API Key 和临时下载链接只能输入对应的 Trainingload.ai 连接弹窗。

## 打开“连接”页面

网页端打开**账号 → 第三方平台连接**，再选择平台卡片。

移动端打开**我的 → 账号 → 连接**。OAuth 会在系统浏览器中打开平台授权页，批准后再返回 App。Strava、Polar、COROS、Suunto、Wahoo 和 Intervals.icu 可以在移动端管理；Garmin 历史导入需要使用网页端。

部分平台需要对当前部署开放接口。如果页面没有 COROS 卡片，说明当前尚不可用，可先上传 FIT、TCX 或 GPX 文件。

| 平台          | 网页端 | 移动端 | 授权方式            | 常见首次操作           |
| ------------- | ------ | ------ | ------------------- | ---------------------- |
| Strava        | 支持   | 支持   | OAuth               | 按选择导入最近 60 天   |
| Polar         | 支持   | 支持   | OAuth               | 按选择导入最近 30 天   |
| COROS         | 支持   | 支持   | OAuth               | 分别同步活动和健康数据 |
| Intervals.icu | 支持   | 支持   | OAuth 或 API Key    | 导入近期活动           |
| Suunto        | 支持   | 支持   | OAuth               | 首次导入近期训练       |
| Wahoo         | 支持   | 支持   | OAuth               | 连接、保存方向后同步   |
| Garmin        | 支持   | 不支持 | Garmin 临时导出链接 | 启动一次历史导入任务   |

## 连接 Strava

1. 打开**连接 → Strava**。
2. 授权前选择是否立即导入最近 60 天。
3. 选择后续数据方向：
   - 自动导入新的 Strava 活动；
   - 把 Trainingload.ai 中非 Strava 来源的活动上传到 Strava；
   - 从 Strava 导入运动员资料和区间；
   - 把 Trainingload.ai 的运动员资料和区间上传到 Strava。
4. 点击**连接 Strava**，在 Strava 批准权限并返回 Trainingload.ai。
5. 重新打开 Strava，确认设置已经保存；需要补偿核对时再执行一次**立即同步**。

除非已经明确哪一端覆盖另一端，否则不要同时打开资料导入和资料导出。新活动自动同步依赖 Strava 通知，手动同步用于补偿核对，不应反复拉取同一时间段。

如果 Strava 同时也是你唯一的登录方式，系统可能暂时不允许断开。请先设置密码或连接另一个登录账号，避免失去 Trainingload.ai 账号访问权。

## 连接 Polar

1. 打开**连接 → Polar**。
2. 选择是否立即导入最近 30 天。
3. 如果 Polar 是持续来源，打开新活动自动同步。
4. 需要 Polar 支持的日常活动、连续心率和睡眠数据时，再打开健康数据同步。
5. 点击**连接 Polar**，在 Polar Flow 批准权限并返回 Trainingload.ai。
6. 如果近期记录仍未出现，重新打开弹窗，只执行一次**立即同步**。

Polar 手动同步检查的是支持的近期窗口，并不是完整账号归档。Polar 是唯一登录方式时，也要先增加密码或其他登录方式才能断开。

## 连接 COROS

1. 打开**连接 → COROS**并完成 OAuth 授权。
2. 卡片显示已连接后，点击网页端的**同步活动**，核对训练记录。
3. 点击网页端的**同步日常数据**，或移动端的**立即同步健康数据**，单独核对日常/健康数据。
4. 查看卡片上的最后同步状态和错误信息。

COROS 的活动与日常数据是两个独立操作。活动同步成功，不代表健康数据同步也已执行。如果页面没有 COROS 卡片，则当前部署尚未开放该连接。

## 连接 Intervals.icu

一般优先使用 OAuth；只有明确需要时再使用 API Key。

### 使用 OAuth

1. 打开**连接 → Intervals.icu → OAuth**。
2. 在 Intervals.icu 授权，并返回同一个 Trainingload.ai 账号。
3. 选择需要的数据同步方向。
4. 保存设置，只执行一次首次或手动同步。

### 使用 API Key

1. 从你自己的 Intervals.icu 账号创建或复制 API Key。
2. 打开**连接 → Intervals.icu → API Key**。
3. 把 Key 粘贴到受保护输入框并连接。
4. 账号已经使用另一把 Key 时，确认是否替换。

Trainingload.ai 不会再次显示已保存的完整 Key，连接后只显示末四位。API Key 与 OAuth 相互替换不会删除已导入历史，但未来同步将使用新凭证。

根据当前开放的功能，弹窗可能提供：

- 每日自动同步活动；
- 从 Trainingload.ai 导出活动；
- 导入或导出运动员资料和区间；
- 导入或导出计划课程。

请为区间和计划课程分别确定唯一数据源。如果两个平台都自动双向写入同一对象，后续更新可能覆盖你想保留的修改。

## 连接 Suunto

1. 打开**连接 → Suunto**。
2. 选择需要的数据方向：自动导入训练、健康数据、导出已完成活动和导出计划课程。
3. 发起 OAuth，并在 Suunto 批准训练数据访问。
4. 返回 Trainingload.ai，等待近期训练的首次导入。
5. 需要修改设置或补偿核对时，重新打开弹窗并执行**立即同步**。

新训练通常通过 Suunto 通知进入，定时同步负责补偿核对。健康数据可以包含平台支持的心率、步数、睡眠和恢复信息。断开后会停止后续交换，但不会删除已导入训练。

## 连接 Wahoo

1. 打开**连接 → Wahoo**。
2. 选择需要的数据方向：自动导入训练、导出已完成活动、导出计划课程、导入资料或导出资料。
3. 发起 OAuth，在 Wahoo 批准权限并返回 Trainingload.ai。
4. 保存设置；如果一条已知近期活动缺失，再执行一次**立即同步**。

没有先确定哪一端负责资料值时，不要同时打开资料导入和导出。重新连接前，先查看弹窗中的最后同步与最后错误。

## 在移动端管理平台

移动端和网页端使用同一个已保存连接，因此一端修改的设置会影响另一端。

1. 打开**我的 → 账号 → 连接**并选择平台。
2. Strava 或 Polar 在授权前显示首次同步选项时，先完成选择。
3. 在系统浏览器中授权，并允许它返回 App。
4. 重新打开平台，配置当前支持的数据方向。
5. 点击**保存设置**；只有需要补偿核对时才点击**立即同步**。
6. COROS 的活动和健康数据需要分别同步。

Intervals.icu 使用独立的移动端设置面板；Garmin 历史导入是网页端专属流程。

## 导入 Garmin 历史

Garmin 历史导入是一次性归档流程，不是持续运行的 Garmin 连接。

1. 在网页端打开**账号 → 第三方平台连接 → Garmin**。
2. 从弹窗打开 [Garmin 官方数据导出页](https://www.garmin.com/account/datamanagement/exportdata/)并申请导出。
3. 等待 Garmin 邮件。通常约需 48 小时，也可能更久。
4. 选择一种导入方式：下载 Garmin 完整导出 ZIP 后直接上传，或复制邮件中**下载**按钮背后的链接。
5. 在 Garmin 历史导入弹窗中选择**上传文件**或**使用 URL**，然后点击**开始导入**。大型导出包通常使用 URL 更省时。
6. 回到弹窗查看排队、下载、扫描、导入、完成、部分失败或失败状态。
7. 完成后，对照发现、排队、已导入和重复数量是否符合预期。

导出 URL 相当于一份临时下载凭证。不要把它粘贴到聊天、智能教练、Issue 或截图中。Trainingload.ai 只接受 Garmin 托管的安全链接；任务等待期间会加密保存，并在归档下载后移除。直接上传的 ZIP 同样只用于本次导入，并在扫描后删除。

## 登录账号不是训练连接

**登录账号**下的 Google、Apple 和 GitHub 是身份验证方式。连接后可以用它登录，但不会导入训练、健康数据、计划或区间。删除最后一种可用登录方式前，系统可能要求先设置密码或连接另一个账号。

## 验证每个平台连接

完成连接后：

1. 确认平台卡片显示**已连接**。
2. 重新打开，确认所选设置已经保存。
3. 最多执行一次首次或手动补偿同步。
4. 打开**活动**，找到一条已知近期训练，并确认来源平台正确。
5. 打开活动详情，确认来源确实提供了预期心率、功率、GPS 或海拔。
6. 对双向能力只做一次无风险测试修改，确认只有预期目标发生变化。

OAuth 成功返回并不等于活动已经导入。授权、数据接收和活动处理是三个不同阶段。

## 故障排查

| 现象                       | 检查方法                                                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| OAuth 返回后仍显示未连接   | 从平台卡片重新发起，批准全部必要权限，并确认浏览器返回同一个 Trainingload.ai 账号。不要重复使用旧授权 URL。              |
| 已连接但近期活动没有出现   | 检查平台首次同步窗口，执行一次手动同步，等待处理，并按日期与来源搜索活动。更早记录可能要使用文件上传或 Garmin 历史导入。 |
| 同一训练出现两次           | 查看两条记录的来源，在继续导入前关闭其中一条转发路径。                                                                   |
| 缺少心率、功率、GPS 或海拔 | 打开来源平台的原始活动；平台未向外提供的数据流无法被导入。                                                               |
| 页面没有平台卡片           | COROS 可能取决于平台批准或功能开放状态，暂时可使用文件上传。                                                             |
| Intervals.icu 无法替换 Key | 确认新 Key 属于目标账号，并明确批准替换凭证。                                                                            |
| Garmin 拒绝链接            | 改为上传下载好的 ZIP；或复制邮件“下载”按钮背后的 URL，不要复制邮件页面地址，并确认链接仍是安全的 Garmin 托管地址。       |
| 无法断开连接               | 如果该平台同时是唯一登录方式，先设置密码或增加另一个登录账号。                                                           |

## 常见问题

### 怎样连接 Strava？

打开**账号 → 第三方平台连接 → Strava**，选择是否立即导入最近 60 天和后续数据方向，再完成授权。返回后重新打开 Strava，如最新训练未出现，执行一次**立即同步**。

### 连接 Garmin 之后会持续同步吗？

不会。这里的 Garmin 是按官方导出做一次性历史导入，不是长期在线连接。导入之后的新训练，请走 Strava、COROS 等持续连接，或上传 FIT / TCX / GPX。

### 怎样连接 COROS 或 Polar？

在对应卡片完成授权，再跑第一次同步。COROS 的活动同步和每日/健康同步是分开的，一边成功不代表另一边也跑过。Polar 可导入最近 30 天，并可选择健康数据。

### 为什么同一条训练出现两次？

两条导入路径转发了同一条记录，例如 COROS 直连再加 Strava。每条设备训练只留一条主路径，再继续回填历史。
