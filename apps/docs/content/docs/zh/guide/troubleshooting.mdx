# 故障排查

从可观察到的现象开始。确认失败阶段前，不要急着反复连接平台、删除活动或重建计划。

## 登录或授权循环

确认设备可以访问服务，并在启动授权的同一浏览器会话里完成 OAuth。断开某个登录方式前，先确保账号还有其他可用登录方式。

## 同步活动没有出现

1. 确认来源平台里确实存在这条训练。
2. 检查平台连接状态。
3. 如果支持，执行一次手动同步或补偿同步。
4. 等待当前导入批次完成。
5. 按日期和运动类型搜索活动。

不要连续断开再重连；这可能只会产生重叠任务，无法修复来源权限问题。

## 活动出现但分析不完整

活动可能先入库，再生成派生图表。处理完成后刷新。如果只缺某一类指标，检查原始数据流：心率分析需要心率采样，功率分析需要功率采样，地图需要 GPS，配速和距离分析需要有效距离与时间。

## 指标看起来不正确

依次检查运动类型、单位与时区、阈值及生效日期、区间模型、负荷来源优先级和原始活动数据。不要为了让单次训练“看起来正确”而反复调阈值。

## 课程无法保存

耐力课程需要有效步骤、时长或距离和受支持目标。力量课程需要：

- 至少一个动作。
- 每个动作都有名称。
- 每个动作至少有一个组方案。
- 每个动作至少包含一组正式组。

编辑器会保留无效草稿，并显示本地化校验提示。

## 计划已在其他地方改变

版本或状态冲突表示页面加载后，其他设备或智能教练操作已经修改计划。刷新并检查最新版本，再重新应用修改，不要盲目重复旧请求。

## 移动记录没有完成同步

仍有恢复可能时，不要卸载应用或清空本地数据。重新打开记录页面，让应用恢复会话并连接网络。参见[移动端运动记录](/zh/docs/guide/mobile-recording)。

## 智能教练无法完成请求

缩短过长请求或分阶段执行；确认计划或活动仍然存在；检查智能教练用量；结构化操作校验失败时，先用普通文字重新说明意图。无法看懂修改前后对比时，不要应用调整。

## 提交有效问题信息

提供大致时间与时区、网页端或移动端、系统和版本、具体页面流程、安全的活动或计划 ID、完整本地化错误文案，以及隐藏个人数据后的截图。

不要提供密码、OAuth Token、API Key 或精确家庭位置。
