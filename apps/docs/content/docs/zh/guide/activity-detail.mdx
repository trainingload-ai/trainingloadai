# 活动详情

活动详情页用于解释一次已经完成的训练。它帮助你从“我上传了一个文件”，走到“我知道这次训练产生了什么影响”。

你可以从这些地方进入活动详情：

- 活动列表。
- 活动搜索。
- 地图。
- 日历或单日页面。
- 训练计划中已关联的课次。

## 复盘前

- 尽量等待活动进入已就绪状态。
- 确认运动类型、开始时间、时长和距离基本合理。
- 判断强度前，先检查相关阈值和区间是否仍然有效。
- 如果训练来自计划，打开或关联原本要完成的计划课程。

## 推荐复盘顺序

每次活动都按相同顺序查看：

1. 检查处理状态和源数据。
2. 阅读汇总指标，了解本次训练的整体规模。
3. 查看时间序列，理解训练过程如何展开。
4. 确认哪个信号产生了负荷估算。
5. 加入地形和计划上下文后再形成结论。

## 处理状态

活动导入后不一定立刻完成分析。处理流程可能包括文件标准化、重复检查、时间序列准备和指标计算。

常见状态：

- **Analyzing**：仍在分析，图表和衍生指标可能不完整。
- **已就绪**：活动可以正常查看。
- **Partial failed**：活动存在，但部分分析可能缺失。
- **Failed**：文件无法处理。

如果活动还没 ready，不要急着判断图表或指标缺失，先等待处理完成。

## 汇总指标

活动顶部通常会展示核心字段，例如：

- 运动类型。
- 开始时间和时区。
- 距离和时长。
- 移动时间和总耗时。
- 爬升。
- 平均/最大心率。
- 平均/最大功率。
- 配速或速度。

具体字段取决于运动类型，以及文件里实际包含哪些数据。

## 图表和时间序列

活动图表用于解释训练过程。根据数据不同，你可能会看到：

- 配速或速度。
- 心率。
- 功率。
- 步频/踏频。
- 海拔。
- 坡度。

用图表可以发现配速漂移、冲刺、爬坡、停顿或传感器异常。

## 训练负荷与强度

Trainingload.ai 会根据可用数据计算单次训练负荷：

- 功率和阈值可靠时，使用功率 TSS。
- 跑步有配速、地形和阈值配速时，使用 rTSS。
- 心率是主要信号时，使用 TRIMP / hrTSS。
- 数据有限时，使用兜底估算。

相关概念见：[训练负荷](/zh/docs/metrics/training-load)。

## 路线与地形上下文

如果活动包含 GPS 和海拔数据，地形会明显影响配速解读。

- 上坡配速可能很慢，但努力程度很高。
- 下坡配速可能很快，但肌肉骨骼压力很高。
- GAP 和 NGP 可以帮助你把起伏路线和较平路线放在一起比较。

相关概念见：[坡度调整配速 GAP](/zh/docs/metrics/pace/grade-adjusted-pace) 和 [标准化坡度配速 NGP](/zh/docs/metrics/pace/normalized-graded-pace)。

## 关联训练计划

如果这次活动属于某个计划课次，把它关联到对应计划训练。这样才能进行计划执行复盘：

- 计划内容 vs 实际完成。
- 预期负荷 vs 实际负荷。
- 完成状态。
- 带计划上下文的智能教练复盘。

如果关联错了，可以取消关联，再手动选择正确课次。

## 让智能教练复盘

当你需要解释，而不是只看数字时，可以找智能教练。适合这样问：

- “这次训练符合计划强度吗？”
- “为什么后半程心率漂移明显？”
- “这次轻松跑是不是跑太硬了？”
- “下一次训练前应该调整什么？”

## 验证你的结论

采取行动前，确认自己能回答：

- 这次训练原本的目的是什么？
- 哪个数据来源和阈值决定了负荷或强度？
- 图表展示的是真实训练模式，还是传感器/数据问题？
- 如果它来自计划，这次活动是否完成了原定课程？
- 当前证据最多支持哪一个最小决策？

不要因为单个孤立指标异常就立刻修改计划。还要对照近期训练和运动员当前状态。

## 故障排查

- **图表缺失**：等待活动进入已就绪状态，再确认源文件是否包含时间序列数据。
- **负荷明显不合理**：依次检查阈值、运动类型和负荷来源优先级，再比较不同公式。
- **路线缺失**：源数据可能没有 GPS，隐私处理也可能隐藏部分路线。
- **没有计划对比**：把活动关联到正确的计划课程，然后刷新详情。
- **只有部分内容可用**：Partial failed 表示部分处理成功；先使用可靠证据，只有确认源文件有效时才重试或重新导入。
