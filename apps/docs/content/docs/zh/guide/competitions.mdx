# 比赛管理

比赛事件独立于训练计划存在。这样，比赛可以影响计划决策，但不必被伪装成一节普通训练课程。

## 开始前

- 确认官方比赛日期、本地开始时间和时区。
- 判断它是低优先级练习赛，还是需要保护的关键比赛。
- 比赛与同日计划课程保持为两条独立记录。
- 只有真实目标明确时才填写目标时间，不要把无依据预测当成目标。

## 添加比赛

打开**比赛**，选择**添加比赛**，填写：

- 比赛名称与日期范围。
- 需要精确开赛时间时，同时设置时间和时区。
- 运动类型和可选细分类型。
- 距离、重要程度、目标类型和可选目标时间。
- 地点与备注。

重要程度用于表达计划应该多大程度地保护这场比赛。不要把所有比赛都标为最高优先级；时间接近的多场关键比赛本身就是需要解决的计划冲突。

## 检查比赛

保存后检查倒计时、日期、运动类型、目标和重要程度。比赛也会出现在相关日历和单日视图中。

系统可以结合比赛窗口和附近计划课程评估当前计划影响，但这只是决策支持，不代表所有冲突课程都会自动删除。

## 处理比赛日冲突

当比赛和计划课程位于同一天：

1. 先确认日期与时区正确。
2. 判断比赛是替代原课程、完成相似训练意图，还是要与一节独立轻松训练共存。
3. 明确移动、跳过或修改原计划课程。
4. 检查比赛前后的强度和恢复安排。
5. 只有在比赛优先级明确后，再让智能教练准备调整草案。

## 安全更新

比赛记录使用版本检查。如果另一个请求已经修改比赛，先刷新并检查最新内容，再重新保存。

## 取消、恢复与删除

- **取消**：保留比赛记录，但不再视为计划中的比赛。
- **恢复**：让已取消的比赛重新生效。
- **删除**：移除记录，只适用于误建或无需保留的项目。

## 验证结果

- 比赛出现在正确年份和日历日期。
- 倒计时和本地时间正确。
- 目标和目标时间内部一致。
- 当前计划处于相关范围时，可以加载比赛影响。
- 比赛日课程冲突清晰可见，没有被静默解决。

## 故障排查

- **倒计时错误**：一起检查比赛日期、开始时间、比赛时区和账号时区。
- **日历没有比赛**：确认比赛未取消，并且当前日期范围包含它。
- **无法加载计划影响**：确认当前计划与比赛窗口重叠，并刷新过期的计划或比赛版本。
- **冲突仍未解决**：明确移动、跳过或修改计划课程；比赛不应静默修改训练计划。
- **更新发生冲突**：刷新比赛，并把修改重新应用到最新版本。
