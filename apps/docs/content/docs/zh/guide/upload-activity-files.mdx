# 上传活动文件

当你有来自手表、码表、训练平台或历史导出的活动文件时，可以使用文件上传。

Trainingload.ai 会把一次上传作为一个导入批次处理，这样你可以清楚看到每个文件的进度和失败原因。

## 上传前检查

确认文件属于支持的活动格式：

- GPX
- TCX
- FIT

上传界面会先通过服务端的 TrackSwap 读取文件内容，识别实际格式、活动数量、圈数和记录点数量。文件扩展名只作为提示：例如内容是 GPX、却被命名为 `.fit` 时，界面会显示 `FIT → GPX`，并按真实内容处理。

为了获得更完整的分析，优先使用设备或平台导出的原始文件。截图、缺少时间序列的 CSV、手动改过的文件，可能没有足够数据生成图表或负荷指标。只包含健康或全天监测数据、没有活动记录的 FIT 文件不能通过活动上传入口导入。

## 格式转换

如果目标平台需要另一种格式，可以先使用 [FIT、GPX、TCX 转换器](/zh/converter)。通用转换器根据文件内容自动识别源格式；指定方向的转换页还会校验实际源格式，避免把误命名文件按错误方向转换。转换响应也会返回 TrackSwap 识别到的源格式。

## 从活动页上传

1. 打开 **活动**。
2. 点击上传入口。
3. 选择一个或多个文件。
4. 确认上传。
5. 查看导入进度弹窗；如果关闭了，也可以从最近导入批次入口继续查看。

如果 Trainingload.ai 检测到可能重复的活动，会先显示重复提示。你可以取消、保留已有活动，或者在确实需要单独副本时强制导入。

## 导入状态

导入过程中，每个文件可能经历这些状态：

- **Queued**：排队等待处理。
- **Normalizing**：转换成内部统一活动格式。
- **Materializing**：创建或更新活动记录。
- **Parquet building**：准备用于图表和分析的时间序列数据。
- **Done**：导入完成。
- **Skipped**：跳过，通常是因为匹配到已有活动。
- **Failed**：文件无法处理。

整个批次可能是完成、部分失败、失败或取消。

## 上传完成后

处理完成后，你可以：

- 从导入弹窗或活动列表打开新活动。
- 检查关键指标是否完整。
- 如果运动类型识别不正确，手动修正。
- 如果它属于训练计划，把活动关联到计划课次。
- 需要上下文复盘时，找智能教练分析这次训练。

后续查看和筛选见：[活动列表与搜索](/zh/docs/guide/activity-feed-search)。

## 验证结果

- 每个选中文件最终都处于 Done、Skipped、Failed 或已取消状态。
- Done 文件只创建一条活动，开始时间、运动类型和时长符合预期。
- Skipped 重复项能够对应到已经存在的活动。
- 活动详情只展示源数据能够支持的指标。
- 确认活动身份后才把它关联到训练计划。

## 常见问题

如果文件失败：

- 从原平台重新导出原始活动。
- 上传前不要手动编辑文件。
- 检查文件是否包含时间序列数据。
- 查看上传项旁的实际格式和扩展名不一致提示。
- 一次只导入一个文件，定位具体失败文件。

如果分析结果不完整，可能是文件缺少心率、功率、GPS、海拔或配速数据。Trainingload.ai 仍可显示活动，但部分指标可能不可用，或者只能估算。
