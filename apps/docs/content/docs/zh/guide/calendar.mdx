# 在日历中对照计划与实际训练

日历把训练安排和实际记录放在同一日期背景中。同日的计划课程与活动仍是两条记录，应通过详情和关联确认，这次记录是否完成了原定课程。

[在 Demo 中打开日历](https://demo.trainingload.ai/zh/calendar)。截图使用真实网页应用中的合成计划与活动数据。在 Demo 中导航到相关日期即可浏览，保存关联或排期变化需要自己的账号。

## 开始前准备

核对账号时区与活动开始时间。使用计划时，检查当前计划开始日期和课程排期。新导入活动应等待处理完成，再判断负荷或分析是否缺失。

以下步骤以网页端为主。窄屏可以使用页面提供的周、月入口和当天面板，移动端使用对应日期与课程入口。

## 1. 定位并选择日期

用前后导航或月份选择器定位日期，也可以回到**今天**。先核对当前周或月，再选择目标日期。

选中日期决定当天面板的内容。一天可以包含计划课程、独立排期训练、实际活动或多种记录，打开前先识别条目类型。

## 2. 阅读当天面板

使用**训练**检查已排课程，使用**活动**检查实际记录。核对日期、显示负荷与条目数量，需要完整当天页面时选择**查看当天**。

| 记录 | 比较前检查什么 |
| --- | --- |
| 计划课程 | 目的、排期日期、运动、结构、备注与执行状态。 |
| 已完成活动 | 开始时间、来源、运动、实际时长与距离、处理及传感器覆盖。 |
| 关联关系 | 正确活动是否真的关联到目标课程。 |

仅有完成标记，还不能识别使用了哪条实际记录。调查真实用力情况时，打开[活动详情](/zh/docs/guide/activity-detail)。

## 3. 把正确活动关联到课程

在自己的账号中打开已排课程详情，选择**关联活动**。

1. 确认课程已排到具体日期，运动类型正确。
2. 先在活动详情核对开始时间，再对照当天候选中的标题和时长，找到对应记录。
3. 选择匹配记录，等待成功反馈。
4. 已关联其他课程时，先阅读**替换关联？**提示，再决定是否替换。
5. 重新打开课程与活动，核对关联结果。

没有候选时，先检查同步、活动本地日期、课程排期与运动，修正差异后再选择对应记录。

关联错误时，可以从现有关联中**解除关联**，或选择正确活动。解除关系与删除活动具有不同效果，Demo 禁用这些写入操作。

## 4. 比较原定目的与实际完成

先比较目的和结构，再看实际时长、距离、强度及可用负荷。缩短、替换或跳过课程时，记录原因。计划外增加的活动也可能是真实训练，应保留其背景。

预计或实际负荷缺失时，先调查数据条件，核对阈值、运动与处理状态。完成、跳过、推迟及其他按状态提供的操作见[管理当前计划](/zh/docs/guide/manage-active-plan)。

## 5. 核对汇总范围

日历可以提供**计划**和**本月**汇总。比较次数、距离、时长和负荷前，先读当前统计范围与显示的日期边界。

计划进度使用当前周期，月份概览使用正在查看的日历月。它们的对比窗口不同，应按页面背景解释数字。

较大范围的复盘见[每周训练复盘](/zh/docs/workflow/weekly-review)，累积负荷与条件预测见 [PMC](/zh/docs/guide/pmc-forecast)。

## 验证结果

选中日期、当天面板和打开的记录应一致。课程与实际活动关联正确，负荷比较能够说明使用的范围和缺失数据。

## 常见问题

### 为什么活动出现在另一日

对照活动开始时间与时区、账号显示时区，再检查计划开始日和课程排期。移动课程前先确认日期。

### 为什么找不到计划课程

检查当前计划、周期范围、具体排期与状态。课程已经移动或跳过时，位置可能与原先预期不同。

### 为什么同一次训练有两条记录

计划课程与实际活动本来就是不同记录，应检查它们的关联。如果同时存在两条实际活动，再调查来源转发和重复导入。

### 为什么 Demo 不能关联活动

Demo 用于检查示例，关联和排期变更需要对应账号权限。

### 修改被拒绝怎么办

读取错误，刷新最新计划或活动状态后再试，并核对目标关联或排期是否真的改变。
