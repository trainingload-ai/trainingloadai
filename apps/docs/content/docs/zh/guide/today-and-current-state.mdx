# 今日与当前状态

移动端的“今日”是每天执行训练的入口；网页端“首页”会用更宽的布局呈现同一账号背景。用它判断当前最需要处理什么、打开计划课程，并确认真实活动已经回到计划中。

## 开始前准备

- 完成新手设置，并登录与网页端相同的账号。
- 设置正确时区，让“今天”和计划日期一致。
- 如果需要看到计划课程，先激活一份计划。
- 等待近期活动完成处理，保证负荷和当前状态卡片已经更新。
- 需要比较计划与实际时，把完成活动关联到课程。

## 1. 把今日建议当作背景

在移动端打开**今日**，或在网页端打开**首页**。建议摘要会使用当前可用的计划、近期活动和负荷背景；它是决策起点，不是医疗许可，也不会自动修改计划。

先检查日期和当前计划是否正确。如果建议过于笼统，等待活动处理、补齐资料，或通过**问教练**提出一个明确问题。

## 2. 打开计划课程

在**训练**区域选择课程，检查：

- 运动、预计时长和状态。
- 页面可用时的课程图表与结构化步骤。
- 教练备注。
- 活动关联状态。

对于仍可执行的耐力课程，**开始计划训练**会携带计划和课程上下文进入记录；受支持的力量课程则进入力量训练执行流程。

如果本地存在未完成记录，应先选择继续、完成并恢复，或丢弃它，再开始新记录。不要为了绕过恢复提示而创建第二份活动。

## 3. 有意识地关联、推迟或跳过

课程操作面板会显示当前有效操作：

- **活动 / 关联活动**：打开已有关联活动，或选择真正完成这节课的活动。
- **推迟**：确认后把符合条件且未完成的课程向后移动一天。
- **跳过**：确认后把计划课程标记为跳过。

推迟和跳过修改的是计划执行状态，不会编辑或删除真实活动。操作后检查当前计划和日历，因为整周衔接可能需要重新复盘。

## 4. 比较本周与上周

把周负荷对比作为调查变化的入口。确认日期边界和运动背景合适，再打开产生数值的活动或 PMC 页面，然后才决定是否修改计划。

本周数值更高或更低，并不能单独说明训练是否成功。还要对照计划负荷、完成质量、主观状态和训练阶段目的。

## 5. 在移动端自定义当前状态

数据可用时，当前状态可以显示 VO2Max、ATL、CTL、TSB、负荷比、单调性、强度、休息天数和周汇总指标。

1. 选择**当前状态**旁的齿轮按钮。
2. 移除不能帮助日常判断的指标。
3. 选择**添加指标**并点选一张指标卡。
4. 长按拖拽图标调整已选指标顺序。
5. 至少保留一个指标，然后选择**完成**。

点选当前状态卡片会打开详情和近期序列；使用**了解**可以进入对应指标文档。

## 6. 跨设备修改后刷新

在今日页面下拉刷新计划、建议、负荷、当前状态和近期活动。网页端修改计划、完成导入或应用智能教练操作后，都应刷新一次。

另一台设备刚保存修改时，不要继续编辑旧计划数据；先确认最新课程日期和状态。

## 验证每日流程

- 今日显示正确账号日期和当前计划。
- 目标课程使用正确运动、结构和状态打开。
- 开始训练会把计划上下文带入耐力记录或力量执行。
- 完成活动只关联一次，并且对应正确课程。
- 推迟或跳过状态也出现在日历和当前计划中。
- 重新打开今日后，当前状态指标选择与顺序仍然保留。
- 刷新后，近期负荷和活动区域已经更新。

## 故障排查

- **没有显示课程：**确认存在当前计划、计划开始日期覆盖今天，并检查课程是否已经移动、跳过或完成。
- **今日日期错误：**修正账号时区，再重启或刷新两端。
- **建议缺失或过于笼统：**等待活动处理，检查智能教练权益与用量，并补充计划和当前状态背景。
- **无法开始训练：**只有符合条件且未完成的课程可以启动；检查状态与运动支持情况。
- **关联了错误活动：**打开活动操作，移除或替换关联，并在确认前核对开始时间和运动。
- **推迟或跳过失败：**刷新计划；基于旧数据的操作可能被版本检查拒绝。
- **当前状态卡片为空：**扩大数据范围、导入受支持活动，并检查该指标需要的阈值或传感器证据。
- **网页端修改没有出现：**下拉刷新，并确认两个设备使用同一账号。
