# 耐力課表 DSL

在**規則**模式中使用此 DSL 來描述單場結構化耐力課表。一份訓練計畫可包含多場課表，每場課表都會獨立解析與驗證。**每一行代表一個步驟**，並由上至下依序執行。

本頁涵蓋跑步、自行車與游泳等耐力步驟。若要規劃動作與組數，請改用[肌力訓練課表](/zh-hant/docs/planning/strength-workouts)結構。

## 開始之前

- 撰寫課表前先選好確切的運動項目；運動項目會決定區間與單位的解讀方式。
- 在使用 `z1`、`z2` 等區間參照之前，請先設定好運動員的配速、功率或心率區間。
- 決定每個步驟是依時間、距離、能量還是感測器條件結束。
- 若不需要文字編輯方式，可直接改用視覺化建構器。

---

## 由左至右撰寫每一行

每一行最多包含三個以空格分隔的部分，順序如下：

| 部分                         | 用途                                                               | 範例                                             |
| ---------------------------- | ------------------------------------------------------------------ | ------------------------------------------------ |
| ① 步驟類型                   | 暖身、主課表、輕鬆恢復、休息、緩和等                               | `warmup`、`work`、`recovery`、`rest`、`cooldown` |
| ② 持續多久／如何結束         | 最前面**僅限一個**「數值 + 單位」：時間、距離、kJ 或心率規則       | `5m`、`3km`、`500kj`、`hr<150bpm`                |
| ③ 強度目標（選填）           | 配速、功率、心率、踏頻／步頻等                                     | `pace …`、`power …`、`hr …`                      |

在 ③ 中**最多只能設定一個目標**。單一步驟可指定配速、功率、心率、踏頻／步頻或坡度，但無法同時指定多項。若有多個目標，請拆分為不同步驟，或將次要提示寫入課表備註。`work: 20m` 與 `work 20m` 等價，冒號為選填。

---

## ① 選擇步驟類型

先寫下以下任一關鍵字，關鍵字不區分大小寫：

| 關鍵字             | 意義                                         |
| ------------------ | -------------------------------------------- |
| `warmup` / `wu`    | 開場暖身                                     |
| `work`             | 主要訓練段落                                 |
| `recovery` / `rec` | 主課表之間的主動恢復                         |
| `rest`             | 靜態休息步驟                                 |
| `cooldown` / `cd`  | 結尾緩和                                     |
| `other`            | 不屬於標準標籤的其他步驟                     |

主動輕鬆恢復請使用 `recovery`，指示休息則使用 `rest`。儲存後的步驟類型會保留此區別，供顯示與匯出使用。

---

## ② 加入結束條件

此部分決定**步驟何時結束**——可依時間、距離、能量或感測器條件。每行只能使用一個主要結束條件；後面出現的 `power` 或 `hr` 屬於強度目標，而非另一個時長。

| 格式                             | 意義                                            |
| -------------------------------- | ----------------------------------------------- |
| `30s`、`5m`、`25min`、`1h`       | 計時時間                                        |
| `5km`、`400m`                    | 距離（`3km` 是 3 公里，並非 3 秒）              |
| `500kj`                          | 自行車累積能量（千焦耳）                        |
| `hr<150bpm`、`power>250W` 等     | 當心率／功率觸及條件時結束此步驟                |

---

## ③ 加入選填目標

全部寫在第一個衡量條件之後，並以空格分隔：

| 關鍵字    | 用途                                                                                                                    |
| --------- | ----------------------------------------------------------------------------------------------------------------------- |
| `pace`    | 跑步配速                                                                                                                |
| `speed`   | 速度（應用程式會顯示配速或 km/h）                                                                                       |
| `power`   | 功率：建議使用**瓦特**（`250W`）；純數字如 `250` 會解析為**瓦特**；舊版 `%FTP`（`85%`）仍相容                           |
| `cadence` | 踏頻／步頻                                                                                                              |
| `hr`      | 心率：**bpm**（`150bpm`、`150-160bpm`、`<150bpm` 或純數字如 `150`）或區間參照（如 `hr z2`）                             |
| `grade`   | 坡度                                                                                                                    |

舊版別名 `pwr`、`cad` 與 `rpm` 仍可解析，但新產生的 DSL 會統一使用完整單字。

DSL 關鍵字、單位與區間代碼皆不區分大小寫：`WORK 25M HR Z2` 與 `work 25m hr z2` 解析結果相同。儲存或重新產生的文字會正規化為小寫關鍵字。

如果想參照運動員目前的區間，而不鎖死固定數值，可以這樣寫：

```text
work 25m hr z2
work 10m power z4
work 20m pace z2
```

這代表「依照運動員目前的 Z2／Z4 區間執行」。日後區間更新時，系統也能以新區間解讀這份課表。若想鎖定確切數值，請改用明確目標，例如 `hr 140-150bpm`、`power 220-250W` 或 `pace 4:30-4:45`。

請將第一個結束條件與強度目標區分清楚：

```text
work hr<150bpm
work 25m hr <150bpm
```

第一行會在心率符合條件時結束，無法再附加其他目標；第二行則持續 25 分鐘，並以心率 150 bpm 作為上限目標。

## `repeat`：重複執行相同的小區塊

```text
repeat 4 {
  work 4m power 270W
  recovery 2m
}
```

- `repeat 4` 會將大括號內的步驟重複執行 **4 次**。
- 大括號中的兩行組成一回合。這個範例會建立 4 回合「270 W 騎乘 4 分鐘 + 恢復 2 分鐘」。部分版本也允許使用 `end` / `endrepeat` 取代 `}`，請以目前編輯器接受的格式為準。

你也可以設定重複直到達成特定條件：

```text
repeat until 30m {
  work 4m power 270W
  recovery 2m
}

repeat until cadence<80rpm {
  work 30s power 300W
  recovery 30s
}
```

`repeat until` 支援時間、距離、卡路里、心率、功率與踏頻條件。系統刻意禁止巢狀重複。若第三方整合無法表示某項條件，必須明確回報不支援或降級處理，而不可靜默更改課表內容。

## 範例 1：跑步

```text
warmup 5m
work 20m pace 7:20-8:20/km
recovery 90s
work 3km
cooldown 5m
```

- `warmup 5m`：輕鬆暖身 5 分鐘。
- `work 20m pace …`：主課表 20 分鐘，配速約 7:20–8:20 / km。
- `recovery 90s`：輕鬆恢復 90 秒。
- `work 3km`：主課表 3 **公里**，而非再跑 20 分鐘。
- `cooldown 5m`：輕鬆緩和 5 分鐘結束。

由上到下即為實際執行順序。

---

## 範例 2：自行車

```text
work 8m power 220-250W
recovery 2m
work 5m hr 150-160bpm
```

- 第 1 行：8 分鐘，220–250 W。
- 第 2 行：2 分鐘輕鬆恢復，不加其他目標。
- 第 3 行：5 分鐘，心率 150–160 bpm。

---

## 範例 3：4 組間歇

```text
repeat 4 {
  work 4m power 270W
  recovery 2m
}
```

重複 4 回合：4 分鐘約 270 W 高強度，接著 2 分鐘輕鬆恢復。若沒有 `repeat`，就得手動貼上這兩行四次。

## 驗證並儲存

1. 在課表編輯器中選擇**規則**。
2. 輸入或貼上 DSL。
3. 若介面提供解析／預覽功能，請於儲存前先執行檢查。
4. 比對正規化文字與視覺預覽是否符合預期的步驟順序。
5. 儲存課表後重新開啟，確認運動項目、時長、重複次數與強度目標皆正確無誤。

儲存後的文字可能會將關鍵字正規化為小寫並統一標準單位。正規化屬於正常現象，但課表原意不應發生改變。

---

## 運動項目與 DSL 支援能力

計畫課表會保留精確的運動項目，例如路跑、越野跑、跑步機、公路自行車、登山車、室內自行車、泳池游泳或開放水域游泳。相關子項目仍共用跑步、自行車或游泳區間與負荷分析，而匯出至 Suunto、Intervals.icu 與 COROS 時會優先對應精確的運動項目。

在 API 中，`sportType` 代表大分類（如跑步、自行車或游泳），`subSportType` 則是標準子類型（例如 `TRAIL_RUNNING` 或 `INDOOR_CYCLING`）。

選單中呈現停用狀態的運動項目，表示結構化編輯器目前尚無法在不遺失原意的情況下表達該項目。它仍可作為活動類型使用，且應用程式不會靜默將不支援的結構轉換成其他課表。

## 驗證課表

- 每個步驟都依輸入順序出現在預覽中。
- 每一行只有一個主要結束條件，且最多只有一個目標。
- 區間參照會依目標運動項目與運動員檔案正確解析。
- 重複區塊包含預期的步驟以及重複次數或結束條件。
- 重新開啟課表後仍完整保留相同結構與運動子類型。

## 疑難排解

- **某一行回報未知關鍵字：** 請改用受支援的步驟類型或目標名稱，並移除語法未列出的標點符號。
- **時間或距離不正確：** 請檢查單位與位置。步驟類型後的第一個衡量值是結束條件。
- **解析器拒絕多個目標：** 每行僅保留一個目標，將次要指引移至備註或拆成另一步驟。
- **以閾值作為結束條件的行無法加入目標：** `work hr<150bpm` 已將心率作為結束條件；若要設定固定時長搭配心率上限，請改寫為 `work 25m hr <150bpm`。
- **重複區塊失敗：** 確認大括號已正確閉合、未使用巢狀重複，並檢查 `repeat until` 條件。
- **切換運動項目後預覽改變：** 區間與單位含義取決於運動項目，請重新選回正確項目並檢查每個目標。
- **匯出時回報降級或不支援結構：** 請先閱讀服務商警告再決定是否簡化，勿假設所有裝置都支援條件式重複。
