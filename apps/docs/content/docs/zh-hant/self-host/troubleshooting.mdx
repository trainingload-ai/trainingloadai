# 自行託管疑難排解

請先從受支援的唯讀檢查開始。務必保留第一個出現的穩定錯誤代碼，這比反覆更動主機直到症狀消失更有診斷價值。

## 第一時間排查

```bash
./self-host status --json
./self-host doctor --json
./self-host logs --tail 200 --service server --service client --json
```

即使 Docker 無法使用，`doctor` 仍會回報可完成的檢查項目。若還原或升級失敗，請保留其報告與未完成標記，切勿刪除標記來強行啟動實例。

## 常見問題

| 症狀                       | 檢查項目                                                                       | 安全的下一步操作                                                               |
| -------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| 安裝程式拒絕發行版本       | 外層校驗碼、Cosign 身分、精確版本與下載檔案是否齊全                            | 從同一個官方發行版本重新下載所有檔案                                           |
| 網站無法開啟               | `status`、客戶端日誌、綁定位址、連接埠衝突與 HTTPS 來源                        | 修正宣告設定後，先執行 `start --dry-run` 再執行 `start`                        |
| 資料庫無法使用             | `doctor` 中的資料庫服務狀態、磁碟空間、權限與遷移結果                          | 恢復主機容量或權限；切勿直接對外暴露或手動編輯 PostgreSQL                      |
| 檔案上傳失敗               | 資料根目錄剩餘空間、inode 容量、檔案擁有權與 uploads 目錄                      | 擴充專用資料磁碟卷並重新執行 `doctor`                                          |
| 看不到 AI 設定             | 部署模式、實例就緒狀態、已登入的擁有者身分                                     | 以已認領的擁有者身分登入；非擁有者無法檢視或變更服務商設定                     |
| AI 請求失敗                | 服務商狀態、確切 Base URL、模型識別碼、金鑰權限與對外 DNS／TLS                 | 修正擁有者管理的設定，或在服務商異常期間先停用 AI                              |
| 還原後 AI 無法使用         | 目標實例是否使用了不同的實例驗證機密                                           | 輸入新的服務商金鑰；切勿嘗試擷取舊的明文金鑰                                   |
| 還原遭到阻擋               | 目標版本、目標權威狀態、備份清單、校驗碼與報告                                 | 使用乾淨且精確版本相符的目標實例，並保留失敗目標以供診斷                       |
| 升級遭到阻擋               | 受支援的來源版本、遷移清單、備份、磁碟空間與回復宣告                           | 依照升級報告處理；切勿手動修改映像檔標籤或遷移紀錄                             |

## 蒐集診斷資訊

當 `doctor` 的輸出不足以定位問題時，執行：

```bash
./self-host diagnostics --output support-<yyyy-mm-dd> --tail 500 --service server --service client --json
```

診斷套件會套用自動遮蔽，但自動遮蔽不代表可以直接公開分享。請務必先在本機開啟檢視，確認是否含有主機名稱、使用者資料、活動細節與業務日誌，再透過維護者核可的私密管道提供。

絕不分享以下內容：

- `.env.selfhost`；
- 擁有者密碼或引導權杖（bootstrap token）；
- 服務商 API 金鑰、Cookie 或私鑰；
- 資料庫傾印或已上傳的活動檔案；
- 未經檢視的診斷套件。

## 務必避免的操作

- 切勿執行 `docker compose down -v`。
- 切勿刪除 PostgreSQL 資料、上傳檔案、資料根目錄標記、操作鎖定檔或未完成生命週期標記。
- 切勿編輯 `_prisma_migrations`、發行清單、校驗碼或升級報告。
- 切勿使用 `--skip-verify` 或可變動映像檔標籤。
- 切勿並行重試會變更狀態的命令。

這些操作可能讓原本可診斷的故障變成無法復原或狀態不明的資料遺失。

## 提供有效證據以升級回報

僅分享精確的發行版本、主機作業系統與架構、穩定的 `error.code`、失敗的命令，以及本機已檢視診斷套件的 SHA-256 雜湊值。除非維護者提供核可的傳輸管道，否則請將完整診斷套件保密。

## 下一步

解除阻擋狀況後，返回[管理你的實例](/zh-hant/docs/self-host/operations)。若復原需要替換資料，請將已驗證的備份還原至全新的乾淨目標實例，而非覆寫失敗的實例。
