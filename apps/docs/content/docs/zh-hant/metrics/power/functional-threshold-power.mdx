# 功能性閾值功率（FTP）

在耐力運動中，**功能性閾值**是貼近「穩定輸出」與「加速疲勞」分界線的實用基準，廣泛用於劃分訓練區間、估算訓練負荷，以及追蹤閾值能力是否隨訓練進步。

實務上最常見的兩個術語分別是單車的 **FTP** 與跑步的 **rFTP**。

## 功能性閾值功率（FTP）

**FTP（Functional Threshold Power）**通常指單車閾值功率，一般定義為**大約能穩定維持 60 分鐘的最高平均功率**。不過在實務中，它是一個會受測試方式、配瓦策略、疲勞與近期訓練影響的估計值。

### 為何重要
- **生理錨點**：FTP 大致對應[乳酸閾值（LT）](/zh-hant/docs/metrics/physiology/lactate-threshold)附近的強度帶。低於 FTP 通常能持續運作很久；高於 FTP 則會迅速累積疲勞。
- **相對強度基準**：不論你的 FTP 是 400 W 還是 150 W，以 FTP 百分比表達強度都能讓課表在同一套框架下對齊個人能力。多數功率訓練計畫皆以 FTP 百分比設計（例如 Zone 2 約為 55–75% FTP）。

### 如何估算 FTP
1. **20 分鐘測試（經典做法）**：全力穩定騎乘 20 分鐘，取平均功率的 95%。
2. **漸增負荷測試（Ramp Test）**：每分鐘逐步拉高目標功率直到力竭，取最後一分鐘平均功率的約 75%。
3. **CP 模型推估**：Trainingload.ai 可從功率—時間曲線（PDC）推算，常採用 `FTP ≈ 0.95 * CP`。

若想直接從活動檔案估算，請使用[FTP 計算機](/zh-hant/ftp-calculator)；若已有不同時段的全力輸出紀錄，則可使用[臨界功率與 W′ 計算機](/zh-hant/critical-power-calculator)同時擬合 CP 與 W′。

## 跑步功能性閾值功率（rFTP）

隨著跑步功率計（Stryd、Garmin、COROS 等）普及，**跑步功能性閾值功率（Running Functional Threshold Power，簡稱 rFTP）**也越來越常見。

它同樣常定義為**大約能穩定維持 60 分鐘的最高平均跑步功率**。

### rFTP 與單車 FTP 的差異
雖然定義相近，但兩者的數字通常**不能直接互換**：
- **數值大小不同**：許多運動員的 rFTP 高於單車 FTP，因為跑步涉及肌腱彈性位能儲存與釋放、徵召更多肌群，且心率通常更高。
- **分開測試與設定**：請勿拿單車 FTP 來設定跑步課表，反之亦然。

### rFTP 與閾值配速的差異
- **rFTP（功率）**：單位為瓦特（W），受坡度與風勢干擾較小（視裝置與演算法而定），往往更貼近真實生理輸出。
- **閾值配速**：單位為 min/km，受地形影響明顯（上坡時即使強度很高，配速仍會變慢）。
  - *註：在平坦無風的路況下，rFTP 對應的配速接近閾值配速；但在起伏地形中，rFTP 通常更具穩定度。*

### 如何估算 rFTP
常見的跑步功率測試協議（例如 Stryd 建議流程）：
- **3/9 測試**：3 分鐘全力跑（接 30 分鐘輕鬆恢復）＋ 9 分鐘全力跑。
- **CP 模型**：透過不同時段（如 30 秒、2 分鐘、10 分鐘）的全力輸出擬合臨界功率；在跑步功率系統中常直接將 CP 作為 rFTP。

## Trainingload.ai 如何運用 FTP

Trainingload.ai 以 FTP 作為功率區間、強度係數（IF）與訓練壓力分數（TSS）的計算基準。若 FTP 設得太低，辛苦課表的負荷會被過度放大；若設得太高，訓練負荷與目標區間則會被低估。

在訓練計畫回顧中，FTP 最能協助回答以下問題：

- 已完成的課表是否落在原訂功率區間？
- 目前計算 TSS 與 IF 所用的閾值是否符合現況？
- 閾值體能是否已有明顯變化，需要更新後續課表目標？
