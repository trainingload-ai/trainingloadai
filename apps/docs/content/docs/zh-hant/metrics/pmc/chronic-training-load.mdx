# 慢性訓練負荷（CTL）：如何建立體能模型

**慢性訓練負荷（Chronic Training Load，簡稱 CTL）**是表現管理圖（PMC）上變化較慢的體能曲線。它代表每日訓練負荷（通常為 TSS）的指數移動平均，預設時間常數為 42 天。Trainingload.ai 也會同步顯示今日 CTL 相對於你歷史最高值的百分比。CTL 彙整的是模型化的歷史負荷軌跡，並非直接量測真實體能、生理適應、健康或比賽表現。

## 體能（CTL）數值從何而來

Trainingload.ai 會先根據每筆活動可用的指標與你設定的負荷來源優先順序，決定該筆活動的訓練負荷。視活動類型與設定而定，來源可能是功率、心率、配速或課表自覺強度（Session RPE）。

這代表：

- 活動資料遺漏或異動都會影響體能（CTL）。
- 修改閾值或負荷來源優先順序，會改變計算出的活動負荷與後續的 PMC 曲線。
- Trainingload.ai 會依設定優先順序為每筆活動選取單一負荷來源；若不同時期混用了尺度不一致的來源，跨期比較的可比性會下降。
- 在沒有記錄活動負荷的日期，當日輸入為 0，前一天的 CTL 會緩慢衰減。

## 計算公式

Trainingload.ai 採用指數時間常數衰減模型，預設 CTL 時間常數為 42 天：

```text
decay_CTL = exp(-1 / 42)
CTL_today = CTL_yesterday × decay_CTL + daily_load × (1 − decay_CTL)
```

其中 `exp` 為自然指數函數。在預設時間常數下，`decay_CTL ≈ 0.976472`，代表今日負荷所佔權重約為 `0.023528`。

## 如何理解體能（CTL）趨勢

- **CTL 上升**：近期每日負荷整體高於目前的 CTL 水準。
- **CTL 平穩**：近期負荷大致維持目前的模型水準。
- **CTL 下降**：近期負荷整體低於目前水準，包含減量訓練或賽前減量期（Tapering）。

## CTL 的適用問題與邊界

CTL 能協助回答：

- 目前的體能（CTL）正在上升、維持還是下降？
- 缺席的課表或恢復期是否改變了長期負荷趨勢？
- 目前的訓練計畫是否正朝預期的負荷方向推進？
- 閾值或負荷來源異動是否影響了跨期可比性？

但單靠 CTL 無法回答：

- 使用者是否已成功產生生理適應？
- 明天的高強度課表是否安全？
- 使用者目前是否已恢復、健康或準備好參賽？
- 某位使用者是否比另一位體能更好？

做出訓練決策前，務必同時考量實際表現趨勢、課表執行品質、主觀體感、[疲勞（ATL）](/zh-hant/docs/metrics/pmc/acute-training-load)與[狀態（TSB）](/zh-hant/docs/metrics/pmc/training-stress-balance)。

## 常見問題

### 什麼是慢性訓練負荷（CTL）？

慢性訓練負荷（CTL）是 PMC 中變化較慢的體能趨勢線，以預設 42 天時間常數對每日訓練負荷做指數平均。當近期每日負荷高於當前 CTL 時曲線上升，低於當前 CTL 時則下降。

### CTL 如何計算？

公式為 `CTL_today = CTL_yesterday × e^(−1/42) + daily_load × (1 − e^(−1/42))`。使用預設常數時，今日負荷權重約 2.35%，昨日 CTL 權重約 97.65%。休息日沒有新增負荷，曲線仍會自然衰減。

### CTL 越高代表體能一定越好嗎？

不一定。CTL 上升僅說明近期模型化負荷足以拉高長期平均值，並不能證明身體已順利適應、處於健康狀態或具備最佳比賽準備度。應搭配實際表現、主觀體感、[ATL](/zh-hant/docs/metrics/pmc/acute-training-load) 與 [TSB](/zh-hant/docs/metrics/pmc/training-stress-balance) 綜合判讀。

### 為什麼改了 FTP 之後 CTL 突然跳動？

CTL 建立在每日負荷之上。一旦更改 FTP、區間設定或負荷來源優先順序，歷史 TSS／TRIMP 輸入也會隨之重算，因此即使沒有新增任何訓練，體能曲線仍可能移動。
