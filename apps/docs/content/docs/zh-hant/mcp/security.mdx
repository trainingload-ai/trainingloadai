# MCP 安全性與隱私權

當您連線 TrainingLoad MCP 後，經您授權的 AI 用戶端可讀取訓練摘要並回答問題。MCP 採用唯讀設計，無法修改活動、訓練計畫、賽事、個人檔案數值或帳號設定。

## 由您決定授與的權限

在建立連線期間，用戶端會開啟 TrainingLoad 授權頁面。核准前請確認用戶端名稱與所請求的資料權限範圍。您無須將 TrainingLoad 密碼或 API 金鑰提供給用戶端。

每次請求都會即時檢查目前的帳號授權狀態。用戶端僅能讀取您已明確授權的資料；若缺少權限、授權過期或遇到暫時性服務問題，系統會回傳對應的錯誤訊息。

健康資料需要額外的 `health:read` 權限，預設並不包含在內。您隨時可從帳號設定中撤銷用戶端的存取權。

## 用戶端可讀取的資料

工具僅回傳回答訓練問題所需的摘要資料，例如活動時長、訓練負荷、訓練計畫完成度與指標趨勢。所有活動與計畫查詢皆嚴格限定於您已授權帳號名下的紀錄。

MCP 不會回傳電子郵件地址、內部使用者 ID、精確 GPS 座標、原始感測器串流、第三方平台憑證或完整的 FIT 檔案。清單筆數與日期範圍皆設有上限，因此用戶端若要檢視較長期的訓練歷史，可能需要分次請求。

## 活動備註屬於資料，而非指令

活動名稱、描述、課表名稱與賽事備註均視為一般訓練紀錄。服務會先淨化不安全的文字內容，並明確指示用戶端不得執行嵌入在這些備註中的任何指令或連結。

## 健康資料的正確使用方式

健康工具提供精簡後的每日身心狀態摘要，僅作為訓練分析的輔助背景資訊，並非醫療診斷，也無法取代合格專業醫療人員的評估。

## 請求限制與疑難排解紀錄

若請求過於頻繁，或單次要求過多資料，服務可能會實施限流。用戶端應遵循錯誤提示，縮小查詢的日期範圍，或稍候再重試。

服務會保留用於疑難排解的稽核資訊，例如工具名稱、結果狀態、錯誤碼、執行耗時與請求 ID。使用者與用戶端識別碼皆經過假名化處理，且紀錄中不包含存取權杖、完整請求內容或完整回應內容。

## 若懷疑有未經授權的存取

請立即從 TrainingLoad 帳號中撤銷該用戶端的存取權，並透過網站的支援管道回報異常。回報時請附上大約時間、用戶端名稱，以及畫面上顯示的請求 ID（如有）。請勿寄送存取權杖或完整的健康紀錄。
