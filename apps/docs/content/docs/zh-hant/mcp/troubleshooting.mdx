# MCP 疑難排解

## 用戶端無法探索伺服器

請確認設定的 URL 完全為 `https://api.trainingload.ai/mcp`（包含尾端的 `/mcp`）。用戶端必須支援遠端 Streamable HTTP。若位於企業網路環境中，網路政策必須放行連往 `api.trainingload.ai` 與 TrainingLoad 授權頁面的 HTTPS 流量。

## OAuth 無法開啟，或返回用戶端時出現錯誤

- 請從用戶端的連線操作重新發起流程，切勿重複使用舊的授權 URL。
- 確認用戶端支援 OAuth 自動探索與 PKCE S256。
- 確認授權回呼（callback）是返回當初發起授權的同一個用戶端執行個體。
- 若授權驗證服務暫時無法使用，請依 `Retry-After` 標頭指示的間隔等待後再重試。

## 找不到某個工具

伺服器會依據帳號方案權益與功能推出開關（rollout flags）篩選 `tools/list`。`get_health_summary` 在尚未授予 `health:read` 前仍會保持可見，以便呼叫時能觸發增量授權。若缺少其他工具，請確認帳號資格與功能開放狀態後重新連線；切勿手動填入 bearer token。

## `INSUFFICIENT_SCOPE`

請使用用戶端的重新連線或重新授權功能，並核准所請求的權限範圍。若用戶端忽略了 MCP 的 `mcp/www_authenticate` 質詢，請先移除再重新新增該連線，讓用戶端重新請求完整的預設唯讀權限範圍。

## 查詢結果為空

空結果代表在該日期範圍內沒有符合條件的已儲存資料，並不代表負荷為零、沒有訓練，或身心狀態健康／正常。請先檢查工具回傳的時區與查詢區間，必要時在文件規範的上限內擴大查詢範圍。

## `CAPABILITY_TIMEOUT`、請求取消或觸發頻率限制

- `CAPABILITY_TIMEOUT`：請縮小日期範圍或降低 `limit` 筆數後重試一次。
- `CAPABILITY_CANCELLED`：用戶端已取消請求或中斷連線，請重新發起新的請求。
- 頻率限制（Rate limit）：請等待回應指定的重試間隔，切勿在短時間內連續重試。

## 用戶端仍顯示舊版工具

請重新整理或重設該用戶端的 MCP 工具快取。在 ChatGPT 中，已發布的工作區應用程式可能會保留凍結的工具快照，直到管理員手動更新為止。在 VS Code 中，請執行 **MCP: Reset Cached Tools**。必要時，請移除伺服器後再重新連線。

## 資料看起來不安全，或似乎屬於其他帳號

請立即停止使用該連線，並從 TrainingLoad 帳號中撤銷存取權。記下用戶端名稱、大約發生時間與請求 ID 後，聯絡支援團隊。切勿提供存取權杖或完整的回應內容。
