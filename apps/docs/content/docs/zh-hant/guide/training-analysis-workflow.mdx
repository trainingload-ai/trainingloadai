# 訓練分析工作流程

唯有當數據真正改善了一個真實的訓練決策時，訓練分析才具有價值。這套工作流程能避免讓滿屏的儀表板指標淪為一堆彼此孤立的零散分數。

## 開始之前

- 先鎖定一個具體決策與明確時間區間（例如：明天這堂關鍵課要不要照計畫練？）。
- 確認相關訓練活動均已達到「就緒（Ready）」狀態。
- 核對個人閾值、時區、運動篩選條件與訓練負荷來源優先順序。
- 若分析涉及訓練計畫，先將已完成活動關聯至對應的計畫課表。
- 盡可能補齊課表 RPE 或目前身體狀態等主觀脈絡。

## 1. 先定義問題，而非先盯指標

每次分析都應從具體決策出發：

- 下一堂關鍵課表應該照原計畫執行嗎？
- 這一週是否達到了預期的訓練刺激？
- 反覆出現的執行卡關，根源是行程衝突、負荷過重，還是課表設計不合適？

接著設定對應的運動類型與日期區間，不要拿一整年的全時期圖表來回答這七天的執行問題。

## 2. 對照計畫課表與實際執行

在看任何綜合分數之前，先回答這四題：

- 原本計畫練什麼？
- 哪些課表完成了、略過了、挪動了，或尚未關聯活動？
- 哪些關鍵課表在時間、強度、結構或負荷上與原計畫不同？
- 這些差異是刻意安排的嗎？

如果跳過這一步，所有訓練負荷數字都會失去背後的訓練目的。

## 3. 驗證底層資料證據

點開構成總計數值的具體活動，逐項檢查：

- 處理狀態與來源平台。
- 感測器資料是否齊全，有無明顯漂移或斷訊錯誤。
- 採用的閾值與訓練區間基準。
- 活動負荷是由哪一種訊號來源算出來的。
- 地形、天氣、裝備或其他足以改變解讀的執行環境脈絡。

誠實標記某項訊號缺漏，遠比用看似精確的猜測強行補洞更有價值。

## 4. 同時判讀負荷壓力與身體反應

將 PMC 三大訊號視為一個整體解讀：

- [CTL](/zh-hant/docs/metrics/pmc/chronic-training-load) 描述較長期的訓練負荷趨勢。
- [ATL](/zh-hant/docs/metrics/pmc/acute-training-load) 描述近期的訓練壓力。
- [TSB](/zh-hant/docs/metrics/pmc/training-stress-balance) 呈現長期與近期模型負荷之間的差值。

接著把這些指標與實際執行品質、主觀疲勞感受以及相關的身體反應趨勢放在一起看。負荷描述的是「施加在身體上的刺激壓力」，本身並不等於已經產生「生理適應」。

## 5. 草擬一項保守的微調方案

優先只調整單一主要變數：

- 維持訓練頻率，調降單堂課表強度。
- 保留課表原本目的，適度縮短時間。
- 將一堂關鍵課表順延 24 至 48 小時。
- 維持原計畫不變，先觀察下一堂關鍵課的實際結果。

同時明確列出「哪些安排不可更動」，避免一次微調演變成整份週期被大幅改寫。

## 6. 確認變更並記錄決策理由

套用任何計畫修改之前，先整理這五項重點：

- **觸發原因（Trigger）**：是什麼計畫執行狀況或負荷型態促使這次檢討。
- **決策內容（Decision）**：確切要修改哪一堂未來課表的哪個欄位。
- **保護目標（Protected intent）**：這份計畫仍然必須守住的核心目的。
- **預期效果（Expected result）**：希望哪一項表現或狀態獲得改善或回穩。
- **檢視節點（Review point）**：用來檢驗這次決策是否奏效的下一筆活動或日期。

如果是由智能教練代為草擬調整方案，請先對照這五點並審閱建議課表，全部清晰無誤後再點擊確認。

## 驗證決策嚴謹度

- 每項結論都能回溯到 Trainingload.ai 中清晰可見的計畫、活動、設定或趨勢。
- 客觀觀測資料與主觀推論及不確定性已清楚分開。
- 僅修改了預期的未來課表。
- 已完成與已略過的歷史紀錄完全不受影響。
- 已訂出明確的下一次檢視節點。

## 疑難排解

- **不同指標彼此矛盾**：在認定哪個訊號「才是對的」之前，先比對日期區間、運動類型、閾值與負荷來源。
- **修改設定後圖表全變了**：釐清變動的是哪項閾值或負荷來源優先順序，並在一致基準下重新解讀歷史資料。
- **無法對照計畫與實際執行**：先關聯正確的已完成活動，並確認計畫課表具備足夠結構以算出預期負荷。
- **AI 建議的改動幅度太大**：明確要求只做一項保守調整、加上保護條件，並在套用前要求確認。
- **目前證據仍不足**：先維持原計畫不變，或只做最安全可逆的小幅微調，等收集完下一堂關鍵課資料再判斷。
