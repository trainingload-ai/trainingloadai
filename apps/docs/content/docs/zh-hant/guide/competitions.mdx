# 賽事管理

賽事紀錄在系統中獨立於訓練計畫之外。這樣的設計讓單一場比賽能為訓練計畫決策提供依據，而不會把賽事本身混同為一堂普通的排定課表。

## 開始之前

- 確認官方賽事日期、當地起跑時間與所屬時區。
- 先判斷這是一場低優先順序的以賽代訓，還是必須重點保護的目標大賽。
- 讓賽事紀錄與同一天可能安排的計畫課表保持獨立。
- 僅在具備真實目標時填寫目標完賽時間，避免填入毫無依據的猜測值。

## 新增賽事

開啟**賽事（Competitions）**並點選**新增賽事（Add Competition）**，依序填寫：

- 賽事名稱。
- 比賽日期或日期區間。
- 當起跑時間很關鍵時，一併填寫開始時間與時區。
- 運動類型與選填的細項定義。
- 賽事距離（若適用）。
- 重要程度：低（low）、中（medium）、高（high）或關鍵（critical）。
- 目標類型（選擇完賽時間目標時填入目標成績）。
- 比賽地點與備註。

重要程度代表訓練計畫應在多大程度上保護這場賽事。切勿將每場比賽都標記為「關鍵」；短時間內安排多場關鍵賽事只會製造規劃衝突，並不會憑空產生額外優先權。

## 檢視賽事與計畫影響

儲存後，請核對倒數天數、日期、運動類型、目標與重要程度。該賽事也會同步出現在對應的訓練日曆與單日檢視中。

Trainingload.ai 可依據賽事時間窗口與前後排定課表，評估該賽事對目前訓練計畫的影響。此影響評估屬於決策輔助資訊，並非自動刪除所有衝突課表的保證。

## 處理比賽當日的課表衝突

當計畫課表與賽事落在同一天時，請依序處理：

1. 先確認賽事日期與時區完全正確。
2. 判斷這場比賽是要取代該堂課表、達成相似訓練目的，還是與另一堂輕鬆課並存。
3. 手動明確編輯、略過或移動該堂計畫課表。
4. 一併檢視賽前賽後的強度安排與恢復日。
5. 待賽事優先順序確立後，再請智能教練協助擬定課表調整建議。

## 安全更新賽事資料

賽事紀錄採用版本感知更新機制。如果其他裝置或請求已修改過這場賽事，請先重新整理並檢視最新版本，再重新儲存變更。

## 取消、恢復或刪除賽事

- **取消（Cancel）**：保留賽事紀錄，但將其移出計畫中的參賽狀態。
- **恢復（Restore）**：當先前取消的賽事重新納入安排時，可將其恢復。
- **刪除（Delete）**：徹底移除紀錄，建議僅用於誤建或不再需要的測試項目。

## 驗證結果

- 賽事顯示於正確的年份與日曆日期。
- 倒數天數與當地時間皆正確無誤。
- 目標距離、比賽日期與目標完賽時間完全相符。
- 當有涵蓋該時段的訓練計畫時，可順利載入計畫影響評估。
- 比賽當日的課表衝突清晰可見，而非被系統靜默覆蓋。

## 疑難排解

- **倒數天數不正確**：同時核對賽事日期、起跑時間、賽事時區與帳號顯示時區。
- **日曆上找不到這場賽事**：確認賽事未被標記為取消，且目前的日曆顯示區間涵蓋該日期。
- **無法載入計畫影響評估**：確認目前進行中的訓練計畫期間與賽事窗口重疊，並重新整理過時的計畫或賽事版本。
- **衝突看起來沒有被自動解決**：請主動移動、略過或編輯計畫課表；系統刻意不讓賽事靜默改動訓練計畫。
- **更新時發生版本衝突**：重新整理賽事頁面，並在最新版本上重新套用變更。
