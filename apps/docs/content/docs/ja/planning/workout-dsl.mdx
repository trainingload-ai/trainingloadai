# 持久系ワークアウト DSL

この DSL は、**Rules** モードで1つの構造化持久系ワークアウトを記述するための記法です。トレーニングプランには複数のワークアウトを含められ、各ワークアウトが個別にパース・検証されます。**1行が1ステップ**を表し、上から下へ順に実行されます。

このページではランニング、サイクリング、スイミングの持久系ステップを扱います。種目とセットで構成するセッションには[筋力ワークアウト](/ja/docs/planning/strength-workouts)を使用してください。

## 始める前に

- 記述を始める前に正確な種目を選択してください。ゾーンと単位の解釈は種目に依存します。
- `z1` や `z2` などのゾーン参照を使う前に、アスリートのペース・パワー・心拍ゾーンを設定してください。
- 各ステップを時間、距離、エネルギー、センサー条件のどれで終了させるか決めます。
- テキスト編集が不要な場合はビジュアルビルダーを使用してください。

---

## 各行を左から右へ記述する

各行は最大3つのスペース区切り要素を次の順番で記述します。

| 要素 | 役割 | 例 |
| --- | --- | --- |
| ① ステップの種類 | ウォームアップ、メイン、リカバリー、レスト、クールダウンなど | `warmup`、`work`、`recovery`、`rest`、`cooldown` |
| ② 長さ／終了条件 | 最初に**1つだけ**「数値＋単位」またはセンサー条件を置く（時間・距離・kJ・心拍条件など） | `5m`、`3km`、`500kj`、`hr<150bpm` |
| ③ 目標（任意） | ペース、パワー、心拍、ケイデンスなど | `pace …`、`power …`、`hr …` |

③ に指定できる目標は**最大1つまで**です。1ステップで狙えるのはペース、パワー、心拍数、ケイデンス、勾配のいずれか1つであり、複数を同時に指定することはできません。複数の狙いがある場合はステップを分けるか、副次的な目安をワークアウトのメモ欄に書いてください。`work: 20m` と `work 20m` は同じ意味で、コロンは省略できます。

---

## ① ステップの種類を選ぶ

行の先頭に次のいずれかのキーワードを書きます。キーワードは大文字・小文字を区別しません。

| キーワード | 意味 |
| --- | --- |
| `warmup` / `wu` | 最初のウォームアップ |
| `work` | メインワーク |
| `recovery` / `rec` | ワーク間のアクティブリカバリー |
| `rest` | レスト（休息）ステップ |
| `cooldown` / `cd` | 最後のクールダウン |
| `other` | 標準ラベルに当てはまらないステップ |

軽く動き続ける回復区間には `recovery`、休止を意図する場合は `rest` を使ってください。保存されるステップ種別はこの区別を維持し、表示やエクスポートに反映されます。

---

## ② 終了条件を追加する

ステップが**いつ終了するか**を、時間・距離・エネルギー・センサー条件のいずれかで指定します。1行に書ける主たる終了条件は1つだけです。その後に続く `power` や `hr` は強度目標であり、2つ目の長さではありません。

| 形式 | 意味 |
| --- | --- |
| `30s`、`5m`、`25min`、`1h` | 時間 |
| `5km`、`400m` | 距離（`3km` は 3 km であり 3 秒ではありません） |
| `500kj` | バイクでの仕事量（キロジュール） |
| `hr<150bpm`、`power>250W` など | 心拍数やパワーが条件を満たしたらステップを終了 |

---

## ③ 任意の目標を追加する

最初の終了条件のあとに、スペース区切りで目標を指定します。

| キーワード | 用途 |
| --- | --- |
| `pace` | ランニングペース |
| `speed` | 速度（アプリ上ではペースまたは km/h で表示） |
| `power` | パワー：**ワット**（`250W`）を推奨。`250` のような単位なし数値は**ワット**として解釈。従来の `%FTP`（`85%`）も利用可能 |
| `cadence` | ケイデンス |
| `hr` | 心拍数：**bpm**（`150bpm`、`150-160bpm`、`<150bpm`、または `150` のような単独数値）または `hr z2` のようなゾーン参照 |
| `grade` | 勾配 |

旧エイリアスの `pwr`、`cad`、`rpm` も引き続きパースできますが、新しく生成される DSL では正式な単語が使われます。

DSL のキーワード、単位、ゾーントークンは大文字・小文字を区別しません。`WORK 25M HR Z2` は `work 25m hr z2` と同じに解釈され、保存・再生成時に小文字キーワードへ正規化されます。

固定値ではなくアスリートの現在のゾーンを参照したい場合は次のように記述します。

```text
work 25m hr z2
work 10m power z4
work 20m pace z2
```

これらは「アスリートの現在の Z2 / Z4 レンジで実施する」という意味になります。後からゾーンを更新した場合も、新しいレンジで解釈できます。目標値を固定したい場合は `hr 140-150bpm`、`power 220-250W`、`pace 4:30-4:45` のように明示的な数値を使ってください。

終了条件としてのセンサー指定と、目標としての指定は明確に分けてください。

```text
work hr<150bpm
work 25m hr <150bpm
```

1行目は心拍数が条件に達した時点で終了するステップであり、さらに別の目標を追加することはできません。2行目は25分間実施し、心拍数 150 bpm を上限目標にするステップです。

---

## `repeat`：同じミニブロックを繰り返す

```text
repeat 4 {
  work 4m power 270W
  recovery 2m
}
```

- `repeat 4` は波括弧内のステップを**4回**繰り返します。
- 波括弧内の2行で1ラウンドです。この例では「4分間 270 W ＋ 2分間リカバリー」を4ラウンド行います。ビルドによっては `}` の代わりに `end` / `endrepeat` で閉じられる場合もありますが、現在のエディタが受け付ける形式を使用してください。

条件に達するまで繰り返すこともできます。

```text
repeat until 30m {
  work 4m power 270W
  recovery 2m
}

repeat until cadence<80rpm {
  work 30s power 300W
  recovery 30s
}
```

`repeat until` では時間、距離、カロリー、心拍数、パワー、ケイデンスの条件を指定できます。リピートの入れ子は意図的に禁止されています。条件付きリピートを表現できない外部連携先では、ワークアウトを黙って別内容へ変換するのではなく、未対応または明示的なダウングレードとして報告する仕様です。

## 例 1：ランニング

```text
warmup 5m
work 20m pace 7:20-8:20/km
recovery 90s
work 3km
cooldown 5m
```

- `warmup 5m`：5分間のイージーなウォームアップ。
- `work 20m pace …`：20分間のメインワーク（目安 7:20〜8:20/km）。
- `recovery 90s`：90秒間のイージーなリカバリー。
- `work 3km`：さらに20分ではなく、距離 **3 km** のワーク。
- `cooldown 5m`：締めくくりの5分間クールダウン。

上から下へセッションの順番どおりに実行されます。

---

## 例 2：バイク

```text
work 8m power 220-250W
recovery 2m
work 5m hr 150-160bpm
```

- 1行目：8分間、220〜250 W。
- 2行目：2分間イージー、目標指定なし。
- 3行目：5分間、心拍数 150〜160 bpm。

---

## 例 3：4本のインターバル

```text
repeat 4 {
  work 4m power 270W
  recovery 2m
}
```

「4分間ハード（目安 270 W）＋ 2分間イージー」を4回繰り返します。`repeat` を使えば同じ2行を4回コピー＆ペーストする必要がありません。

## 検証して保存する

1. ワークアウトエディタで **Rules** を選択します。
2. DSL を入力または貼り付けます。
3. パース／プレビュー機能がある場合は、保存前に実行します。
4. 正規化されたテキストとビジュアルプレビューが、意図したステップ順になっているか比較します。
5. ワークアウトを保存して開き直し、種目・時間・リピート回数・目標が正しく保持されているか確認します。

保存後のテキストは小文字キーワードや標準単位へ正規化される場合があります。正規化自体は正常な動作ですが、ワークアウトの意味が変わっていないかは必ず確認してください。

---

## 種目と DSL の対応範囲

予定ワークアウトには、ロードランニング、トレイルランニング、トレッドミルランニング、ロードサイクリング、マウンテンバイク、インドアサイクリング、プールスイミング、オープンウォータースイミングといった正確な種目が保持されます。関連種目どうしはラン・バイク・スイムのゾーンと負荷分析を共有しつつ、Suunto・Intervals.icu・COROS へのエクスポート時には正確な種目マッピングを優先します。

API 上では、`sportType` がランニング・サイクリング・スイミングといった大分類、`subSportType` が `TRAIL_RUNNING` や `INDOOR_CYCLING` のような正規サブタイプを表します。

種目セレクターで無効化されている種目は、意味を損なわずに構造化エディタで表現できる段階にまだ達していないことを意味します。アクティビティ種別としては利用でき、アプリが未対応構造を勝手に別のワークアウトへ変換することはありません。

## ワークアウトの確認項目

- 入力した順番どおりにすべてのステップがプレビューに表示されている。
- 各行に主たる終了条件が1つ、目標が1つ以内になっている。
- ゾーン参照が意図した種目とアスリートプロフィールに基づいて解決されている。
- リピートブロックに想定どおりのステップと回数または終了条件が入っている。
- ワークアウトを開き直しても同じ構造と種目サブタイプが保たれている。

## トラブルシューティング

- **未知のキーワードエラーが出る：** サポートされているステップ種別または目標名を使い、文法に含まれない記号を削除してください。
- **時間や距離の解釈がおかしい：** 単位と位置を確認してください。ステップ種別の直後に来る最初の尺度が終了条件として解釈されます。
- **複数の目標がパーサーに拒否される：** 1行に指定する目標は1つにとどめ、副次的な目安はメモ欄または別ステップへ分けてください。
- **条件終了の行で目標が拒否される：** `work hr<150bpm` はすでに心拍数を終了条件として使っています。時間固定で心拍上限を設けたい場合は `work 25m hr <150bpm` としてください。
- **リピートが失敗する：** 波括弧が閉じているか、入れ子になっていないか、`repeat until` の条件が正しいか確認してください。
- **種目を切り替えたらプレビューが変わった：** ゾーンと単位の意味は種目に依存します。正しい種目を選び直し、すべての目標を再確認してください。
- **エクスポート時にダウングレードや未対応構造の警告が出る：** 連携先の警告内容を確認してから簡略化してください。すべてのデバイスが条件付きリピートに対応しているわけではありません。
