# MCPトラブルシューティング

## クライアントがサーバーを検出できない

URL が末尾の `/mcp` を含めて正確に `https://api.trainingload.ai/mcp` になっているか確認してください。クライアントはリモートの Streamable HTTP に対応している必要があります。社内ネットワーク環境では、`api.trainingload.ai` と TrainingLoad の認可ページの両方への HTTPS 通信が許可されているか確認してください。

## OAuth 画面が開かない、またはエラーでクライアントに戻る

- 古い認可 URL を再利用せず、クライアント側の接続アクションからやり直してください。
- クライアントが OAuth ディスカバリーと PKCE S256 に対応しているか確認してください。
- コールバックが、認可を開始したのと同じクライアントインスタンスに戻っているか確認してください。
- 認可検証サービスが一時的に利用できない場合は、返された `Retry-After` の時間だけ待ってから再試行してください。

## ツールが見当たらない

サーバーはアカウントの利用資格とロールアウトフラグに応じて `tools/list` をフィルタリングしています。`get_health_summary` は、呼び出し時に段階的認可を開始できるよう、`health:read` の付与前でも一覧に残ります。他のツールが見当たらない場合は、アカウントとロールアウト対象を確認したうえで再接続してください。Bearer トークンを手動で設定してはいけません。

## `INSUFFICIENT_SCOPE`

クライアントの再接続または認可アクションを実行し、要求されたスコープを承認してください。クライアントが MCP の `mcp/www_authenticate` チャレンジを無視する場合は、一度接続を削除して追加し直し、意図した読み取り専用スコープ一式を再要求させてください。

## 結果が空になる

空の結果は「指定した日付範囲に一致する保存データがない」ことを意味します。負荷ゼロ、トレーニング未実施、または健康・正常という意味ではありません。ツールが返したタイムゾーンと照会範囲を確認し、必要に応じてドキュメント記載の上限内で範囲を広げてください。

## `CAPABILITY_TIMEOUT`、キャンセル、レート制限

- `CAPABILITY_TIMEOUT`: 日付範囲を狭めるか `limit` を小さくして、1回だけ再試行してください。
- `CAPABILITY_CANCELLED`: クライアント側でキャンセルまたは切断が発生しました。新しいリクエストを開始してください。
- レート制限: 返された再試行間隔だけ待機してください。短い間隔で連続リトライしないでください。

## クライアントに古いツール一覧が残っている

そのクライアントの MCP ツールキャッシュを更新またはリセットしてください。ChatGPT では、公開済みワークスペースアプリが管理者の更新まで古いツールスナップショットを保持する場合があります。VS Code では **MCP: Reset Cached Tools** を実行してください。必要に応じてサーバーを一度削除し、再接続します。

## データが安全でないように見える、または別アカウントのデータが表示される

直ちにその接続の利用を中止し、TrainingLoad 側からアクセスを取り消してください。クライアント名、おおよその時刻、リクエスト ID を控えたうえでサポートへご連絡ください。アクセストークンやレスポンス全文は共有しないでください。
