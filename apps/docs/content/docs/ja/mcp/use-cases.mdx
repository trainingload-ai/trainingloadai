# MCPのユースケース

以下のプロンプトを、TrainingLoad に接続したクライアントへそのまま貼り付けて試せます。記載されたすべてのツールを使う必要はなく、質問に答えるための最小限の組み合わせで十分です。

## 現在の状態と主観的な疲労感

> TrainingLoad を使って、本日時点の私のトレーニング状態を要約してください。直近7日間とその前の7日間を比較し、フォームと次の3件の予定ワークアウトを含め、事実と推測を明確に分けてください。

想定される経路: `get_training_snapshot` → `get_training_readiness` → 必要に応じて `list_planned_workouts`。

回答には、`asOf`、タイムゾーン、トレーニング負荷の差分、ATL/CTL/TSB の有無、そしてレディネス指標が医学的判断や「トレーニングして安全」という保証ではなく観察用の負荷シグナルであることが明記されているのが望ましいです。

## 2つのトレーニングブロックを比較する

> 2026年9月1日〜28日と2026年10月1日〜28日を比較してください。ランニング、サイクリング、スイミング別にトレーニング負荷を分解し、データで裏付けられる変化だけを挙げてください。

想定される経路: `compare_training_periods` + `get_training_breakdown`。

繰り返し使える形式にしたい場合は、組み込みの `compare-training-blocks` プロンプトを選択してください。負荷とは別にセッション数・時間・距離が変化している場合は `get_activity_statistics` を、頻度・連続実施日数・ばらつきを確認したい場合は `get_training_consistency` を追加します。

## 完了済みアクティビティを1件詳しく見る

> このアクティビティのゾーン別滞在時間とラップ／スプリットのサマリーを表示してください。保存されている集計フィールドだけを使ってペースのばらつきを指摘し、生のGPS軌跡やセンサーストリームは要求しないでください。

想定される経路: `get_activity` → `get_activity_zones` + `get_activity_splits`。

## フィットネス推移と自己ベスト

> 今年のランニングの推定 VO2_MAX の推移、現在のトレーニングゾーン、5 km と 10 km の自己ベストを表示してください。推定値をラボでの実測値のように表現しないでください。

想定される経路: `get_fitness_trends` + `get_training_zones` + `get_personal_bests`。

## トレーニングプランの実行状況

> 直近8週間のトレーニングプランの実行状況を要約してください（完了、スキップ、未完了のワークアウト）。そのうえで来週の予定ワークアウトを一覧にし、達成率の分母の考え方も説明してください。

想定される経路: `get_plan_adherence` + `list_planned_workouts`。

`get_plan_adherence` は、アクティビティがプランと一致するかを推測するのではなく、ワークアウトのステータスに基づいて集計します。完了として数えられるのは `DONE` のみで、選択期間内の未来の `PLANNED` ワークアウトも分母に含まれます。

特定のトレーニングプラン全体を確認したい場合は、まず `list_training_plans` で不透明な ID を取得し、続けて `get_plan_summary` で達成状況、実績負荷と予定負荷の比較、週次進捗、種目構成を取得します。

## レース前の準備チェック

> 次の大会を見つけて、関連するトレーニングプラン、直近のトレーニング負荷・フォームのシグナル、今後の予定ワークアウトを確認してください。不足している根拠を明記し、レディネス指標を医学的判断や「出場して安全」という決定にすり替えないでください。

想定される経路: `list_competitions` → `get_competition` → `list_training_plans` / `get_plan_summary` → `get_training_readiness` → `list_planned_workouts`。

MCP プロンプトに対応したクライアントでは、全文をコピーする代わりに `race-preparation-check` を選択できます。

## 同期トラブルの切り分け

> Strava の連携状況を確認してください。完了済みアクティビティのインポートとエクスポートが利用可能で自動同期になっているか、最新の同期にエラーがあるかを教えてください。アカウントIDや生のエラー文言は表示しないでください。

想定される経路: `get_integration_status`。

## コンディションの把握（個別同意が必要）

> ヘルスデータへのアクセスを認可した後、直近14日間に取得できたウェルネス指標の変化を要約してください。欠損値は明示し、診断は行わないでください。

想定される経路: `get_health_summary`。`health:read` が未認可の場合、クライアントはトークン入力を求めるのではなく段階的同意のフローを表示します。

## どの回答も検証しやすくする一文

プロンプトの末尾に次の一文を足すと、根拠を確認しやすくなります。

> 実際に呼び出した TrainingLoad のツール名、各対象日付範囲、結論の根拠になった返却フィールドを一覧にしてください。欠損値を推測で埋めないでください。
