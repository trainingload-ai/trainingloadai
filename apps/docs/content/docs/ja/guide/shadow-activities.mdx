# シャドウアクティビティ：サマリーしか表示されない理由は？

**シャドウアクティビティとは、存在は検出できたものの完全な記録データがまだ取得できていないアクティビティのことです。** 見落とされていないことがわかるよう、Trainingload.ai はタイトルと開始時刻、および次に取れる操作を保持します。

シャドウアクティビティは完全にインポートされたアクティビティではありません。サマリー情報だけからグラフやトレーニング負荷を推測して捏造することはありません。本データの取り込みに成功すると、シャドウは完全なアクティビティに置き換わります。また、すでに完全な記録が存在する場合、後続の同期でデータを取得できなくても既存データが消去されることはありません。

現在、主に次の 2 つのケースがあります。

## ケース 1：Intervals.icu にアクティビティ情報はあるが元ファイルを提供できない

Intervals.icu は Strava から受け取ったアクティビティのサマリーを表示できますが、API 仕様によりオリジナルファイルの取得が明確に制限されています。Intervals.icu 上で見えているからといって、Trainingload.ai がその API 経由で完全な記録を取得できるわけではありません。

この場合、Trainingload.ai は Strava から直接取得を試みます。カードの案内に従って Strava の接続、認可の更新、またはアクティビティインポートの有効化を行い、同期完了を待ってください。

Strava 側からも必要なデータを取得できない場合は、シャドウアクティビティのまま残ります。Intervals.icu を何度再同期しても、元ファイルに対する制限は回避できません。

## ケース 2：Strava にアクティビティ詳細はあるがストリームを提供できない

アクティビティ名・合計距離・時間といった詳細情報と、各時点の GPS・心拍数・パワー・距離サンプル（ストリーム）は別データです。**アクティビティ詳細があっても、インポート可能なストリームが存在するとは限りません。**

- **もともとサンプルが存在しない：** たとえばデバイス記録なしで距離と時間だけ Strava に手動登録したアクティビティです。詳細ページは存在しますが、再試行しても存在しないサンプルは生成されません。
- **一時的に記録を取得できない：** プラットフォーム側で処理中であるか、詳細データエンドポイントが一時的に利用できない場合があります。1 回の「見つからない（not found）」応答だけでは、削除済みやストリームの恒久的な欠如とは断定できません。

不確実な取得エラーに対して、Trainingload.ai は一定回数まで自動で再試行します。それでも取得できない場合はシャドウアクティビティを残し、手動再試行オプションを表示します。なお、心拍数・パワー・GPS だけが欠けていても、有効な時系列データがあれば通常のアクティビティとしてインポートされるため、必ずしもシャドウになるわけではありません。

## どう対処すればよいですか？

| わかっている状況 | 推奨される対処 |
| --- | --- |
| カードに接続・認可更新・インポート有効化の案内が出ている | 案内された設定を完了し、同期または再試行を待ちます。 |
| アクティビティをアップロードした直後、または処理中 | 処理完了を待ってから 1 回だけ再試行します。 |
| プラットフォーム側の一時障害が解消した | 1 回再試行して完全な記録を再取得します。 |
| 手動入力したアクティビティで元からサンプルがない | 何度再試行しても改善しません。元のデバイス記録がないか探してください。 |
| 複数回試してもシャドウアクティビティのまま | 元のプラットフォームからアクティビティファイルをエクスポートできるか確認し、必要ならサポートへ連絡してください。 |

再試行はデータの再取得を要求する操作であり、連携元が今すぐ提供できることを保証するものではありません。シャドウや既存の完全なアクティビティを先に削除する必要はありません。連携解除と再接続を繰り返しても、存在しないサンプルが作られることはありません。

## オリジナルファイルが手元にある場合

最初にワークアウトを記録したデバイスまたはプラットフォームから、記録データを含む FIT・TCX・GPX ファイルをエクスポートできる場合は、[アクティビティファイルのアップロード](/ja/docs/guide/upload-activity-files)を利用してください。すでに完全なアクティビティが存在する場合は、重複警告と日付・内容を確認しましょう。

## サポートに問い合わせる場合

アクティビティの日付、連携元プラットフォーム、表示されているメッセージ、および元のプラットフォームからファイルをエクスポートできるかどうかを添えてご連絡ください。アクセストークンやパスワードは絶対に送信しないでください。その他の切り分け手順は[トラブルシューティング](/ja/docs/guide/troubleshooting)をご覧ください。
