# トレーニング分析ワークフロー

トレーニング分析は、実際の判断を良くして初めて意味を持ちます。このワークフローに沿うことで、ダッシュボードに並ぶ指標が単なる無関係なスコアの寄せ集めになるのを防げます。

## 始める前に

- 「明日のポイント練習を予定通り行うか」など、1 つの判断と対象期間を決めます。
- 対象のアクティビティが「完了（Ready）」ステータスになるのを待ちます。
- 閾値、タイムゾーン、種目フィルター、負荷ソースの優先順位を確認します。
- プランが判断に関わる場合は、実施済みアクティビティを予定ワークアウトに紐づけておきます。
- 利用可能な場合は、セッション RPE や現在の状態といった主観的コンテキストも記録します。

## 1. 問いを定義する

指標ではなく「下したい判断」から始めましょう。

- 次のポイント練習は予定通り実施すべきか？
- 今週は狙い通りのトレーニングストレスを与えられたか？
- 繰り返される実行上の課題は、スケジュール・負荷・ワークアウト設計のどれに原因があるか？

対象の種目と期間を設定します。直近 7 日間の実行判断に、全期間のグラフを混ぜないでください。

## 2. 予定と実績を比較する

スコアを読む前に、次の問いに答えます。

- 何を予定していたか？
- 何が完了し、スキップされ、移動され、あるいは未紐づけのままか？
- 時間・強度・構成・負荷が予定と異なった主要セッションはどれか？
- その差は意図的なものだったか？

このステップを飛ばすと、トレーニング負荷の数値は本来のトレーニング目的から切り離されてしまいます。

## 3. 根拠データを検証する

合計値の背後にあるアクティビティを開き、次を確認します。

- 処理ステータスと連携元プラットフォーム
- センサーデータの有無と明らかなデータエラー
- 閾値とゾーン設定
- アクティビティ負荷がどのソースから算出されているか
- 地形、天候、使用機材など解釈を左右する実施環境

もっともらしい推測で穴埋めするよりも、欠けているシグナルを「欠けている」と明示しておくほうが正確です。

## 4. トレーニング負荷と身体の反応をセットで読む

PMC のシグナルは 3 つセットで読み解きます。

- [CTL（体力）](/ja/docs/metrics/pmc/chronic-training-load)：長期的なトレーニング負荷の傾向を表します。
- [ATL（疲労）](/ja/docs/metrics/pmc/acute-training-load)：直近のトレーニングストレスを表します。
- [TSB（コンディション）](/ja/docs/metrics/pmc/training-stress-balance)：長期負荷と短期負荷のモデル上の差を表します。

そのうえで、実行の質、主観的な疲労感、関連する反応トレンドと照らし合わせます。負荷は加えたストレス量を表すものであり、それ単体で適応（走力向上など）を証明するものではありません。

## 5. 控えめな変更案を 1 つだけ作る

まずは主要な変数を 1 つだけ調整します。

- 頻度は保ち、1 セッションだけ強度を下げる
- ワークアウトの目的は保ち、時間だけを短縮する
- ポイント練習を 1 つだけ 24〜48 時間ずらす
- プランは変更せず、次のポイント練習の結果を見てから判断する

調整によってトレーニングブロック全体が暗黙に書き換わらないよう、「変えない項目」も明確にしておきましょう。

## 6. 根拠を記録してから確定する

プラン変更を適用する前に、次の 5 点を整理します。

- **きっかけ（Trigger）：** 見直しの理由になった予実差や負荷パターン
- **判断（Decision）：** 変更する具体的なワークアウトと項目
- **守るべき意図（Protected intent）：** プランで引き続き達成したい目的
- **期待する結果（Expected result）：** 何が改善または安定する想定か
- **確認ポイント（Review point）：** 判断を検証する次のアクティビティまたは日付

AIコーチが調整案を作成した場合も、この 5 点が明確になってから提案ワークアウトを確認・確定してください。

## 判断を確認する

- すべての結論が Trainingload.ai 上で確認できるプラン・アクティビティ・設定・傾向に裏付けられていること
- 観測されたデータと、解釈・不確実性が区別されていること
- 意図した将来のワークアウトだけが変更されていること
- 完了済み・スキップ済みの履歴がそのまま残っていること
- 次の具体的な確認ポイントが設定されていること

## トラブルシューティング

- **指標同士で言っていることが違う：** 1 つを「正解」と決めつける前に、期間・種目・閾値・負荷ソースを比較してください。
- **設定編集後にグラフが変わった：** 変更した閾値または負荷ソース優先順位を特定し、履歴全体を一貫した基準で読み直してください。
- **予定と実績を比較できない：** 正しいアクティビティを紐づけ、予定ワークアウトに予定負荷を算出できるだけの構成があるか確認してください。
- **AI が大規模な書き換えを提案してくる：** 守るべき制約を明示し、確認付きの控えめな変更案を 1 つだけ依頼してください。
- **判断材料が足りない：** プランはそのままにするか最も安全な可逆的調整にとどめ、次の重要セッションのデータを集めてから見直しましょう。
