# タイムラインでワークアウトを分析する

タイムラインは、アクティビティに記録された複数のストリームを共通の横軸上に揃えて表示します。特定の 1 時点を確認したり、選択した区間のペース・パワー・心拍数・ケイデンス・ルートをまとめて比較したりできます。左側の区間統計とグラフ上の時点読み取りは、それぞれ異なる問いに答えます。

このガイドはランニングおよびサイクリングの **デスクトップ Web** を対象としています。表示できるグラフはアクティビティの記録データに依存します。全体的な振り返り手順は[アクティビティ詳細](/ja/docs/guide/activity-detail)からご覧ください。

## サンプルを開く

[10km レースのデモアクティビティを開く](https://demo.trainingload.ai/en/activities/17921623926005309429)をクリックし、ルートの下にある **タイムライン** を選択します（最初は概要タブが開きます）。Demo は読み取り専用のため、分析セグメントの保存編集は無効です。

ご自身のアクティビティを使う場合は、処理完了を待ち、時系列サンプルが記録されていることを確認してください。サマリーのみのアクティビティでは同期タイムラインは表示されません。インドアセッションでも GPS なしでグラフを確認できます。データを解釈する前に種目・閾値・単位も確認しておきましょう。

## 1. アクティビティ全体を見る

**タイムライン** を開くと、上部にセグメント見出し、左側に指標設定と区間統計、右側に横軸が揃ったグラフが表示されます。横軸の初期設定は時間モードです。位置情報があるアクティビティでは、タブの上部にルートが残ります。

長時間のアクティビティは表示幅を超えるため、横にスクロールして後半を確認します。範囲を選択するまで、左側の区間統計はアクティビティ全体を対象とします。

初期状態では左側の **平均（Average）**、**最小（Min）**、**最大（Max）** がアクティビティ全体を示します。有効なサンプルがない指標は表示されない場合があり、ストリーム内の欠損区間はグラフの途切れとして表現されます。

## 2. 特定の時点を確認する

グラフ上でポインターを動かすと、同じ横軸位置における各グラフ内のフローティング数値が表示されます。GPS がある場合は、マップ上にも対応する地点が示されます。

クリックするとその位置の選択を維持できます。ポインターをグラフ外へ移動すると一時的なホバー数値は消えますが、左側の区間統計はアクティビティ全体または選択範囲に紐づいたまま残ります。

タイムラインの位置指定コントロールにフォーカスを当てると、左右の矢印キーでサンプル単位の移動ができ、**Home**／**End** で先頭・末尾へ移動できます。フォーカスが外れるとキーボードによる時点表示は消えます。

| 知りたいこと | 確認する場所 |
| --- | --- |
| その瞬間に何が記録されたか | 各グラフ内に表示される時点の読み取り値 |
| その区間全体で平均的にどうだったか | 左側の区間統計にある平均値 |
| その区間の有効な最小・最大値はいくつか | 同じ区間統計の最小値・最大値 |

## 3. 区間を選んで比較する

記録済みのラップを選ぶことも、自分で範囲をドラッグして選ぶこともできます。

1. セグメント見出しをクリックすると、そのセグメントが強調表示され区間統計が更新されます。もう一度クリックすると選択が解除されます。
2. 別の範囲を調べたい場合は、グラフ上を横にドラッグして離します。すべてのグラフが選択範囲にズームされます。
3. 選択範囲の平均・最小・最大値とグラフ波形を比較し、ポインターを動かして区間内の個別サンプルを確認します。
4. 位置情報がある場合は、ハイライトされたルート区間を確認します。周辺の地図と照らし合わせて、その区間がどのような地形で行われたかを把握しましょう。

一定のペース・出力で長く走った区間では、ペースやパワーが変わらないのに心拍数が変化していないかを確認します。インターバルでは、疾走区間とリカバリー区間がセッションの目的に合致していたかを見比べましょう。時間・地形・停止・利用可能なセンサーデータから傾向を整理してください。

## 4. 全体表示に戻す・横軸を切り替える

**セグメント** の横にある **タイムラインオプション** を開き、**アクティビティ全体を表示** を選ぶと範囲選択とズームが解除され全体表示に戻ります。グラフをダブルクリックするか、タイムライン内で **Escape** キーを押してもリセットできます。

同じメニューで **横軸** を **時間** と **距離** の間で切り替えられます。距離モードには有効な累積距離データが必要です。横軸を切り替えても、選択中の区間は元の時間境界を保持します。

## 5. グラフをカスタマイズする

**ペース** や **心拍数** などの指標名をクリックすると設定が開きます。表示する指標、線の色、グラフの高さ、スムージングを変更できます。**上へ移動**、**下へ移動**、**グラフを削除** で表示行を整理しましょう。

下部の **グラフを追加** から別の利用可能ストリームを追加できます。同じ指標を複数追加して生データとスムージング表示を見比べることも可能です。**拡大** を使うと個別のグラフを大きく表示できます。

スムージングは描画される曲線の滑らかさだけを変えます。時点読み取り値と区間統計は元の記録データの意味を保ちます。グラフのレイアウトはこのブラウザの設定として保存され、元のアクティビティデータは変更しません。

## 6. ご自身のアカウントで分析セグメントを編集する

デバイスのラップとは異なる区間設定で分析したい場合は **セグメントを編集** を使用します（編集権限のあるアカウントでのサインインが必要です）。

1. **セグメントを編集** を開き、各セグメントの名前・開始・終了を確認します。
2. 名前を変更したり境界を調整したりします。状況に応じて **隙間にセグメントを追加**、**半分に分割**、**次と結合**、**削除** も利用できます。
3. すべての境界をアクティビティの範囲内に収め、開始が終了より前になり、セグメント同士が重ならないようにします。
4. **セグメントを保存** を選択し、更新された区間統計を確認します。**キャンセル** を押すと保存せずにドラフトを閉じます。

分析セグメントを保存しても、元のファイル・デバイスラップ・アクティビティ全体のトレーニング負荷は変わりません。境界を変更したセグメントは、記録ストリームからその範囲の統計を再計算します。**デバイスラップを復元** を選ぶとエディタ内の定義を元のラップ範囲に戻すことができ、そのまま保存できます。

別のウィンドウで定義が変更されていた場合は、エディタを一度閉じて開き直し最新版を読み込んでから編集してください。保存に失敗してもドラフトは残るため再試行できます。公開 Demo ではこの編集機能は無効です。

## 結果の確認

区間を選んだあと、その境界・区間統計・ルート区間がアクティビティの同じ部分を指していることを確認します。全体表示に戻して統計が全体に戻ることも確認しましょう。アカウントで分析セグメントを保存した場合は、アクティビティを開き直して定義が維持されているか確かめてください。

## よくある質問

### ポインターを動かしても左側の数値が変わらないのはなぜですか？

左側はアクティビティ全体または選択範囲の統計です。ポインター位置の瞬間値は各グラフ内のフローティング表示を確認してください。

### 途切れやハイフン（-）が表示されるのはなぜですか？

ストリームの欠損、サンプリングの空白、無効値などがあると途切れやハイフンになります。速度・ケイデンス・パワーの「0」は有効な記録である場合がありますが、停止中のサンプルには有効なペースがなく、欠損した心拍サンプルが 0 で補われることもありません。

### ラップの境界を編集すると数値が変わるのはなぜですか？

未変更のデバイスラップはインポートされたサマリーを使うことがありますが、変更または新規作成した分析セグメントはその範囲内の有効な記録サンプルから再計算されます。欠損区間の有無や境界位置によって結果が変わります。

### パワーに「推定（Estimated）」と表示されるのはなぜですか？

そのストリームは推定パワーを使用しています。パワーメーターによる実測値と比較したり強度を判断したりする際は、ソースの違いを意識してください。

### ルート上で選択区間がハイライトされないのはなぜですか？

その時間帯に有効な GPS データがないか、マップが利用できない可能性があります。記録グラフの分析を続けつつ、マップの状態を個別に確認してください。

### スマートフォンでタイムラインが表示されないのはなぜですか？

この機能はデスクトップ Web 向けです。スマートフォンではアプリと種目が対応するアクティビティ詳細・データグラフを利用するか、デスクトップでアクティビティを開いてください。

### グラフの読み込みに失敗した場合はどうすればよいですか？

再試行ボタンが表示されている場合はそれを実行してください。ほかの読み込み済みグラフはそのまま利用できます。更新失敗時には直前の結果を保持したままエラー状態を示すことがあります。データ自体の欠如とリクエスト失敗を切り分けて確認しましょう。
