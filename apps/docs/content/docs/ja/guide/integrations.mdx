# トレーニングアプリ連携：Strava・Garmin・COROSの選び方

トレーニング記録をどこから取り込むかを選び、継続同期が必要か一度きりの履歴インポートが必要かを決めます。このページでは Cloud 版の連携を解説します。具体的な認可・設定手順は[Strava・Garmin・COROSを接続してワークアウトを取り込む](/ja/docs/guide/connect-third-party-platforms)を参照してください。

セルフホスト環境では、別途 [Intervals.icu 設定](/ja/docs/self-host/configuration#connect-intervalsicu)と [Garmin Personal API ガイド](/ja/docs/self-host/garmin-personal-api)を利用するか、アクティビティファイルを直接アップロードしてください。

各プラットフォームの提供状況や対応する同期方向は変更されることがあります。最終的には接続ダイアログに表示されている操作内容を基準にしてください。

## 接続する前に

- 取り込みたいトレーニングデータを持つプラットフォームのアカウントにサインインしておきます。
- 各アクティビティの主経路となるプラットフォームを 1 つ決めます。同じワークアウトを 2 つの連携サービス経由で転送しないでください。
- 継続接続、一度きりの履歴インポート、ファイルアップロードのどれが必要かを確認します。
- プラットフォームの認証情報や API キーは手元に用意し、必ず公式の接続ダイアログにのみ入力してください。
- 最初のインポート成功を見分けられるよう、Trainingload.ai に現在表示されている最新のアクティビティを控えておきます。

## インポート経路を選ぶ

| ソース | 向いている用途 | 接続方式 |
| --- | --- | --- |
| Strava | 継続的なアクティビティ同期 | 同期設定付きのアカウント連携 |
| Polar | Polar アクティビティの継続インポート | OAuth 接続と同期設定 |
| COROS | アクティビティと日次データの同期、対応プランのエクスポート | 手動同期コントロール付きのアカウント連携 |
| Intervals.icu | アクティビティ同期および対応する予定ワークアウト連携 | OAuth または API キー（アカウント設定による） |
| Suunto | 継続的なワークアウトインポートおよび対応ガイド連携 | OAuth 接続と同期設定 |
| Wahoo | Wahoo ワークアウトの継続インポート | OAuth 接続と同期設定 |
| Garmin | 新規トレーニングの同期、または過去アクティビティ履歴の取り込み | OAuth 接続またはファイルインポート |
| FIT / TCX / GPX | 単発ファイルや非対応ソースからのエクスポート | 手動アップロード |

## プラットフォームを接続する

1. プラットフォームのカードを選択します。
2. 求められるデータ方向と設定を確認します。
3. OAuth で認可するか、必要な API キーを入力します。
4. 同期設定を保存します。
5. ダイアログに初回同期オプションがある場合は実行します。
6. **アクティビティ** を開き、新しく取り込まれたワークアウトを確認します。

プラットフォームの API キーを AIコーチ、プランのメモ、サポート用スクリーンショットに貼り付けないでください。必ず公式の接続ダイアログのみを使用してください。保存されたシークレットはクライアントに再表示されません。

## 初回同期と自動同期の違い

初回同期は、対象となる直近期間のデータをインポートするか、履歴取り込みジョブを開始します。自動同期は、今後のプラットフォーム側イベントを自動的に受け取ります。一部のプラットフォームでは、取りこぼした通知を補うための手動突き合わせ同期も用意されています。

大量のデータをインポートする際の注意点：

- 実行中のバッチが完了する前に再度開始しないでください。
- 処理の進み具合によって、アクティビティが時間差で一覧に表示されることがあります。
- 繰り返し再接続するのではなく、重複検出の結果を確認してください。
- センサーデータが欠けている場合は、まず元のプラットフォームのデータを確認してください。

## Garmin 履歴インポート

**現在、Trainingload.ai の Garmin 公式 OAuth 接続では、認可前に記録されたアクティビティを取得できません。接続を解除して再接続しても履歴は補完されません。** 過去の記録を取り込むには、Garmin の完全エクスポート ZIP（またはその一時ダウンロードリンク）をインポートするか、個別の FIT・TCX・GPX ファイルをアップロードしてください。この制限はセルフホスト版の Garmin Personal API には当てはまりません。セルフホスト環境では専用ガイドに従ってください。

Garmin ページでは、**OAuth** が新規アクティビティと許可された健康サマリーを受信し、**ファイルインポート** が過去のトレーニング記録を取り込みます。これらは別の操作ですので、目的に合わせて選択してください。

## Intervals.icu との予定ワークアウト同期の仕組み

ここで扱うのは実施済みアクティビティの記録ではなく、カレンダー上に予定されたワークアウトです。Intervals.icu の接続設定では、**予定ワークアウトをインポート** と **予定ワークアウトをエクスポート** を個別にオン／オフできます。

- **予定ワークアウトをインポート**：Intervals.icu での追加・編集・削除を Trainingload.ai に取り込みます。
- **予定ワークアウトをエクスポート**：Trainingload.ai での追加・編集・削除を Intervals.icu に送信します。

**両方向がオンの場合、削除も同期されます。** 前回同期以降にもう一方のコピーが変更されていない場合、片方を削除するともう一方も削除されます。

### ワークアウトを追加・編集・削除するとどうなりますか？

以下の表は両方向がオンになっている場合を前提としています。

| あなたの操作 | もう一方のプラットフォームでの動作 |
| --- | --- |
| Trainingload.ai でワークアウトを追加 | 対応する新しいワークアウトが Intervals.icu に表示されます。 |
| Intervals.icu でワークアウトを追加 | 対応する新しいワークアウトが Trainingload.ai に表示されます。 |
| Trainingload.ai 側だけで日付・名称・内容を変更 | 対応する Intervals.icu のワークアウトが更新されます。 |
| Intervals.icu 側だけで日付・名称・内容を変更 | 対応する Trainingload.ai のワークアウトが更新されます。 |
| Trainingload.ai でワークアウトを削除 | Intervals.icu 側が未変更であれば削除されます。変更されている場合は編集済みコピーが保持されます。 |
| Intervals.icu でワークアウトを削除 | Trainingload.ai 側が未変更であれば削除されます。変更されている場合は編集済みコピーが保持されます。 |

### 両方のコピーを編集した場合、どちらが優先されますか？

その時点で実行されている同期方向によって決まります。

- Intervals.icu からインポートするときは、Intervals.icu 側の内容が採用されます。
- Intervals.icu へエクスポートするときは、Trainingload.ai 側の内容が採用されます。

毎日の自動同期では、エクスポートの前にインポートが実行されます。そのため、自動同期開始時点で両方が編集されていた場合は Intervals.icu 側が優先されます。

編集内容の上書きを防ぐには、片側での編集を終えて同期を待ってから、もう一方での編集を続けてください。

### 片方を削除したのに、もう一方が残っているのはなぜですか？

残っているコピーが前回の同期以降に編集されているためです。その編集内容は保持され、2 つのワークアウトは相互更新を停止し、削除したワークアウトが即座に再作成されることはありません。

たとえば、Trainingload.ai 側で日曜のランを土曜に移動したあと、Intervals.icu 側の日曜のランを削除したとします。この場合 Trainingload.ai は土曜のランを保持し、それによって削除済みの Intervals.icu ワークアウトが復活することはありません。

もう一方のコピーが変更されたかどうかシステムが確認できない場合も、誤削除を防ぐためコピーを保持します。完了済み・スキップ済みのワークアウトや、実際のアクティビティに紐づいたワークアウトも必要な履歴を保持します。

### ワークアウトを削除して同じ名前で作り直した場合はどうなりますか？

作り直したワークアウトは新しいワークアウトとして扱われ、別個に同期されます。名前・日付・内容が一致していても、削除済みのワークアウトに再接続されることはありません。同じワークアウトに関する重複通知によって余分なコピーが作られることもありません。

### もう一方の画面がまだ更新されないのはなぜですか？

両方の画面が同時に即時更新されるわけではありません。システムはプラットフォームからの通知を受け取りつつ、予定ワークアウトを定期的にチェックします。毎日の自動チェックは、あなたのタイムゾーンにおける昨日から向こう 7 日間を対象とします。

ワークアウトをその日付範囲外に移動しただけでは削除とはみなされず、移動先が個別に確認されます。また、接続が一時的に利用できない場合も、もう一方のコピーが削除されることはありません。

## 連携の解除

連携を解除すると、今後の同期が停止され、有効な認証情報が削除されます。通常、すでに取り込まれているアクティビティは削除されません。アクティビティを個別に削除する場合は、保持したい唯一のコピーではないことを確認してから行ってください。

## 接続を確認する

- 該当する場合、プラットフォームカードが接続済み状態になっていること
- 手動同期が認可エラーではなく、完了またはキュー登録の結果を返すこと
- インポートされたアクティビティに想定通りのソースが表示されていること
- ダイアログを開き直したときに、保存した同期設定が維持されていること

## トラブルシューティング

### 認可後にカードが未接続のまま戻る

求められた権限をすべて承認したか、およびブラウザが同じ Trainingload.ai アカウントに戻っているかを確認してください。古い認可 URL を使い回さず、プラットフォームカードからやり直してください。API キー連携の場合は、期限切れまたは無効化されたキーをダイアログ内で差し替えてください。

### 接続は成功したのにアクティビティが表示されない

プラットフォーム側の対象期間とアクティビティ種別を確認してください。用意されている手動同期または初回同期を 1 回実行し、インポートジョブの処理を待ちます。対象期間外の記録は FIT・TCX・GPX でエクスポートし、ファイルアップロードを利用してください。

### 同じワークアウトが複数表示される

各アクティビティに表示されているソースを確認してください。主経路を 1 つに絞り（例：COROS 直接、または Strava 経由のどちらか）、過去の履歴を追加インポートする前に重複経路を無効化してください。どちらかを削除する前に重複警告を確認しましょう。

### 心拍数・パワー・GPS・筋力詳細が欠けている

まず元のプラットフォームでワークアウトを開いて確認してください。連携元が公開していないストリームデータは取り込めません。元データに存在する場合は処理完了を待ち、可能であればプラットフォームの突き合わせ同期を再実行してください。

### このページにある操作が画面に表示されない

現在のアカウント・プラットフォーム・端末において有効な操作は、接続ダイアログの表示が最終基準となります。一部の操作はプラットフォーム側の審査状況、サブスクリプションプラン、または段階的公開状況に依存します。

## よくある質問

### Trainingload.ai はどのトレーニングアプリ連携に対応していますか？

Strava、Polar、COROS、Intervals.icu、Suunto、Wahoo は継続接続に対応しています。Garmin は新規データ向けの OAuth 接続と、過去履歴向けのファイルインポートに対応しています。FIT・TCX・GPX は単発ファイルや非対応ウォッチ向けです。

### Strava連携とGarminインポートはどちらを使うべきですか？

新しい Garmin ワークアウトには Garmin OAuth 接続を、認可前の過去記録には履歴インポートを使用してください。同じワークアウトが Strava にも届く場合は、重複を避けるため主経路を 1 つに決めてください。

### 同じウォッチに対して 2 つの連携を有効にしてもよいですか？

設定自体は可能ですが、同じ記録を二重にインポートしないようにしてください。大量の履歴を取り込む前に、主経路を 1 つに決めましょう（例：COROS 直接のみとし、Strava 転送を重ねない）。

### 連携はどこから設定しますか？

Web ではサイドバー下部のアカウントメニューから **アカウント** を開き、**サードパーティ連携** までスクロールします。モバイルでは **マイページ → メニュー → データ認可** を開きます。プラットフォーム別の手順は[Strava・Garmin・COROSを接続してワークアウトを取り込む](/ja/docs/guide/connect-third-party-platforms)を参照してください。
