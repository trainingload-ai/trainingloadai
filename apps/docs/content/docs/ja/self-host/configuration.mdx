# セルフホストインスタンスを設定する

データの保存場所とローカルアクセス用ポートはインストール前に決めておきます。インストール後は、アプリ内の設定画面から AI プロバイダーの選択や変更を行えます。

## 始める前に

- リリースバンドル付属の `.env.example` とインスタンススキーマに定義された設定項目のみを使用してください。
- 状態を変更するライフサイクル操作の前には、必ず対応する `--dry-run --json` を実行してください。
- `.env.selfhost`、パスワード、API キー、トークンをチャット、Issue、共有ターミナルログへ貼り付けないでください。
- 既存のデータディレクトリにはトレーニング記録が入っています。手動で置き換えたり空にしたりしないでください。

## ローカルのデータ保存先を選ぶ [#choose-the-local-data-path]

デフォルトはリリースディレクトリ内の `./data` です。ここには PostgreSQL データ、アップロードファイル、操作記録、バックアップ、キャッシュが格納されます。アプリケーションはホスト側のアップロードパスを `/data/uploads` にマウントするため、別途オブジェクトストレージを用意する必要はありません。

初回インストール前に別のパスを指定する手順は次のとおりです。

1. 展開・検証済みのリリースディレクトリで、付属テンプレートから非公開のインスタンス設定ファイルを作成します。

   ```bash
   umask 077
   cp .env.example .env.selfhost
   chmod 600 .env.selfhost
   ```

2. `openssl rand -hex 32` で異なる 32 バイトの値を3つローカル生成し、`.env.selfhost` 内の3つのシークレットプレースホルダーを置き換えます（通常のインストーラーではこの処理が自動実行されます）。
3. `SELF_HOST_DATA_ROOT` のコメントを外し、専用パスを指定します。

   ```dotenv
   SELF_HOST_DATA_ROOT=/srv/trainingload-data
   ```

4. 通常のインストーラーでドライランを実行し、`"ok": true` が返ったことを確認してから本実行します。

   ```bash
   ./install.sh --dry-run --json
   ./install.sh --json
   ```

指定先は未作成のパスか、このインスタンス専用のディレクトリである必要があります。管理 CLI はファイルシステムのルート、リリースディレクトリの親階層、署名済みリリース配下、安全でないシンボリックリンク、無関係な既存ファイルを含むパスを拒否します。

稼働中のインスタンスでファイル移行の代わりに `SELF_HOST_DATA_ROOT` を書き換えないでください。既存インスタンスの移行には、検証済みバックアップを取得して新規初期化した移行先へリストアする手順が必要です。

## ネットワーク公開範囲を制御する

公開されるのは Client の HTTP ポートのみで、デフォルトではループバックにバインドされます。

```dotenv
SELF_HOST_SITE_ADDRESS=http://localhost:43210
SELF_HOST_HTTP_BIND=127.0.0.1
SELF_HOST_HTTP_PORT=43210
```

別の空きポートを使う場合は、サイトアドレスと HTTP ポートの両方を変更してください。PostgreSQL と Server は Compose のプライベートネットワーク内に保ちます。別のパソコンから利用する場合は、ブラウザのオリジンをローカルに保ったまま SSH トンネルを使用してください。アプリケーションバンドルには Caddy、HTTPS ポート、Docs プロファイルは含まれていません。

ホスト設定を変更したあとは、ライフサイクル CLI を通して検証・反映します。

```bash
./self-host start --dry-run --json
./self-host start --json
./self-host doctor --json
```

### ローカルからのアクセス経路

設定したローカルアドレスをブラウザで開いてアクセスします。データベースや内部アプリケーションサービスに公開ポートは不要です。接続トラブルの回避策としてこれらをインターネットに公開しないでください。

## 個人用アカウント

初回起動時にユーザー名を入力し、案内に沿って初期設定を進めます。1つのインスタンスは1名専用であり、一般登録や複数アカウントには対応していません。

セルフホスト版ではクラウド版のサインアップやソーシャルログインではなく、ローカルアカウントを使用します。期限切れになったローカルセッションは自動的に復元されます。アカウント削除を確定すると、そのアカウントのデータが削除され、完了後にインスタンスはユーザー名設定画面へ戻ります。バックアップやインスタンス設定ファイルは別管理のため、アカウントを削除してもそれらのファイルは消去されません。

## Intervals.icu を連携する [#connect-intervalsicu]

セルフホスト版では Owner の**個人 API キー**で Intervals.icu と接続します。Intervals.icu の OAuth クライアント、リダイレクト URI、Webhook は不要でありサポートされていません。

セルフホスト版では [Garmin Personal API](/ja/docs/self-host/garmin-personal-api) にも対応しています。COROS MCP は無効です。いずれの個人連携でもホスト側への追加シークレット設定は不要です。

Intervals.icu の連携手順は次のとおりです。

1. [Intervals.icu の設定ページ](https://intervals.icu/settings)を開き、ページ下部付近にある個人 API キーをコピーします。Client の連携ダイアログにある **Get API Key** ボタンから直接このページを開けます。
2. オンボーディングのアクティビティ取り込みステップで **Intervals.icu** を選ぶか、後から **Account → Third-party connections → Intervals.icu** を開きます。
3. API キーを入力し、必要なアクティビティ・予定ワークアウト・ウェルネス・スポーツ設定の同期方向を選択して保存します。
4. 手動同期を1回実行し、最終同期時刻とインポート結果を確認します。

[Intervals.icu の Open API ドキュメント](https://www.intervals.icu/features/open-api/)に記載のとおり、各ユーザーは個人 API キーでアクティビティの送受信、ウェルネスデータ、予定ワークアウトの REST API を利用できます。キーはローカルの Server にのみ送信されます。Server はインストール時に生成された専用の連携シークレットを用いて AES-256-GCM で暗号化し、暗号文を PostgreSQL に保存するため、以降の API レスポンスで平文が返ることはありません。

これはオフライン機能ではありません。有効化すると、ローカルの Server が `intervals.icu` へ直接接続し、選択した方向に従ってデータを送受信します。キーは個人の Intervals.icu アカウントに紐づくため、共有環境変数に入れたり、ログ・Issue・チャットへ貼り付けたりしないでください。

バックアップには API キーの暗号文が含まれますが、インスタンスシークレットは別の安全な場所に保管する必要があります。保存済み認証情報を復号できるよう、リストア時はデータベースとあわせて元の認証シークレットおよび連携シークレットを復元してください。管理ツールはこれらのシークレットを出力・エクスポートしません。詳しい手順はリリースバンドル内の `BACKUP_RESTORE.md` を参照してください。

## Client で AI を設定する [#configure-ai-in-the-client]

AI はデフォルトで無効になっています。オンボーディングの最終ステップでは、Trainingload.ai クラウドのプロバイダー同意画面の代わりに BYOK AI 設定が表示されます。スキップして後から設定することも可能です。

1. ローカルの Client を開きます。
2. オンボーディング中に **Configure your AI service** を開くか、後から **Settings → Self-hosted AI** を開きます。
3. OpenAI、DeepSeek、OpenRouter、DashScope、または **Custom OpenAI-compatible** から選択します。
4. 新規設定またはプロバイダー変更時に API キーを入力し、標準モデルと推論モデルの両方を記入します。組み込みプロバイダーでは Base URL を空欄にすればデフォルトエンドポイントが使われますが、カスタムの OpenAI 互換プロバイダーでは必須です。
5. 保存したら AI 機能を開き、リクエストが1回正常に通ることを確認します。

モデル ID はお使いのプロバイダーがサポートする識別子を指定してください。リモートの Base URL には HTTPS を使用してください。LAN 内のカスタムモデルエンドポイントで HTTP を使用してよいのは、そのネットワーク経路をご自身で把握・管理している場合のみです。

OpenAI の API キーは ChatGPT Plus / Pro のサブスクリプションとは別契約です。ChatGPT のサブスクリプションを API キーとして入力することはできず、本インスタンスの API 利用料も含まれません。

### キーの保存方法

- ブラウザはキーをローカルの `server` にのみ送信します。
- サーバーはインスタンスの認証シークレットから暗号鍵を導出し、AES-256-GCM で暗号化して PostgreSQL に保存します。
- 以降の API レスポンスではキーが設定済みかどうかのみを返し、平文キーは一切返しません。
- アプリ内で保存した AI 設定は即時反映され、環境変数による設定より優先されます。
- **None** を選択すると保存済みのプロバイダー認証情報が削除され、AI が無効化されます。

リストア時はデータベースとあわせて元のインスタンス認証シークレットを復元してください。別のシークレットでは既存の AI 認証情報や認証状態を復号できないため、再起動前に元の設定であることを確認してください。

### ホスト外へ送信されるデータ

AI を無効にしたままでも、アクティビティ管理、トレーニングプラン、分析機能はすべて使えます。外部 AI プロバイダーを有効にした場合は、応答に必要な質問文とトレーニング情報がそのプロバイダーへ送信されます。事前にプロバイダーのデータ保持・プライバシー・データ保管地域・課金条件を確認してください。

セルフホスト版では Trainingload.ai クラウドの会員プランや AI クレジットは使われません。**AI Usage** 画面では、ご自身のプロバイダー利用時の課金の仕組みを確認できます。実際の API 利用量、残高、請求書は契約先プロバイダーのダッシュボードで確認してください。

## 公開ファイルツール向けの任意診断設定

`.env.selfhost` で `PUBLIC_FAILED_UPLOAD_CAPTURE_ENABLED=true` を設定すると、公開ファイルツールでサーバーエラーが発生した際に元ファイルを保持できます。デフォルトは `false` です。保持ファイルには GPS などの個人情報が含まれる可能性があります。保存先は `data/operations/public-upload-failures` でバックアップ対象外となり、72時間経過するか容量・件数上限に達した時点で自動削除されます。

## 自動プロビジョニング向けの環境変数フォールバック

無人プロビジョニング向けに、リリーススキーマでは `.env.selfhost` にプロバイダー設定一式を記述する方式も引き続き受け付けます。ただしこれはフォールバック用途であり、対話的な設定方法としては推奨されません。Client は環境変数キーを表示せず、環境変数管理から Client 管理へ切り替える際には Owner が新しいキーを入力する必要があります。

## 確認項目

- ホストレベルの設定変更後、`./self-host doctor --json` が `"ok": true` を返す。
- データルートにインスタンスマーカーと所定のサブディレクトリが存在し、無関係なファイルが含まれていない。
- AI 設定ページがインスタンスの Owner にのみ表示される。
- AI 設定の保存後、入力欄がクリアされ、キー設定済みであることだけが表示される。
- セルフホストのサードパーティ連携ページに Intervals.icu と Garmin Personal API（いずれも OAuth ではなく API キー方式）が表示され、COROS MCP が利用可能として表示されない。
- **AI Usage** ページに会員購入、クレジット残高、クレジットパックが表示されず、`/billing/*` エンドポイントを呼び出さない。
- Intervals.icu キーの保存後、入力欄がクリアされて末尾4文字のみが表示され、手動同期が成功する。
- AI を無効にしても AI 以外の機能には影響せず、外部プロバイダーへの新規リクエストが停止する。

## トラブルシューティング

- **データルートが拒否される：** リリースツリー外の空の専用パスを指定してください。マーカーやシンボリックリンクの検証を回避しないでください。
- **AI 設定セクションが表示されない：** インスタンスがセルフホスト構成であり、作成済みの Owner としてサインインしているか確認してください。
- **プロバイダー変更時にキーの再入力を求められる：** プロバイダー変更時には新しい認証情報の入力を求める仕様です。
- **リストア後に AI が動かなくなった：** 再起動前に元のインスタンス認証シークレットを復元してください。
- **リストア後に Intervals.icu が動かなくなった：** データベースとあわせて元の連携シークレットが復元されているか確認してください。
- **モデルがプロバイダー側で拒否される：** プロバイダーアカウントから正確なモデル ID をコピーし、使用中の API キーにそのモデルへのアクセス権限があるか確認してください。
