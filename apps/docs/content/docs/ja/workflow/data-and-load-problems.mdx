# アクティビティ・トレーニング負荷・回復データの問題を診断する

## 症状から確認を始める

| 症状 | 最初に確認する項目 | 次に参照するガイド |
| --- | --- | --- |
| アクティビティが見当たらない | 連携先プラットフォームの接続状態、インポート期間、ファイル処理ステータス | [データの連携](/ja/docs/guide/connect-data) |
| アクティビティが重複している | 複数のインポート経路とソース側の識別子 | [外部サービス連携](/ja/docs/guide/integrations) |
| アクティビティはあるが負荷が計算されない | 処理ステータス、時間、心拍数・パワー・ペースの有無、プロフィール閾値 | [アクティビティ詳細](/ja/docs/guide/activity-detail) |
| チャートやラップが表示されない | 元ファイルにレコード列やラップ情報が含まれているか | [アクティビティファイルのアップロード](/ja/docs/guide/upload-activity-files) |
| 睡眠・HRV・安静時心拍数が空になっている | 健康データの権限、連携先での対応範囲、日付、タイムゾーン | [アカウント・権限・利用状況](/ja/docs/guide/account-permissions-and-usage) |
| PMC が想定より極端に低い、または高い | 重複記録、欠損日、選択中の種目、負荷ソース、閾値の変更履歴 | [トレーニング分析ワークフロー](/ja/docs/guide/training-analysis-workflow) |

## 順番に原因を切り分ける

1. 想定しているデータソースと対象期間を確認します。
2. そのデータソースが必要なセンサーストリームを提供しているか確認します。
3. インポートと処理のステータスを確認します。
4. プロフィールの閾値と負荷ソースの優先順位を確認します。
5. 問題が出ているアクティビティ1件と、正常に処理されたアクティビティ1件を比較します。
6. ここまで確認したうえで、必要に応じて設定変更やサポートへの問い合わせを行います。

## サポート用に安全な情報を整理する

問い合わせる際は、アクティビティの日付、種目、データソース、画面上のステータス、期待した動作と実際の結果、再現性をまとめてください。メールアドレス、OAuth トークン、API キー、正確な自宅位置、連携先の非公開識別子は必ず取り除いてください。

好みの負荷値に合わせる目的だけで閾値を書き換えないでください。設定変更は今後の解釈に影響し、派生指標の履歴も変わる可能性があります。
