# 훈련 앱 연동 옵션: Strava, Garmin, COROS 동기화

훈련 기록을 어디에서 가져올지 고른 뒤, 지속적 자동 동기화가 필요한지 일회성 과거 기록 가져오기가 필요한지 결정합니다. 이 페이지는 Cloud 환경의 연동을 다루며, 구체적인 연동 절차는 [Strava, Garmin, COROS 등 플랫폼 연동](/ko/docs/guide/connect-third-party-platforms)을 따르세요.

셀프 호스팅 환경이라면 별도의 [Intervals.icu 설정](/ko/docs/self-host/configuration#connect-intervalsicu)과 [Garmin Personal API 가이드](/ko/docs/self-host/garmin-personal-api)를 참고하거나 활동 파일을 직접 업로드하세요.

플랫폼별 제공 여부와 지원 방향은 변경될 수 있으므로, 최종 기준은 연동 대화상자에 실제로 표시되는 옵션을 따릅니다.

## 연동 전 확인 사항

- 가져오려는 훈련 데이터가 저장된 플랫폼 계정으로 로그인합니다.
- 각 활동의 주 소스가 될 플랫폼을 하나 정합니다. 같은 워크아웃이 연동된 두 서비스를 거쳐 중복 전달되지 않도록 주의하세요.
- 지속적 연동, 일회성 과거 기록 가져오기, 파일 업로드 중 어떤 방식이 필요한지 확인합니다.
- 플랫폼 로그인 정보나 API 키는 준비해 두되, 반드시 공식 연동 대화상자 안에서만 입력하세요.
- 첫 가져오기가 성공했는지 쉽게 알아볼 수 있도록 현재 Trainingload.ai에 표시된 가장 최근 활동을 확인해 둡니다.

## 가져오기 경로 선택

| 소스 | 가장 적합한 용도 | 연동 방식 |
| --- | --- | --- |
| Strava | 지속적인 활동 동기화 | 동기화 설정이 포함된 계정 연동 |
| Polar | 지속적인 Polar 활동 가져오기 | OAuth 연동 및 동기화 설정 |
| COROS | 활동 및 일일 데이터 동기화, 호환 플랜 내보내기 | 수동 동기화 제어가 포함된 계정 연동 |
| Intervals.icu | 활동 동기화 및 호환 예정 워크아웃 워크플로 | 계정 구성에 따라 OAuth 또는 API 키 |
| Suunto | 지속적인 워크아웃 가져오기 및 지원 가이드 워크플로 | OAuth 연동 및 동기화 설정 |
| Wahoo | 지속적인 Wahoo 워크아웃 가져오기 | OAuth 연동 및 동기화 설정 |
| Garmin | 신규 훈련 동기화 또는 과거 활동 기록 가져오기 | OAuth 연동 또는 파일 가져오기 |
| FIT / TCX / GPX | 개별 파일 또는 미지원 소스의 내보내기 파일 | 수동 업로드 |

## 플랫폼 연동 절차

1. 해당 플랫폼 카드를 선택합니다.
2. 요청하는 데이터 방향과 설정 항목을 확인합니다.
3. OAuth로 권한을 승인하거나 필요한 API 키를 입력합니다.
4. 동기화 환경설정을 저장합니다.
5. 대화상자에서 초기 동기화(initial sync)를 제공하면 실행합니다.
6. **Activities(활동)**를 열어 가장 최근에 가져온 워크아웃을 확인합니다.

플랫폼 API 키는 절대 AI 코치, 플랜 메모 또는 지원용 스크린샷에 붙여 넣지 마세요. 반드시 플랫폼 연동 대화상자에서만 사용해야 하며, 저장된 시크릿은 클라이언트에 다시 표시되지 않습니다.

## 초기 동기화와 자동 동기화의 차이

초기 동기화(initial sync)는 대상이 되는 최근 기간을 가져오거나 과거 기록 가져오기 작업을 시작합니다. 자동 동기화(automatic sync)는 앞으로 발생하는 플랫폼 이벤트를 처리합니다. 일부 플랫폼은 누락된 알림을 보완하기 위한 수동 동기화(재조정) 동작도 제공합니다.

대량 가져오기를 진행하는 동안에는 다음을 지켜 주세요.

- 현재 배치가 끝날 때까지 같은 작업을 다시 시작하지 않습니다.
- 항목별 처리 속도에 따라 활동이 순차적으로 표시될 수 있습니다.
- 연동을 반복해서 해제·재연결하기보다 중복 감지 결과를 먼저 확인합니다.
- 특정 센서 스트림이 비어 있다면 원본 플랫폼 데이터를 먼저 확인합니다.

## Garmin 과거 기록 가져오기

**현재 공식 Garmin OAuth 연동으로는 권한 승인 이전에 기록된 과거 활동을 불러올 수 없습니다. 연동을 해제했다가 다시 연결해도 과거 기록은 채워지지 않습니다.** 과거 기록을 가져오려면 Garmin 전체 내보내기 ZIP(또는 임시 다운로드 링크)을 가져오거나 개별 FIT, TCX, GPX 파일을 업로드하세요. 이 제약은 셀프 호스팅용 Garmin Personal API에는 해당하지 않으므로 셀프 호스팅 사용자는 별도 가이드를 따르세요.

Garmin 설정 페이지에서 **OAuth**는 앞으로 기록되는 새 활동과 승인된 건강 요약을 수신하며, **File import(파일 가져오기)**는 과거 훈련 기록을 불러옵니다. 둘은 별개 동작이므로 목적에 맞게 선택하세요.

## Intervals.icu 예정 워크아웃 동기화 동작 방식

여기서 말하는 예정 워크아웃은 완료된 활동 기록이 아니라 캘린더에 예정된 훈련을 뜻합니다. Intervals.icu 연동 설정에서는 **Import planned workouts(예정 워크아웃 가져오기)**와 **Export planned workouts(예정 워크아웃 내보내기)**를 각각 따로 켤 수 있습니다.

- **Import planned workouts**: Intervals.icu의 추가·수정·삭제 내역을 Trainingload.ai로 가져옵니다.
- **Export planned workouts**: Trainingload.ai의 추가·수정·삭제 내역을 Intervals.icu로 내보냅니다.

**양방향을 모두 켜 두면 삭제도 함께 동기화됩니다.** 마지막 동기화 이후 반대쪽 사본이 수정되지 않았다면, 한쪽에서 삭제할 때 반대쪽 사본도 함께 삭제됩니다.

### 워크아웃을 추가·수정·삭제하면 어떻게 되나요?

아래 표는 양방향 동기화가 모두 켜져 있을 때 기준입니다.

| 수행한 작업 | 반대쪽에서 일어나는 일 |
| --- | --- |
| Trainingload.ai에서 워크아웃 추가 | Intervals.icu에 대응하는 새 워크아웃이 생성됩니다. |
| Intervals.icu에서 워크아웃 추가 | Trainingload.ai에 대응하는 새 워크아웃이 생성됩니다. |
| Trainingload.ai의 날짜·이름·처방만 수정 | 대응하는 Intervals.icu 워크아웃이 업데이트됩니다. |
| Intervals.icu의 날짜·이름·처방만 수정 | 대응하는 Trainingload.ai 워크아웃이 업데이트됩니다. |
| Trainingload.ai에서 워크아웃 삭제 | 반대쪽이 수정되지 않았다면 Intervals.icu 사본도 삭제됩니다. 수정되었다면 수정된 사본이 유지됩니다. |
| Intervals.icu에서 워크아웃 삭제 | 반대쪽이 수정되지 않았다면 Trainingload.ai 사본도 삭제됩니다. 수정되었다면 수정된 사본이 유지됩니다. |

### 양쪽 사본을 모두 수정하면 어느 쪽이 우선하나요?

현재 실행 중인 동기화 방향에 따라 결정됩니다.

- Intervals.icu에서 가져올 때(Import)는 Intervals.icu 버전이 적용됩니다.
- Intervals.icu로 내보낼 때(Export)는 Trainingload.ai 버전이 적용됩니다.

일일 자동 동기화는 가져오기(Import)를 먼저 실행한 뒤 내보내기(Export)를 실행합니다. 따라서 자동 동기화 시점에 양쪽 모두 수정되어 있었다면 Intervals.icu 버전이 우선합니다.

수정한 내용이 덮어씌워지지 않도록 한쪽에서 편집을 마치고 동기화가 완료된 뒤 다른 쪽에서 이어서 편집하는 것을 권장합니다.

### 한쪽을 삭제했는데 반대쪽 사본이 그대로 남아 있는 이유는?

남아 있는 사본이 마지막 동기화 이후 수정되었기 때문입니다. 이 경우 수정된 내용은 보존되고, 두 워크아웃의 상호 동기화는 중단되며, 방금 삭제한 워크아웃을 동기화가 즉시 되살리지도 않습니다.

예를 들어 Trainingload.ai에서 일요일 러닝을 토요일로 옮긴 뒤 Intervals.icu에서 일요일 러닝을 삭제하면, Trainingload.ai는 토요일 러닝을 유지하고 Intervals.icu에서 삭제한 워크아웃도 다시 생성되지 않습니다.

시스템이 반대쪽 사본의 변경 여부를 확정할 수 없을 때는 함부로 삭제하지 않고 보존합니다. 또한 완료되었거나 건너뛴 워크아웃, 실제 활동과 연결된 워크아웃 역시 보관해야 할 기록을 유지합니다.

### 워크아웃을 삭제한 뒤 같은 이름으로 새로 만들면 어떻게 되나요?

새로 만든 워크아웃은 별개의 신규 항목으로 취급되어 독립적으로 동기화됩니다. 이름, 날짜, 처방 내용이 같더라도 이전에 삭제된 워크아웃과 다시 연결되지 않으며, 같은 워크아웃에 대한 반복 알림으로 중복 사본이 생기지도 않습니다.

### 반대쪽이 즉시 업데이트되지 않는 이유는?

양쪽 화면이 실시간으로 동시에 갱신되지는 않습니다. 시스템은 플랫폼 알림을 수신하고 예정된 워크아웃을 주기적으로 확인합니다. 일일 자동 점검은 사용자 시간대 기준으로 어제부터 향후 7일간을 대상으로 합니다.

워크아웃을 그 날짜 범위 밖으로 이동하더라도 삭제된 것으로 간주되지 않으며, 이동한 위치를 별도로 확인합니다. 일시적인 연결 장애 때문에 반대쪽 사본이 삭제되는 일도 없습니다.

## 연동 해제

연동을 해제하면 앞으로의 동기화가 중단되고 활성 인증 정보가 제거됩니다. 이미 가져온 활동은 일반적으로 삭제되지 않습니다. 활동을 삭제하려면 보존해야 할 유일한 사본이 아닌지 확인한 뒤 별도로 삭제하세요.

## 연동 정상 여부 확인

- 해당하는 경우 플랫폼 카드에 연동됨(Connected) 상태가 표시됩니다.
- 수동 동기화 실행 시 인증 오류가 아니라 완료 또는 대기열 등록 결과를 반환합니다.
- 가져온 활동에 기대한 소스 이름이 표시됩니다.
- 설정 대화상자를 다시 열었을 때 저장한 동기화 설정이 그대로 유지됩니다.

## 문제 해결

### 권한 승인 후에도 카드가 연동 해제 상태로 돌아옵니다

요청된 권한을 모두 승인했는지, 브라우저가 같은 Trainingload.ai 계정으로 돌아왔는지 확인하세요. 예전 인증 URL을 재사용하지 말고 플랫폼 카드에서 다시 시작하세요. API 키 연동이라면 만료되었거나 폐기된 키를 대화상자에서 교체합니다.

### 연동은 성공했는데 활동이 나타나지 않습니다

플랫폼이 지원하는 날짜 범위와 활동 유형을 확인하세요. 수동 또는 초기 동기화를 한 번 실행하고 가져오기 작업이 처리될 때까지 기다립니다. 지원 범위를 벗어난 과거 기록이라면 FIT, TCX, GPX로 내보내 파일 업로드를 이용하세요.

### 같은 워크아웃이 두 번 이상 표시됩니다

각 활동에 표시된 소스를 확인하세요. 예를 들어 COROS 직접 가져오기 또는 Strava를 통한 COROS 전달 중 하나만 주 경로로 유지하고, 추가 기록을 가져오기 전에 중복 경로를 비활성화합니다. 어느 사본을 삭제하기 전에 중복 경고를 먼저 확인하세요.

### 심박수, 파워, GPS 또는 근력 상세 데이터가 빠져 있습니다

먼저 원본 플랫폼에서 해당 워크아웃을 열어 확인하세요. 외부 플랫폼이 제공하지 않는 스트림은 Trainingload.ai가 가져올 수 없습니다. 원본에는 데이터가 있는데 누락되었다면 처리가 끝날 때까지 기다린 뒤 플랫폼의 재조정(수동 동기화) 기능을 사용해 보세요.

### 이 문서에 설명된 옵션이 화면에 보이지 않습니다

현재 계정, 플랫폼, 환경에서 실제 사용 가능한 기능의 기준은 연동 대화상자입니다. 일부 기능은 플랫폼 승인, 구독 등급 또는 단계적 배포 상태에 따라 달라질 수 있습니다.

## 자주 묻는 질문(FAQ)

### Trainingload.ai는 어떤 훈련 앱 연동을 지원하나요?

Strava, Polar, COROS, Intervals.icu, Suunto, Wahoo는 지속 연동을 지원합니다. Garmin은 신규 데이터용 OAuth 연동과 과거 기록용 파일 가져오기를 제공합니다. FIT, TCX, GPX 업로드는 개별 파일이나 미지원 워치에 활용할 수 있습니다.

### Strava 연동과 Garmin 가져오기 중 무엇을 써야 하나요?

새로운 Garmin 워크아웃은 Garmin OAuth를, 과거 기록은 Garmin 기록 가져오기를 사용하세요. 같은 워크아웃이 Strava로도 전송된다면 중복을 막기 위해 하나의 주 가져오기 경로만 선택하는 것이 좋습니다.

### 같은 워치에 대해 두 가지 연동을 동시에 켤 수 있나요?

켤 수는 있지만 같은 기록을 중복으로 가져오지 않도록 주의해야 합니다. 대량 과거 기록 가져오기를 실행하기 전에 하나의 주 경로(예: COROS + Strava 전달이 아니라 COROS 직접 연동)만 선택하세요.

### 연동 설정은 어디에서 진행하나요?

웹에서는 사이드바 하단의 계정 메뉴를 열고 **Account(계정)**를 선택한 뒤 **Third Party Connections(서드파티 연동)**로 스크롤합니다. 모바일에서는 **Me → Menu → Data authorization**을 엽니다. 플랫폼별 상세 절차는 [Strava, Garmin, COROS 등 플랫폼 연동](/ko/docs/guide/connect-third-party-platforms)을 따르세요.
