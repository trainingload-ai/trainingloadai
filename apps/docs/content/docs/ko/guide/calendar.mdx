# 훈련 캘린더에서 계획과 실제 훈련 비교하기

훈련 캘린더는 앞으로의 계획과 실제로 기록된 훈련을 하나의 날짜 축 위에 함께 보여 줍니다. 같은 날짜에 표시되더라도 예정된 워크아웃과 완료된 활동은 별개의 기록이므로, 상세 정보와 연결 상태를 통해 해당 기록이 실제로 그 예정 세션을 수행한 결과인지 확인해야 합니다.

[데모에서 캘린더 열기](https://demo.trainingload.ai/en/calendar)에서 화면을 미리 살펴볼 수 있습니다. 스크린샷은 실제 웹 앱의 샘플 플랜과 활동 데이터를 사용했습니다. 데모에서는 날짜 탐색과 조회만 가능하며, 활동 연결이나 일정 변경을 저장하려면 본인 계정이 필요합니다.

## 시작하기 전에

계정 시간대와 활동 시작 시각을 먼저 확인합니다. 예정된 훈련의 경우 진행 중인 플랜의 시작일과 워크아웃 일정을 점검하세요. 새로 가져온 활동은 분석 처리가 끝날 때까지 기다린 뒤 부하 누락 여부를 판단합니다.

웹과 macOS용 Trainingload.ai Personal에서는 사이드바에서 **Calendar(캘린더)**를 엽니다. 좁은 웹 화면에서는 달력 버튼으로 월 선택기를 열 수 있고, 모바일 앱에서는 **Calendar** 탭을 엽니다.

## 1. 날짜 찾기 및 선택

넓은 화면에서는 캘린더를 스크롤하거나 월 선택기와 화살표를 사용합니다. 날짜를 선택하면 해당 일간 패널이 열리며, **Today(오늘)** 버튼으로 현재 날짜로 바로 돌아올 수 있습니다.

선택한 날짜에 따라 일간 패널의 내용이 바뀝니다. 하루에는 플랜 소속 예정 세션, 독립 예정 워크아웃, 기록된 활동 또는 이들의 조합이 함께 있을 수 있으므로 항목 라벨을 확인한 뒤 여세요.

## 2. 일간 패널 읽기

**Training(훈련)** 탭에서 예정된 워크아웃을, **Activities(활동)** 탭에서 기록된 활동을 확인합니다. 선택한 날짜, 표시된 훈련 부하, 항목 개수를 검토하고, 전체 화면이 필요하면 **View day(하루 상세 보기)**를 선택합니다.

| 기록 유형 | 비교 전 확인할 항목 |
| --- | --- |
| 예정된 워크아웃 | 훈련 목적, 예정 날짜, 종목, 구성, 메모, 실행 상태 |
| 완료된 활동 | 시작 시각, 소스, 종목, 기록된 시간/거리, 처리 상태, 센서 포함 범위 |
| 연결(Association) | 올바른 활동이 실제로 의도한 워크아웃에 연결되어 있는지 여부 |

완료 라벨만으로는 어느 기록인지 알 수 없습니다. 실제 운동 강도와 내용을 살펴보려면 [활동 상세 분석](/ko/docs/guide/activity-detail)을 여세요.

## 3. 워크아웃에 올바른 활동 연결하기

본인 계정에서 예정된 워크아웃의 상세 화면을 열고 **Link activity(활동 연결)** 항목을 선택합니다.

1. 워크아웃에 예정 날짜가 설정되어 있고 종목이 맞는지 확인합니다.
2. 활동 상세에서 기록의 시작 시각을 먼저 확인한 뒤, 해당 날짜의 후보 목록에서 제목과 운동 시간을 비교해 일치하는 기록을 찾습니다.
3. 일치하는 기록을 선택하고 저장 성공 피드백이 뜰 때까지 기다립니다.
4. 해당 활동이 이미 다른 예정 세션에 연결되어 있다면 **Replace link?(연결을 교체할까요?)** 확인 안내를 읽고 결정합니다.
5. 워크아웃과 활동을 다시 열어 연결이 정상 반영되었는지 확인합니다.

후보 목록에 활동이 나타나지 않으면 동기화 상태, 활동의 현지 날짜, 워크아웃 일정, 종목 일치 여부를 점검하세요. 원인을 해결하지 않은 채 관련 없는 활동을 임의로 연결하지 마세요.

잘못 연결된 항목을 수정하려면 기존 연결의 **Remove link(연결 해제)**를 사용하거나 올바른 활동을 다시 선택합니다. 연결 해제와 활동 삭제는 서로 다른 작업입니다. 데모 계정에서는 이러한 쓰기 작업이 비활성화되어 있습니다.

## 4. 계획된 훈련과 실제 수행 비교하기

먼저 훈련 목적과 구성을 비교한 뒤, 기록된 시간·거리·강도·훈련 부하를 살펴봅니다. 세션을 단축했거나 대체·건너뛰기한 이유를 기록해 두면 이후 리뷰에 큰 도움이 됩니다. 원래 플랜에 없던 추가 활동도 실제 훈련 부하에 기여하는 중요한 기록입니다.

예상 부하나 실제 부하가 비어 있다면 0으로 간주하지 말고 역치, 종목, 처리 상태부터 확인하세요. 현재 워크아웃 상태에서 지원하는 완료, 건너뛰기, 연기 등 실행 제어는 [진행 중인 플랜 관리](/ko/docs/guide/manage-active-plan)를 참고합니다.

## 5. 요약 범위 확인하기

캘린더에서는 **Plan(플랜)** 요약과 **Month(월간)** 요약이 제공될 수 있습니다. 횟수, 거리, 시간, 훈련 부하를 비교하기 전에 현재 활성화된 범위와 날짜 경계를 먼저 확인하세요.

플랜 진행 요약은 현재 활성 주기를 기준으로 하고, 월간 개요는 화면에 보이는 달력 월을 기준으로 합니다. 비교 기간이 서로 다르므로 모든 요약이 같은 기간을 뜻한다고 가정하지 말고 표시된 맥락을 기준으로 읽으세요.

주간 단위 리뷰는 [주간 리뷰](/ko/docs/workflow/weekly-review)를, 누적 부하와 조건부 전망은 [PMC 예측](/ko/docs/guide/pmc-forecast)을 활용합니다.

## 결과 확인

선택한 날짜, 일간 패널, 열어 본 각 기록의 날짜가 서로 일치해야 합니다. 예정 워크아웃과 활동이 의도대로 연결되어 있어야 하며, 부하 비교 시 대상 범위와 누락 데이터 여부를 함께 파악할 수 있어야 합니다.

## 예정된 워크아웃 일정 조정하기 [#adjust-upcoming-workouts]

1. 진행 중인 플랜이 있을 때 웹 또는 Personal에서 날짜를 우클릭하고 **Adjust schedule(일정 조정)**을 선택합니다.
2. 예정된 워크아웃을 다른 날짜로 드래그하거나, 우클릭 후 **Move workout(워크아웃 이동)**으로 날짜를 지정합니다. 처방 내용을 바꾸려면 워크아웃 메뉴의 **Edit workout(워크아웃 편집)**을 사용하고, 날짜 메뉴로 새 워크아웃을 추가하거나 워크아웃 메뉴로 삭제할 수 있습니다. 편집기는 이 변경 사항을 하나의 초안(draft)으로 묶어 관리합니다.
3. 짝을 이루는 색상과 **Before(변경 전)** / **After(변경 후)** 라벨을 확인한 뒤 **Review changes(변경 검토)** → **Confirm plan changes(플랜 변경 확정)**를 눌러 일괄 적용합니다. 나중에 마무리하려면 편집기를 닫을 때 **Save draft(초안 저장)**를 선택하고, 이후 **Adjust schedule**에서 대기 중인 조정안을 다시 열 수 있습니다.
4. 캘린더를 다시 열어 바뀐 날짜와 워크아웃 내용을 확인합니다. 확정 전에 일정이 외부에서 변경되었다면 **Load latest schedule(최신 일정 불러오기)**을 눌러 적용 가능한 나머지 편집을 검토하세요.

좁은 화면에서는 워크아웃 메뉴나 드래그 핸들을 사용해 월간 그리드 안에서 이동할 수 있습니다. 이미 지났거나 완료되었거나 활동이 연결된 세션은 일정 변경이 제한될 수 있습니다.

메인 캘린더에서 워크아웃 하나만 옮기려면 새 날짜로 드래그하거나 메뉴에서 **Move workout**을 선택하고, 미리보기 날짜를 확인한 뒤 **Confirm adjustment**를 누릅니다.

AI 코치 대화에서 **View workout calendar(워크아웃 캘린더 보기)**가 제공되면 그 안에서 미리보기를 열어 지원하는 변경 사항을 검토·편집하고, 저장된 초안을 확인한 뒤 확정할 수 있습니다.

## 자주 묻는 질문

### 활동이 다른 날짜에 표시되는 이유는?

활동의 시작 시각 및 시간대를 계정의 표시 시간대와 비교하고, 플랜 시작일과 예정 날짜를 함께 확인하세요. 날짜 원인을 파악하기 전에 워크아웃을 임의로 옮기지 마세요.

### 플랜 워크아웃이 보이지 않는 이유는?

진행 중인 플랜 여부, 플랜 날짜 범위, 개별 워크아웃의 일정과 상태를 확인하세요. 이동했거나 건너뛴 세션은 원래 예상한 날짜에 표시되지 않을 수 있습니다.

### 한 번의 훈련에 기록이 두 개 표시되는 이유는?

예정된 세션과 실제 완료 활동은 별개의 기록입니다. 두 항목의 연결 상태를 확인하세요. 실제 활동 자체가 두 개 중복 생성된 경우라면 삭제하기 전에 중복 전달 경로나 중복 가져오기를 먼저 점검해야 합니다.

### 데모에서는 왜 활동을 연결할 수 없나요?

데모는 예시 데이터를 살펴보는 용도입니다. 활동 연결과 일정 변경은 본인 계정의 쓰기 권한이 필요합니다.

### 변경이 거부되면 어떻게 하나요?

오류 메시지를 읽고 최신 플랜이나 활동 상태를 새로고침한 뒤 다시 시도하세요. 재시도 후 의도한 연결이나 일정이 실제로 반영되었는지 확인합니다.
