# 훈련 데이터 연동

완료된 워크아웃을 Trainingload.ai로 가져온 뒤 날짜, 소스, 상세 데이터를 확인합니다. 원본 기록이 저장된 위치에 따라 플랫폼 연동, 파일 업로드 또는 모바일 기록 중 알맞은 방식을 선택하세요.

[데모에서 활동 둘러보기](https://demo.trainingload.ai/en/activities)에서 화면 구성을 미리 볼 수 있습니다. 실제 파일을 가져오거나 외부 플랫폼 권한을 연결하려면 본인 계정이 필요합니다. 업로드 스크린샷은 실제 앱의 샘플 계정 화면을 기준으로 합니다.

## 1. 데이터 소스 선택

| 경로 | 적합한 경우 | 이후 확인 사항 |
| --- | --- | --- |
| 지원 플랫폼 연동 | 가져오거나 동기화할 활동이 외부 플랫폼에 저장되어 있을 때 | 제공되는 동기화 방향, 기간 범위, 작업 결과 및 가져온 활동 |
| 원본 FIT, TCX, GPX 파일 | 특정 워크아웃, 아카이브 백업 또는 직접 연동이 없는 소스일 때 | 파일별 형식 검사 결과와 배치 가져오기 결과 |
| 모바일 기록 | Trainingload.ai 앱으로 직접 워크아웃을 기록할 때 | 완료된 기록의 동기화 상태와 생성된 활동 |

플랫폼별 지원 기능과 인증 절차는 [훈련 앱 연동 옵션](/ko/docs/guide/integrations)과 [Strava, Garmin, COROS 등 플랫폼 연동](/ko/docs/guide/connect-third-party-platforms)을 참고하세요. 현재 사용 중인 배포 환경과 계정에서 실제로 제공되는 기능을 기준으로 진행해야 하며, 일회성 과거 기록 가져오기(history import)와 지속적 자동 동기화(ongoing sync)는 서로 다른 기능입니다.

## 2. 기준 워크아웃에 대해 단일 주 경로 지정

확인용으로 날짜, 종목, 대략적인 운동 시간을 알고 있는 워크아웃 하나를 정해 둡니다. 같은 세션이 기기에서 여러 서비스로 전달된다면 대량 과거 기록 가져오기를 시작하기 전에 어느 경로를 주 소스로 삼을지 먼저 정해야 합니다.

원본 기록 파일은 보관해 두세요. 변환되었거나 요약 정보만 담은 파일은 원본 FIT 내보내기와 포함된 필드가 다를 수 있습니다. 활동 가져오기에는 운동 활동 기록이 필요하며, 종일 건강 지표만 담은 내보내기는 다른 데이터 유형입니다.

## 3. 선택한 경로로 가져오기

### 파일 업로드

1. **Activities(활동)**를 열고 업로드 진입점을 선택합니다.
2. 원본 파일을 선택하고 형식 검사가 끝날 때까지 기다립니다.
3. 감지된 파일 형식과 유효성 검사 오류가 있는지 확인합니다. 파일 확장자만으로는 실제 파일 형식이 보장되지 않습니다.
4. 업로드를 진행하며 중복 알림이 뜨면 내용을 확인합니다.
5. 배치 진행 상황 대화상자에서 파일별 결과를 확인합니다. 창을 닫았더라도 최근 배치를 다시 열어 확인할 수 있습니다.

파일 검사, 중복 처리, 배치 상태 확인 전체 절차는 [활동 파일 업로드](/ko/docs/guide/upload-activity-files)를 참고하세요.

### 플랫폼 동기화

해당 플랫폼의 연동 설정을 열어 제공되는 데이터 방향을 확인한 뒤 인증을 완료하고, 초기 가져오기 또는 수동 동기화가 제공된다면 실행합니다. 작업 결과가 완료될 때까지 기다린 뒤 **Activities(활동)**에서 기준 워크아웃을 찾습니다.

동기화 조건과 과거 기록 가져오기 범위는 플랫폼마다 다릅니다. 계정이 '연동됨(Connected)'으로 표시되더라도 기대한 과거 워크아웃이 이미 도착했다는 뜻은 아닙니다. 계정 정보나 인증 키는 반드시 플랫폼 공식 연동 흐름 안에서만 입력하세요.

### 모바일 기록

기록을 종료하고 저장한 뒤 앱이 동기화를 마칠 때까지 기다립니다. 같은 워크아웃을 다시 기록하기 전에 복구 대기 상태나 업로드 대기 상태를 먼저 확인하세요. 자세한 절차는 [모바일 활동 기록](/ko/docs/guide/mobile-recording)을 따릅니다.

## 4. 가져오기 진행과 활동 분석 구분하기

| 화면 표시 | 확인할 내용 |
| --- | --- |
| 가져오기 항목이 대기 중이거나 처리 중 | 가져오기 배치에서 최종 결과가 나올 때까지 기다립니다. |
| 완료됨(Done) 또는 활동 링크 표시 | 해당 활동을 열어 활동 자체의 분석 상태를 확인합니다. |
| 중복으로 건너뜀(Skipped as a duplicate) | 어떤 기존 활동과 일치했는지 확인합니다. |
| 부분 실패(Partial failure) | 어느 파일이나 분석이 실패했는지 파악하고 정상 완료된 결과를 활용합니다. |
| 실패(Failed) | 원본 파일 업로드나 플랫폼 동기화를 재시도하기 전에 해당 항목의 오류 메시지를 읽습니다. |

모든 차트나 파생 지표 계산이 끝나기 전에 활동 항목이 목록에 먼저 나타날 수 있습니다. 센서 데이터 누락, 분석 처리 요청 실패, 지원하지 않는 원본 파일은 각각 대응 방법이 다릅니다.

## 5. 기록된 활동 검증

소스, 종목, 현지 날짜, 운동 시간, 거리를 먼저 확인한 뒤, 기록에 실제로 포함된 측정값만 점검합니다.

| 원본 근거 데이터 | 지원되는 분석 |
| --- | --- |
| GPS 샘플 | 기록된 이동 경로 및 위치 기반 맥락 |
| 심박수 샘플 | 심박수 차트 및 지원하는 파생 분석 |
| 파워 샘플 | 파워 차트 및 역치 기반 분석 (추정 파워는 별도 라벨로 표시됨) |
| 사용 가능한 시계열 기록 | 지원하는 범위의 상세 차트, 타임라인 탐색, 구간 통계 |

외부 연동은 애초에 기록되지 않았거나 공유되지 않은 측정값을 만들어낼 수 없습니다. 기대한 항목이 빠져 있다면 가져오기를 반복하기 전에 원본 플랫폼과 원본 파일을 먼저 비교해 보세요.

## 6. 일일 훈련 흐름에 연결하기

[활동 상세 분석](/ko/docs/guide/activity-detail)을 열어 내용을 리뷰합니다. 캘린더에서 현지 날짜가 맞는지 확인하고 해당하는 예정 워크아웃에 연결합니다. 그다음 종목과 누적 기록을 기준으로 [PMC 예측](/ko/docs/guide/pmc-forecast)을 살펴봅니다.

활동 동기화가 완료되었다고 해서 수면, HRV, 모든 종일 건강 지표까지 함께 가져와지는 것은 아닙니다. 제공되는 데이터 카테고리별로 따로 확인하세요.

## 결과 확인

기준 워크아웃이 의도한 경로를 통해 한 번만 표시되고, 가져오기 및 분석 결과가 명확하며, 소스와 날짜가 정확하고 센서 포함 범위를 설명할 수 있어야 합니다. 예정된 세션에 해당하는 활동이라면 활동 정보를 확인한 뒤 연결을 확정하세요.

## 자주 묻는 질문

### 플랫폼을 연동했는데 활동이 보이지 않습니다

해당 플랫폼이 지원하는 기간 범위, 로그인한 원본 계정, 작업 결과, 활동 목록 필터를 확인하세요. 수동 동기화가 제공된다면 한 번만 실행하고, 작업이 끝날 때까지 기다린 뒤 다른 가져오기를 시도하세요.

### 같은 워크아웃이 두 번 표시됩니다

소스, 시작 시각, 운동 시간, 기록된 센서 범위를 비교하세요. 특히 한쪽이 훈련 플랜에 연결되어 있다면 기록을 삭제하기 전에 중복 전달 경로가 설정되어 있지 않은지 먼저 확인해야 합니다.

### 가져온 뒤 차트가 비어 있습니다

활동 분석이 아직 처리 중인지, 원본 파일에 시계열 샘플이 포함되어 있는지 확인하세요. 요약 수치만 있는 기록은 모든 차트를 제공하지 않습니다. 실제 요청 실패 오류라면 화면에 표시된 재시도 동작을 사용하세요.

### 연동을 해제하면 가져온 기록도 삭제되나요?

플랫폼 연동 해제와 활동 삭제는 별개의 작업입니다. 확인하기 전에 연동 해제 대화상자에 안내되는 영향을 읽고, 기존 활동은 별도로 확인하세요.
