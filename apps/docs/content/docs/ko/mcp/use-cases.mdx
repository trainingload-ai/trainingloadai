# MCP 활용 사례

아래 프롬프트를 TrainingLoad에 연결된 클라이언트에 그대로 붙여 넣어 보세요. 클라이언트가 나열된 모든 도구를 호출할 필요는 없으며, 질문에 답하는 데 필요한 최소한의 조합만 사용하면 됩니다.

## 현재 상태와 자각 피로

> TrainingLoad를 사용해 오늘 기준 내 훈련 상태를 요약해 주세요. 최근 7일을 그 직전 7일과 비교하고, 폼(TSB)과 예정된 다음 3개의 워크아웃을 포함하며, 사실과 추론을 구분해 주세요.

예상 경로: `get_training_snapshot` → `get_training_readiness` → 필요 시 `list_planned_workouts`.

답변에는 `asOf` 기준일, 시간대, 훈련 부하 차이, ATL/CTL/TSB 데이터 가용 여부, 그리고 준비도 출력은 의학적 판단이나 “훈련해도 안전함”에 대한 판정이 아니라 관찰 기반 훈련 부하 신호라는 점이 명시되어야 합니다.

## 두 훈련 블록 비교

> 2026년 9월 1~28일과 2026년 10월 1~28일을 비교해 주세요. 러닝, 사이클링, 수영별로 훈련 부하를 분해하고 데이터로 뒷받침되는 변화만 짚어 주세요.

예상 경로: `compare_training_periods` + `get_training_breakdown`.

반복해서 사용하려면 기본 제공 `compare-training-blocks` 프롬프트를 선택하세요. 훈련 부하와 무관하게 세션 수, 시간 또는 거리가 달라졌다면 `get_activity_statistics`를, 빈도·연속 일수·변동성이 중요하다면 `get_training_consistency`를 함께 활용할 수 있습니다.

## 완료된 단일 활동 점검

> 이 활동의 존별 체류 시간 분포와 랩 또는 스플릿 요약을 보여 주세요. 저장된 집계 필드만 사용해 페이스가 불균일한 구간을 짚어 주고, 원시 트랙이나 센서 스트림은 요청하지 마세요.

예상 경로: `get_activity` → `get_activity_zones` + `get_activity_splits`.

## 체력 추세와 개인 최고 기록

> 올해 추정 러닝 VO2_MAX 추세, 현재 훈련 존, 그리고 5km 및 10km 개인 최고 기록을 보여 주세요. 추정치를 실험실 측정값으로 표현하지 마세요.

예상 경로: `get_fitness_trends` + `get_training_zones` + `get_personal_bests`.

## 훈련 플랜 이행률

> 최근 8주간의 훈련 플랜 이행 내역을 완료, 건너뜀, 대기 중 워크아웃으로 나누어 요약해 주세요. 이어서 다음 주 워크아웃 목록을 보여 주고 완료율 분모 기준을 설명해 주세요.

예상 경로: `get_plan_adherence` + `list_planned_workouts`.

`get_plan_adherence`는 활동이 플랜과 일치하는지 추측하지 않고 워크아웃 상태를 기준으로 집계합니다. `DONE`만 완료로 집계되며, 미래의 `PLANNED` 워크아웃은 선택한 기간의 분모에 포함됩니다.

단일 플랜 전체를 보려면 `list_training_plans`로 불투명(opaque) ID를 찾은 뒤 `get_plan_summary`로 완료율, 실제 대비 예상 부하, 주간 진행 현황 및 종목 구성을 확인하세요.

## 대회 준비 점검

> 다음 대회를 찾아 관련 훈련 플랜, 최근 부하/폼 신호, 예정된 워크아웃을 검토해 주세요. 부족한 근거를 명시하고, 준비도 지표를 의학적 판단이나 대회 출전 가능 판정으로 단정하지 마세요.

예상 경로: `list_competitions` → `get_competition` → `list_training_plans` / `get_plan_summary` → `get_training_readiness` → `list_planned_workouts`.

MCP 프롬프트를 지원하는 클라이언트에서는 전체 문장을 복사하는 대신 `race-preparation-check`를 바로 선택할 수 있습니다.

## 동기화 문제 해결

> Strava 연동을 확인해 주세요. 완료된 활동 가져오기와 내보내기가 사용 가능하고 자동화되어 있는지, 최근 동기화에 오류가 있는지 알려 주세요. 계정 ID나 원시 오류 텍스트는 노출하지 마세요.

예상 경로: `get_integration_status`.

## 건강 맥락(별도 동의)

> 건강 접근 권한을 승인한 뒤 최근 14일간 확인 가능한 컨디션 변화를 요약해 주세요. 누락된 값을 표시하고 의학적 진단은 하지 마세요.

예상 경로: `get_health_summary`. `health:read`가 아직 승인되지 않았다면 클라이언트가 토큰을 요구하는 대신 점진적 동의 화면을 표시해야 합니다.

## 어떤 답변이든 더 쉽게 검증하기

프롬프트 끝에 다음 문장을 추가해 보세요.

> 실제로 호출한 TrainingLoad 도구 목록, 각 날짜 범위, 그리고 결론을 뒷받침하는 반환 필드를 함께 나열해 주세요. 누락된 값은 임의로 채우지 마세요.
