# MCP 문제 해결

## 클라이언트가 서버를 찾지 못함

URL이 `/mcp`를 포함해 정확히 `https://api.trainingload.ai/mcp`인지 확인하세요. 클라이언트는 원격 Streamable HTTP를 지원해야 합니다. 사내 네트워크 환경이라면 `api.trainingload.ai`와 TrainingLoad 인증 페이지 모두에 대한 HTTPS 연결이 허용되어 있어야 합니다.

## OAuth가 열리지 않거나 오류와 함께 클라이언트로 돌아감

- 이전 인증 URL을 재사용하지 말고 클라이언트의 연결 기능에서 처음부터 다시 시작하세요.
- 클라이언트가 OAuth 디스커버리와 PKCE S256을 지원하는지 확인하세요.
- 콜백이 인증을 시작한 동일한 클라이언트 인스턴스로 돌아오는지 확인하세요.
- 인증 검증기가 일시적으로 응답하지 않으면 `Retry-After` 간격만큼 기다린 뒤 재시도하세요.

## 특정 도구가 보이지 않음

서버는 계정 이용 권한(entitlement)과 롤아웃 플래그에 따라 `tools/list`를 필터링합니다. `get_health_summary`는 호출 시 점진적 인증을 트리거할 수 있도록 `health:read` 승인 전에도 목록에 유지됩니다. 다른 도구가 보이지 않는다면 계정과 롤아웃 대상 여부를 확인한 뒤 다시 연결하세요. 베어러 토큰을 수동으로 추가하지 마세요.

## `INSUFFICIENT_SCOPE`

클라이언트의 재연결 또는 권한 승인 기능을 사용해 요청된 권한 범위(스코프)를 승인하세요. 클라이언트가 MCP `mcp/www_authenticate` 챌린지를 무시한다면 연결을 제거한 뒤 다시 추가해 의도한 전체 읽기 전용 스코프 세트를 요청하도록 하세요.

## 빈 결과 반환

빈 결과는 해당 날짜 범위에 일치하는 저장 데이터가 없다는 뜻입니다. 훈련 부하가 0이거나 훈련하지 않았다거나 건강/정상 상태임을 의미하지 않습니다. 도구가 반환한 시간대와 조회 범위를 확인한 뒤, 적절하다면 문서에 명시된 상한 내에서 범위를 넓혀 보세요.

## `CAPABILITY_TIMEOUT`, 요청 취소 또는 속도 제한

- `CAPABILITY_TIMEOUT`: 날짜 범위를 좁히거나 `limit` 값을 줄인 뒤 한 번 재시도하세요.
- `CAPABILITY_CANCELLED`: 클라이언트가 요청을 취소했거나 연결이 끊어졌습니다. 새 요청을 시작하세요.
- 속도 제한(Rate limit): 반환된 재시도 간격만큼 기다린 뒤 시도하세요. 짧은 간격으로 반복 호출하지 마세요.

## 클라이언트에 여전히 이전 도구가 표시됨

해당 클라이언트의 MCP 도구 캐시를 새로고침하거나 초기화하세요. ChatGPT에서는 게시된 워크스페이스 앱이 관리자가 업데이트할 때까지 고정된 도구 스냅샷을 유지할 수 있습니다. VS Code에서는 **MCP: Reset Cached Tools**를 실행하세요. 필요하다면 서버를 제거한 뒤 다시 연결하세요.

## 데이터가 안전하지 않아 보이거나 다른 계정 데이터로 의심됨

즉시 연결 사용을 중단하고 TrainingLoad에서 권한을 철회하세요. 클라이언트 이름, 대략적인 시각, 요청 ID를 기록한 뒤 지원팀에 문의하세요. 액세스 토큰이나 전체 페이로드는 절대 공유하지 마세요.
