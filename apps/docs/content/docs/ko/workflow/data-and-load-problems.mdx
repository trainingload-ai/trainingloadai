# 활동, 훈련 부하 및 회복 데이터 문제 진단하기

## 증상부터 확인하기

| 증상 | 먼저 확인할 항목 | 다음으로 볼 가이드 |
| --- | --- | --- |
| 활동이 보이지 않음 | 플랫폼 연동 상태, 가져오기 기간, 파일 상태 | [데이터 연결](/ko/docs/guide/connect-data) |
| 활동이 중복으로 표시됨 | 복수의 가져오기 경로 및 원본 소스 식별자 | [연동 설정](/ko/docs/guide/integrations) |
| 활동은 있지만 훈련 부하가 없음 | 처리 상태, 운동 시간, 심박수·파워·페이스, 프로필 임곗값 | [활동 상세](/ko/docs/guide/activity-detail) |
| 차트나 랩 표시 실패 | 원본 파일에 레코드와 랩 데이터가 포함되었는지 여부 | [활동 파일 업로드](/ko/docs/guide/upload-activity-files) |
| 수면, HRV 또는 안정시 심박수가 비어 있음 | 건강 데이터 권한, 플랫폼 지원 범위, 날짜 및 시간대 | [계정, 권한 및 사용량](/ko/docs/guide/account-permissions-and-usage) |
| PMC가 예상보다 너무 낮거나 높음 | 중복 활동, 누락된 날짜, 선택된 종목, 부하 소스, 임곗값 변경 이력 | [훈련 분석 워크플로](/ko/docs/guide/training-analysis-workflow) |

## 순서대로 진단하기

1. 예상한 데이터 출처와 기간을 확인합니다.
2. 원본 소스가 필요한 센서 스트림을 실제로 제공했는지 확인합니다.
3. 가져오기 및 처리 상태를 확인합니다.
4. 프로필 임곗값과 훈련 부하 소스 우선순위를 확인합니다.
5. 문제가 발생한 활동 1건과 정상 처리된 활동 1건을 비교합니다.
6. 위 단계를 모두 거친 뒤에만 설정을 변경하거나 지원팀에 문의합니다.

## 안전하게 지원 요청 자료 수집하기

활동 날짜, 종목, 출처, 화면에 표시된 상태, 예상 결과 대 실제 결과, 문제 재현 가능 여부를 함께 정리합니다. 이메일 주소, OAuth 토큰, API 키, 정확한 집 위치, 비공개 플랫폼 식별자는 반드시 제거합니다.

원하는 훈련 부하 수치를 맞추기 위해 임곗값을 임의로 수정하지 마세요. 설정 변경은 이후의 해석에 영향을 미치며 파생된 과거 이력까지 바꿀 수 있습니다.
