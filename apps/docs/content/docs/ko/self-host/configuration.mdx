# 셀프 호스팅 인스턴스 설정

설치하기 전에 데이터 저장 위치와 로컬 접속 포트를 결정합니다. 설치를 마친 뒤에는 애플리케이션 설정 화면에서 AI 공급자를 선택하거나 변경할 수 있습니다.

## 시작하기 전에

- 릴리스 번들의 `.env.example`과 인스턴스 스키마에 선언된 설정만 사용합니다.
- 수명 주기 상태를 변경하기 전에는 항상 동일한 인자로 `--dry-run --json`을 먼저 실행합니다.
- `.env.selfhost`, 비밀번호, API 키, 토큰을 채팅, 이슈, 공유 터미널 기록에 절대 붙여넣지 마세요.
- 기존 데이터 디렉터리에는 훈련 기록이 들어 있으므로 수동으로 교체하거나 비우지 마세요.

## 로컬 데이터 경로 선택하기 [#choose-the-local-data-path]

기본 경로는 릴리스 디렉터리 내부의 `./data`입니다. 여기에는 PostgreSQL 데이터, 업로드 파일, 작업 기록, 백업, 캐시가 모두 저장됩니다. 애플리케이션은 이 호스트 경로의 업로드 디렉터리를 `/data/uploads`로 마운트하므로 별도의 오브젝트 스토리지 서비스가 필요하지 않습니다.

최초 설치 전에 다른 경로를 지정하려면 다음 순서를 따릅니다.

1. 검증하고 압축을 푼 릴리스 디렉터리에서 번들 템플릿으로부터 개인 인스턴스 설정 파일을 생성합니다.

   ```bash
   umask 077
   cp .env.example .env.selfhost
   chmod 600 .env.selfhost
   ```

2. `openssl rand -hex 32`로 서로 다른 32바이트 값 3개를 로컬에서 생성한 뒤 `.env.selfhost`의 시크릿 플레이스홀더 3곳을 교체합니다. 일반 설치 프로그램을 실행하면 이 작업이 자동으로 처리됩니다.
3. `SELF_HOST_DATA_ROOT`의 주석을 해제하고 전용 경로를 지정합니다. 예시는 다음과 같습니다.

   ```dotenv
   SELF_HOST_DATA_ROOT=/srv/trainingload-data
   ```

4. 일반 설치 드라이 런을 실행하고 `"ok": true`가 반환된 경우에만 설치를 진행합니다.

   ```bash
   ./install.sh --dry-run --json
   ./install.sh --json
   ```

대상 경로는 아직 존재하지 않거나 이 인스턴스 전용으로 비어 있는 디렉터리여야 합니다. 관리 CLI는 파일시스템 루트, 릴리스 상위 디렉터리, 서명된 릴리스 하위 트리, 안전하지 않은 심볼릭 링크, 무관한 기존 파일이 있는 경로를 거부합니다.

실행 중인 인스턴스의 `SELF_HOST_DATA_ROOT`를 수정해 파일 마이그레이션 대신 사용하지 마세요. 기존 인스턴스를 옮기려면 검증된 백업을 만든 뒤 새로 초기화된 대상 인스턴스로 복원해야 합니다.

## 네트워크 노출 제어하기

기본적으로 루프백 인터페이스에 Client HTTP 포트 하나만 노출됩니다.

```dotenv
SELF_HOST_SITE_ADDRESS=http://localhost:43210
SELF_HOST_HTTP_BIND=127.0.0.1
SELF_HOST_HTTP_PORT=43210
```

다른 빈 포트를 사용하려면 사이트 주소와 HTTP 포트를 함께 변경합니다. PostgreSQL과 Server는 Compose 내부 사설 네트워크에 그대로 유지하세요. 다른 컴퓨터에서 접속해야 한다면 브라우저 오리진을 로컬로 유지한 채 SSH 터널을 사용합니다. 애플리케이션 번들에는 Caddy, HTTPS 포트, Docs 프로필이 포함되어 있지 않습니다.

호스트 설정을 바꾼 뒤에는 공식 수명 주기 진입점으로 검증하고 시작합니다.

```bash
./self-host start --dry-run --json
./self-host start --json
./self-host doctor --json
```

### 로컬 요청 경로

설정한 로컬 주소로 브라우저에서 애플리케이션에 접속합니다. 데이터베이스와 내부 애플리케이션 서비스는 외부 포트를 열 필요가 없습니다. 연결 문제를 해결하려고 이 서비스들을 인터넷에 노출하지 마세요.

## 개인 계정

처음 열 때 사용자 이름을 입력하고 안내에 따라 설정을 완료합니다. 인스턴스 하나는 1인 전용이며 공개 회원가입이나 다중 계정을 지원하지 않습니다.

셀프 호스팅은 클라우드 회원가입이나 소셜 로그인 대신 로컬 계정을 사용합니다. 만료된 로컬 세션은 자동으로 복원됩니다. 계정 삭제를 확정하면 해당 계정의 데이터가 삭제되고 완료 후 다시 사용자 이름 설정 화면으로 돌아갑니다. 백업과 인스턴스 설정 파일은 별도로 관리되며, 계정을 삭제해도 이 파일들은 지워지지 않습니다.

## Intervals.icu 연결하기 [#connect-intervalsicu]

셀프 호스팅에서는 Owner 본인의 **개인 API 키**로 Intervals.icu를 연결합니다. Intervals.icu OAuth 클라이언트, 리다이렉트 URI, 웹훅은 필요하지 않으며 지원되지도 않습니다.

셀프 호스팅은 [Garmin Personal API](/ko/docs/self-host/garmin-personal-api)도 함께 지원합니다. COROS MCP는 활성화되어 있지 않습니다. 두 개인 연동 모두 추가 호스트 시크릿이 필요하지 않습니다.

Intervals.icu를 연결하는 방법은 다음과 같습니다.

1. [Intervals.icu 설정](https://intervals.icu/settings)을 열고 페이지 하단의 개인 API 키를 복사합니다. Client 연결 대화상자의 **API 키 가져오기(Get API Key)** 버튼을 누르면 이 페이지가 바로 열립니다.
2. 온보딩의 활동 가져오기 단계에서 **Intervals.icu**를 선택하거나, 나중에 **계정 → 타사 연동 → Intervals.icu**를 엽니다.
3. API 키를 입력하고 필요한 활동, 예정 워크아웃, 웰니스, 종목 설정 동기화 방향을 선택한 뒤 저장합니다.
4. 수동 동기화를 한 번 실행해 최근 동기화 시각과 가져온 결과를 확인합니다.

[Intervals.icu Open API 문서](https://www.intervals.icu/features/open-api/)에 따르면 모든 사용자는 개인 API 키로 REST API를 호출해 활동 업로드·다운로드, 웰니스 데이터, 예정 워크아웃을 다룰 수 있습니다. 입력한 키는 오직 로컬 Server로만 전송됩니다. Server는 설치 시 생성된 전용 연동 시크릿을 사용해 AES-256-GCM으로 키를 암호화해 PostgreSQL에 저장하며, 이후 어떤 API 응답에서도 평문 키를 반환하지 않습니다.

이 기능은 오프라인 기능이 아닙니다. 활성화하면 로컬 Server가 `intervals.icu`에 직접 연결해 선택한 방향대로 데이터를 읽거나 전송합니다. API 키는 개별 Intervals.icu 사용자에게 속하므로 공용 환경 변수에 넣거나 로그, 이슈, 채팅에 붙여넣지 마세요.

백업에는 암호화된 API 키가 포함되지만 인스턴스 시크릿은 별도의 안전한 위치에 보관해야 합니다. 저장된 자격 증명을 계속 복호화할 수 있도록 데이터베이스를 복원할 때 원래의 인증 및 연동 시크릿도 함께 복원해야 합니다. 관리 도구는 이 시크릿들을 출력하거나 내보내지 않습니다. 전체 절차는 릴리스 번들의 `BACKUP_RESTORE.md`를 참고하세요.

## 클라이언트에서 AI 설정하기 [#configure-ai-in-the-client]

AI는 기본적으로 비활성화되어 있습니다. 마지막 온보딩 단계에서는 Trainingload.ai 클라우드 공급자 동의 화면 대신 BYOK AI 설정 화면이 바로 제공되며, 건너뛰고 나중에 설정할 수도 있습니다.

1. 로컬 Client를 엽니다.
2. 온보딩 중 **AI 서비스 설정(Configure your AI service)**을 열거나, 나중에 **설정 → 셀프 호스팅 AI(Settings → Self-hosted AI)**를 엽니다.
3. OpenAI, DeepSeek, OpenRouter, DashScope 또는 **사용자 지정 OpenAI 호환(Custom OpenAI-compatible)**을 선택합니다.
4. 처음 설정하거나 공급자를 변경할 때 공급자 API 키를 입력하고 표준 모델과 추론 모델을 모두 지정합니다. 기본 내장 공급자는 Base URL을 비워 두면 기본 엔드포인트를 사용하지만, 사용자 지정 OpenAI 호환 공급자는 반드시 Base URL을 입력해야 합니다.
5. 저장한 뒤 AI 기능을 하나 열어 요청이 정상 동작하는지 확인합니다.

반드시 공급자가 실제로 지원하는 모델 식별자를 입력하세요. 원격 Base URL에는 HTTPS를 사용해야 합니다. 사용자 지정 LAN 모델 엔드포인트에 HTTP를 사용하는 것은 해당 네트워크 경로를 완전히 이해하고 통제할 때로만 제한하세요.

OpenAI API 키는 ChatGPT Plus 또는 Pro 구독과 별개입니다. ChatGPT 구독은 API 키로 입력할 수 없으며 이 인스턴스의 API 사용량을 포함하지 않습니다.

### 키 저장 방식

- 브라우저는 키를 오직 로컬 `server`로만 전송합니다.
- 서버는 인스턴스 인증 시크릿에서 암호화 키를 유도해 공급자 키를 AES-256-GCM으로 암호화하여 PostgreSQL에 저장합니다.
- 이후 API 응답은 키가 설정되어 있는지 여부만 반환하며 평문 키는 절대 돌려주지 않습니다.
- 애플리케이션에서 저장한 AI 설정은 즉시 적용되며 환경 변수 설정보다 우선합니다.
- **없음(None)**을 선택하면 저장된 공급자 자격 증명이 삭제되고 AI가 비활성화됩니다.

데이터베이스를 복원할 때는 원래의 인스턴스 인증 시크릿을 함께 복원해야 합니다. 다른 시크릿으로는 기존 AI 자격 증명이나 인증 상태를 복호화할 수 없으므로 재시작 전에 원래 설정을 확인하세요.

### 호스트 외부로 전송되는 데이터

AI를 꺼 둔 상태에서도 활동, 훈련 플랜, 분석 기능을 모두 사용할 수 있습니다. 외부 AI 공급자를 활성화하면 질문과 응답 생성에 필요한 훈련 정보가 해당 공급자에게 전송됩니다. 먼저 공급자의 데이터 보관, 개인정보 처리방침, 저장 지역, 과금 약관을 확인하세요.

셀프 호스팅은 Trainingload.ai 클라우드 멤버십이나 AI 크레딧을 사용하지 않습니다. **AI 사용량(AI Usage)** 화면에서는 본인 공급자 사용 시 과금 방식을 안내합니다. 실제 API 사용량, 잔액, 청구서는 해당 공급자의 대시보드에서 확인하세요.

## 공개 파일 도구용 선택 진단 설정

`.env.selfhost`에 `PUBLIC_FAILED_UPLOAD_CAPTURE_ENABLED=true`를 설정하면 공개 파일 도구에서 서버 오류가 발생했을 때 원본 파일을 보관합니다. 기본값은 `false`입니다. 보관된 파일에는 GPS 등 개인정보가 포함될 수 있습니다. 이 파일들은 `data/operations/public-upload-failures`에 저장되며 백업에서는 제외되고, 72시간이 지나거나 용량·개수 한도에 도달하면 자동으로 정리됩니다.

## 자동 프로비저닝용 환경 변수 폴백

무인 자동 프로비저닝을 위해 릴리스 스키마는 `.env.selfhost`에 완전한 공급자 설정 그룹을 정의하는 방식도 여전히 허용합니다. 이는 대화형 기본 경로가 아닌 폴백 수단입니다. Client는 환경 변수 키를 노출하지 않으며, 환경 변수 기반 설정에서 Client 관리 설정으로 전환할 때 Owner가 새 키를 직접 입력해야 합니다.

## 검증하기

- 호스트 수준 변경 후 `./self-host doctor --json`이 `"ok": true`를 반환합니다.
- 데이터 루트에 인스턴스 마커와 예상 하위 디렉터리가 존재하며 무관한 파일이 없습니다.
- AI 설정 페이지가 인스턴스 Owner에게만 표시됩니다.
- AI 설정을 저장하면 입력 필드가 비워지고 키가 설정되었다는 상태만 표시됩니다.
- 셀프 호스팅 타사 연동 페이지에 Intervals.icu와 Garmin Personal API(OAuth가 아닌 API 키 방식)가 표시되며, COROS MCP는 사용 가능으로 표시되지 않습니다.
- **AI 사용량(AI Usage)** 페이지에 멤버십 결제, 크레딧 잔액, 크레딧 팩이 표시되지 않으며 `/billing/*` 엔드포인트를 호출하지 않습니다.
- Intervals.icu 키를 저장하면 입력 필드가 비워지고 마지막 4자리만 표시되며 수동 동기화가 성공합니다.
- AI를 비활성화하면 비-AI 기능에 영향을 주지 않고 외부 공급자 호출만 중단됩니다.

## 문제 해결

- **데이터 루트가 거부됨:** 릴리스 트리 외부에 비어 있는 전용 경로를 선택하세요. 마커나 심볼릭 링크 검사를 우회하지 마세요.
- **AI 설정 섹션이 보이지 않음:** 셀프 호스팅 인스턴스인지, 그리고 생성된 Owner 계정으로 로그인되어 있는지 확인하세요.
- **새 공급자를 선택할 때 키를 다시 요구함:** 공급자를 변경할 때는 의도적으로 새 자격 증명을 입력하도록 설계되어 있습니다.
- **복원 후 AI가 작동하지 않음:** 재시작 전에 원래의 인스턴스 인증 시크릿을 복원하세요.
- **복원 후 Intervals.icu가 작동하지 않음:** 데이터베이스와 함께 원래의 연동 시크릿이 복원되었는지 확인하세요.
- **상위 공급자에서 모델을 거부함:** 공급자 계정에서 정확한 모델 식별자를 복사하고 해당 API 키에 그 모델 접근 권한이 있는지 확인하세요.
