# 셀프 호스팅 인스턴스 운영 관리

인스턴스 운영은 Linux, macOS, WSL2에서는 `./self-host <command> --json`, Windows PowerShell에서는 `.\self-host.ps1 <command> --json` 명령으로 수행합니다. 이 공식 관리 진입점은 릴리스에 포함된 검증, 잠금(locking), 감사(audit) 및 데이터 안전 규칙을 모두 그대로 유지합니다.

## 시작하기 전에

- 설치된 릴리스 디렉터리와 내부의 `.env.selfhost` 파일은 비공개로 유지합니다.
- 자동화 스크립트는 사람이 읽는 메시지 문구가 아니라 JSON의 `ok`, `exitCode`, `error.code`, `details` 필드로 결과를 판단하세요.
- 상태를 변경하는 모든 작업을 실행하기 전에 동일한 명령을 `--dry-run` 옵션으로 먼저 실행합니다.
- `docker compose down -v`를 실행하거나 수명 주기 마커를 삭제하거나 데이터베이스를 수동으로 다운그레이드하지 마세요.

## 상태, 헬스 체크 및 로그 확인

```bash
./self-host status --json
./self-host doctor --json
./self-host logs --tail 200 --service server --service client --json
```

`status`는 제한된 크기의 런타임 스냅샷을 반환합니다. `doctor`는 신뢰된 설정, 호스트 리소스, 데이터 경로, 데이터베이스 상태, 준비 상태(Readiness), 활성화된 공급자를 종합적으로 점검합니다. 로그는 자동 마스킹되고 분량이 제한되지만 업무 데이터가 포함될 수 있으므로 공유하기 전에 반드시 직접 내용을 확인하세요.

## 시작 및 중지

```bash
./self-host start --dry-run --json
./self-host start --json

./self-host stop --dry-run --json
./self-host stop --json
```

중지(`stop`) 명령은 컨테이너, 설정, 영구 데이터를 모두 보존합니다. 데이터를 유지한 채 런타임 리소스만 정리하려면 문서화된 `uninstall` 절차를 따르고, 볼륨을 수동으로 삭제하지 마세요.

## 검증된 백업 생성하기

```bash
./self-host backup --output weekly-<yyyy-mm-dd> --dry-run --json
./self-host backup --output weekly-<yyyy-mm-dd> --json
```

백업에는 PostgreSQL 논리 덤프와 원본 업로드 파일이 포함됩니다. 캐시, 진단 번들, 부트스트랩 토큰, TLS 비공개 상태, 로컬 고도 데이터, 시크릿 값은 제외됩니다. 생성된 백업 번들은 호스트 외부의 암호화된 저장소에 보관하고, 주기적으로 깨끗하게 격리된 대상 환경에서 복원 테스트를 수행하세요.

## 안전하게 복원하기

복원은 반드시 원본 데이터베이스와 업로드 디렉터리가 비어 있고 새로 초기화된, 동일한 정확한 버전의 대상 인스턴스에서만 수행합니다.

```bash
./self-host restore /secure/path/to/backup --dry-run --json
./self-host restore /secure/path/to/backup --json
./self-host doctor --json
```

현재 실행 중인 인스턴스를 덮어쓰지 마세요. 복원에 실패하면 불완전한 대상 인스턴스가 정상인 것처럼 시작되지 않도록 차단 마커와 리포트가 남습니다.

## 업그레이드

업그레이드에는 완전한 서명된 대상 릴리스 디렉터리가 필요합니다. 현재 인스턴스, 대상 릴리스 번들, 호스트 외부에 검증된 백업을 모두 준비하세요. 실제 대상 컨트롤러 기반 업그레이드를 실행하기 전에 현재 컨트롤러와 대상 컨트롤러 양쪽에서 호환성 드라이 런을 먼저 실행합니다.

```bash
instance='/absolute/path/to/current-instance'
target='/absolute/path/to/trainingload-selfhost-<target-version>'

"$instance/self-host" upgrade "$target" --directory "$instance" --dry-run --json
"$target/self-host" upgrade "$target" --directory "$instance" --dry-run --json
"$target/self-host" upgrade "$target" --directory "$instance" --json
"$target/self-host" doctor --directory "$instance" --json
```

데이터베이스 마이그레이션은 전진 전용(forward-only)입니다. 애플리케이션 롤백은 업그레이드 리포트에서 롤백 가능함이 명시적으로 선언되고 이전 이미지를 계속 검증할 수 있을 때만 지원되며, 데이터베이스 자체를 다운그레이드하지는 않습니다.

## 권장 운영 루틴

- 매일: `status`와 디스크 여유 용량을 확인합니다.
- 매주: `doctor`를 실행하고 호스트 외부에 검증된 백업을 생성합니다.
- 모든 업그레이드 전: 대상 릴리스 노트를 읽고 대상 번들을 검증하며, 백업을 확인하고 롤백 선언을 검토합니다.
- 정기적으로: 격리된 대상 환경에 백업을 복원해 Owner 계정, 활동 기록, 업로드 파일이 정상 복구되는지 점검합니다.

## 검증하기

- 상태를 변경하는 모든 작업 직전에 동일한 명령과 파라미터로 `--dry-run`을 실행했습니다.
- 시작, 복원 또는 업그레이드 후 `doctor`가 `"ok": true`를 반환합니다.
- 인스턴스 호스트 외부에 최신 검증된 백업이 최소 1개 이상 보관되어 있습니다.
- 복원 모의 훈련을 통해 백업 파일이 단순히 존재할 뿐 아니라 실제로 복구 가능함을 확인했습니다.

## 문제 해결

작업이 실패하면 반환된 안정적 오류 코드를 보존하고 `doctor`를 실행하세요. 진단 번들은 필요할 때만 생성해 로컬에서 검토하며, 원본 `.env.selfhost`, 데이터베이스 덤프, 업로드 파일, 비밀번호, 토큰, 공급자 API 키는 절대 공개하지 마세요. 다른 작업이 인스턴스 잠금을 점유하고 있는 동안 상태 변경 명령을 병렬로 재시도하지 마세요.
