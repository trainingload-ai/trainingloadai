# 单次活动时间线设计方案

状态为 PC 端实施中，界面规则已按 2026-11-11 的真实活动反馈修订。本文用于开源 Web 版实现，记录日期为 2026-11-11。

## 1. 目标与范围

在一次活动内回答两个问题：

1. 某一刻的配速、心率、步频或功率分别是多少，当时在路线的哪里？
2. 某一圈或某一段训练中，各项指标如何变化，这段对应哪一截路线？

采用已经确认的原型布局。上方是活动路线，下方是从上到下排列的横向图表。所有图共享一个横轴、一根游标和一个选区。参考 [Intervals.icu 活动时间线](https://www.intervals.icu/features/activity-timeline/) 的多图对照方式，页面样式沿用 Trainingload.ai 现有活动详情。PC 标签显示名为「时间线」，放在活动分析标签栏的最后。

| 范围     | 首版                                                                                         |
| -------- | -------------------------------------------------------------------------------------------- |
| 产品入口 | 本轮交付单次活动详情的 PC Web 时间线，移动 Web 作为后续阶段                                  |
| 运动类型 | 跑步、骑行，包括有可用时序的室内活动                                                         |
| 核心操作 | 点定位、固定游标、时间和距离切换、设备圈段与自定义分析分段、拖选同步放大、图表配置与增删排序 |
| 地图     | 有 GPS 时显示全程路线，并联动定位和高亮。无 GPS 时直接显示图表                               |
| 已有分析 | 总览、圈段表、最佳区间、心率和功率等专项分析继续各自提供原有功能                             |
| 后续迭代 | 自动识别间歇、计划与实际分段叠加、自定义计算指标、分享和导出、原生移动端                     |

## 2. 入口和布局

### 2.1 桌面 Web

在现有详情页的「总览」右侧增加「时间线」标签。默认入口仍是总览。选中时间线后，从上到下依次看到已有的活动标题和概要、已有地图、分组行、图表组及共享横轴。地图保留在标签页上方，由活动详情持有一个地图实例。

图表组首行以设备圈段为基础，不再根据心率、功率或配速区间拆分。左侧保留分段标题和编辑入口，不显示设备／自定义来源说明，选项菜单保留时间／距离切换与恢复全程。顶部每段补充时长、距离、平均配速／速度、平均心率、平均功率，以及主要心率／功率区间和占比。

桌面表头使用左对齐的数据栏：首行圈段名称与时长，下一行时间范围与距离，再以三列展示配速／速度、心率与功率。主要区间用简短的 Z 编号、占比和细色条表达，完整名称可悬停查看。选中段使用顶部细线和轻量底色，下方只高亮对应时间范围，左右边界必须与表头一致；未选中的曲线区域保持中性背景。左侧控件参考 client 现有 SelectTrigger、Button 和 PowerStat 的视觉规范：144 像素固定控制列、同行 28 像素指标入口与放大按钮、20 像素读数和基线对齐的单位；纵轴另占 36 像素。表头、曲线、游标和刻度共用这些列宽常量。指标入口在静止状态不绘制实框，悬停或打开时再强调交互。配置 Popover 采用标签／控件两列排布，复用账户页的 ColorPicker 色卡与 Hex 输入。图表使用同一中性底色、较弱的虚线网格和细行分隔，顶部区间色条降为 1 像素；选中段使用中性蒙层和精确边界，避免整列区间色干扰曲线。横轴刻度保持单行并带短刻度线，滚动容器只允许横向溢出，纵向随整页滚动。

每段默认至少 144 像素，选中后至少 208 像素。最小宽度会同步作用于分段、曲线、选中背景、游标和刻度，使用可正反转换的分段线性映射，禁止只拉宽顶部分段。短段扩展后时间或距离刻度可能不等距，统计始终按原始时间边界计算。分段、全部曲线和刻度使用同一个横向滚动容器。只绘制可见窗口内的曲线，纵轴与指标选择器固定在左侧，避免圈段多时创建超宽 canvas。

图表左列将指标配置入口和放大按钮放在同一行，下方显示单位和当前读数，右列显示曲线。各行的绘图区边界一致，共享横轴刻度位于最后一条曲线下方。底部「＋ 添加图表」打开 Dialog，在弹窗内选择本次活动的可用指标，选中后插入新行并关闭。取消弹窗不改变布局，焦点回到添加入口。

```text
活动标题与概要
全程路线图                         ● 当前点
总览   时间线   圈段   心率   …
[分段] [⋯]       [圈段与统计] [圈段与统计] …
[编辑分段]
[海拔 ▾] 62 m    ───────┼────────────
[配速 ▾] 4:20    ───────┼────────────
[心率 ▾] 173 bpm ───────┼────────────
[步频 ▾] 182 spm ───────┼────────────
                  共享横轴刻度
                  ＋ 添加图表
```

### 2.2 移动 Web 后续阶段

当前窄屏走 `MobileActivityDetailSheetContent`，包括独立活动详情和日历活动详情。两处从现有「数据图表」区域进入「时间线」，沿用各自的导航和返回行为。进入后复用同一时间线内容，地图在上、图表在下。退出时回到来源详情，键盘焦点回到入口。

窄屏减少横轴刻度和圈段标签的文字，保留指标名、单位和当前读数。点按曲线定位，拖动底部定位滑块连续查看。区间选择使用圈段或两个边界操作，避免在绘图区截获纵向滚动。打开时间线后，来源详情中的地图实例应卸载或暂停渲染。

### 2.3 视觉与可访问性

- 沿用产品主题、指标颜色、单位制和现有小圆角。颜色用于区分曲线与选区，指标名、数值和选区边界提供同样的信息。
- 图表支持浏览器缩放。绘图区变窄时优先减少刻度，避免遮住数据和当前读数。
- 轴切换、圈段、清除和边界选择使用原生控件或已有可访问组件。绘图区提供可聚焦的定位语义和格式化后的 `aria-valuetext`，箭头键可逐个样本移动。
- 屏幕阅读器只播报固定定位或选区变更，鼠标移动时连续变化的数值保持静默。

## 3. 指标与交互规则

### 3.1 可用指标

| 活动 | 默认顺序                     | 数据来源                                                     |
| ---- | ---------------------------- | ------------------------------------------------------------ |
| 跑步 | 海拔、配速、心率、步频       | `enhancedAltitude`、`speed`、`heartRate`、`cadence`          |
| 骑行 | 海拔、速度、功率、心率、踏频 | `enhancedAltitude`、`speed`、`power`、`heartRate`、`cadence` |

至少有一条可用时序时提供分析入口。可用时序包含至少两个不同有效时间的样本。仅有平均值或最大值的活动继续通过总览查看数据。活动类型按现有详情策略判定。功率沿用现有实测／估算选取规则，并展示来源。跑步配速复用现有速度转配速和单位格式化，曲线在采样缺口处断开。

某指标完全缺失时省略该行。局部缺失显示断线和 `—`。合法零值保留，例如滑行期间的速度、踏频和实测功率。速度为零时配速显示 `—`。

### 3.2 单点和选区

| 操作                                     | 曲线、数值及地图结果                                                                   |
| ---------------------------------------- | -------------------------------------------------------------------------------------- |
| 首次进入                                 | 展示全程，时间轴为默认轴，初始无固定点和选区                                           |
| 桌面悬停                                 | 临时游标同步所有图和地图。移出后恢复固定点，未固定时移除游标                           |
| 点击曲线或键盘定位                       | 固定当前采样时间。地图在该时刻有有效位置时显示标记                                     |
| 桌面横向拖动                             | 拖动中预览选区，松手后提交并同步放大所有图表。地图在提交时更新一次高亮，保留全程视野   |
| 移动端手动选区                           | 先用曲线或滑块定位，再分别设置起点与终点。反向设置时按时间排序，两个边界相同则保持单点 |
| 点击圈段                                 | 用该圈的有效起止时间更新选区。在选择中移动游标时，选区保持独立                         |
| 双击图表、按 Escape 或在选项菜单恢复全程 | 恢复共享横轴范围，并清除区间标注和路段高亮                                             |
| 切换横轴                                 | 保留固定点和选区的原始时间，重新投影横向坐标                                           |

分段模式以 `activity.laps` 为准，显示「第 N 圈」。优先使用 `startTime` 和 `endTime`，缺少结束时间时，可以从已验证的开始时间和 `elapsedTime` 推导。若导入来源用 `timestamp` 表示圈末，先验证该来源的定义。暂停期间的 `timerTime` 与 `elapsedTime` 可能不同。圈段区间裁到活动边界，无效、重叠或零长度圈段应在预处理阶段剔除，详情页原有圈段表继续负责展示其余摘要。

心率和功率区间只参与分段统计及状态标色，不改变分段边界。主要区间按该段内有效采样的停留时间计算，占比为该区间时间除以全部有效区间采样时间，不使用平均值所属区间代替主要区间。阈值左闭右开，最后一区间按服务端规则无上界。合法零功率纳入统计，零心率作为缺失处理；采样缺口不跨越计算。跑步优先以主要心率区间标色，骑行优先以主要功率区间标色，缺少时回退到另一项。

### 3.3 加载、空态与错误

- 活动详情沿用现有处理中、失败及无权限分支。已就绪时优先复用指标可用性查询，初次加载保留紧凑的占位。
- 已有指标可展示时允许立即查看。单项请求失败时提供局部重试，其余图表及定位仍可操作。若所有请求均失败，显示错误和重试入口。
- 全部查询成功但没有可对齐时序时，返回总览即可查看摘要。地图加载和图表加载相互独立，地图瓦片或轨迹失败时保留图表的可用状态。

### 3.4 单条图表配置

点击指标名打开配置 Popover，支持从本次活动可用指标中替换指标、选择颜色、选择 64／86／128／180 像素高度、选择原始数据或 5／10／30／60 秒平滑，以及上移、下移和删除。添加 Dialog 允许重复选择同一指标，以不同配置进行对照。每行拥有稳定 ID，指标替换时保留其位置与尺寸。

平滑只影响绘图，当前读数保持原始采样语义。空值和数据缺口重置平滑窗口。每行另提供与现有图表一致的放大窗口入口，窗口中的图表支持横向拖选放大。主时间线拖选时所有行共用同一缩放范围，切换时间／距离轴仍保存原来的活动时间边界。

### 3.5 分段统计与编辑保存

设备圈段未改变边界时优先展示导入的圈段统计；改名仍保留该统计。自定义或修改边界的分段从原始时序重新计算，平均值按有效采样覆盖时间加权，距离来自同一累计距离索引。缺失值保持「—」，不得把缺少数据表示为 0。估算功率保留估算标记。

编辑 Dialog 支持名称、起止时间、新增到空余区间、从中间拆分、合并下一段、删除和恢复设备圈段。时间允许分秒或时分秒，保留毫秒精度。提交前与服务端都校验有效数值、活动边界、唯一 ID、先后顺序、重叠和至多 512 段。取消不提交，失败保留草稿，公开演示不可编辑。

通过 `GET /activities/:hashId/timeline-segments` 读取 `{ revision, segments }`；`segments: null` 表示沿用设备圈段。`PUT` 提交完整定义和打开编辑器时的 revision，活动归属和就绪状态由服务端验证，在活动写锁中比对版本后原子保存。版本过期返回 409，避免覆盖另一个窗口的修改。定义保存在独立 `ActivityAnalysisSegments` 表，活动删除时级联清理；不修改 FIT、设备 `ActivityLap` 或全活动训练负荷。迁移为 `0024_activity_analysis_segments`，仅新增表和外键。

### 3.6 最佳表现的可配置统计表

「按距离／按时间」切换放在标题区右侧。表头末尾的「编辑列」打开标准 Dialog，支持所有数据列的显示／隐藏、上下排序、恢复默认、取消和应用；至少保留一列。选择按运动类型与距离／时间模式分别存入本机的版本化偏好键，切换模式或刷新后保留。默认显示区间标识、最佳表现、起止／历时和平均／最大心率。

可选项包括区间距离、时间范围、平均配速／速度、平均／最大心率、平均／最大功率、平均步频、步幅、触地时间、垂直振幅、垂直比和温度。只请求已选列需要的指标，复用现有指标查询缓存，不请求 GPS。统计严格沿用最佳区间的经过时间边界：均值按有效样本覆盖时长加权，最大值只计区间内有效覆盖；缺口不跨越、不在尾部外推，缺失显示「—」，零心率剔除而合法零功率保留。缺少可信活动起点时不推测区间位置。估算功率保留标记，单位沿用 client 偏好。

点击每行第一列或最佳表现值可定位对应路线，列的隐藏和排序不改变区间本身或地图联动。表格沿用 client 的中性表头、细分隔线、等宽数字与轻量选中状态，不新增彩色边框或指标卡片。

## 4. 共用时间模型

### 4.1 输入归一化

现有单指标接口 `GET /charts/execute/activity` 返回逐指标的 `rows` 与 `metadata`，行上有 UTC 时间和可选累计距离。现有部分图表调用 `formatTimeToElapsed`，以该指标的第一条数据为零点。时间线必须在整个活动内只选择一次时间原点：

1. 优先使用合法的 `activity.startTime`。缺失时等待本次所需序列首次查询完成，从已取得的有效时序和 GPS 记录中选最早时间，并在本次打开期间锁定。已知活动起点时可以渐进展示各项数据。
2. 内部以整数毫秒表示 `elapsedMs = timestampMs - originMs`。无时区、无法解析或早于活动起点的记录不参与对齐。时区转换只用于显示实际钟表时间。
3. 横轴终点优先从合法的活动结束时间或经过用时确定，至少覆盖可用采样的尾部。忽略明显超出已知活动范围的异常记录，具体容差用仓库样本验证并写入测试。缺少活动边界时采用全部有效采样的首尾跨度。
4. 各序列按时间排序并去重。相同时间同一指标优先保留有效值，多个有效值按稳定顺序取值。空字符串、空值和非有限数先转为缺失，避免 `Number("")` 产生假零。

例子。活动从 `07:00:00Z` 开始，配速从起点开始记录，第一条心率在 `07:00:28Z`。心率曲线从 `0:28` 开始，游标在 `0:15` 时仍可以显示配速和 GPS，心率显示 `—`。

### 4.2 时间和距离互换

- 为整个时间线建立一条按时间排序的累计距离索引。优先读取现有 `distance` 指标序列，使用同一 Query Key。实施时若已有的指标结果携带等价且覆盖完整的距离数据，可以省去额外请求。无论来源，所有图使用同一份索引。
- 相同时间戳只保留一个有效距离。平台段是正常输入，距离回退或重置则视为不可跨越的断点。只在距离索引能形成全活动统一的非递减坐标且存在正向距离变化时提供距离轴。持续回退或重置形成重叠距离区间时回退到时间。
- 时间转距离只在有效连续样本间插值。无覆盖区间不外推。距离转时间使用同一索引，直接从距离轴定位到平台值时固定取最早到达时刻。由时间轴切入距离轴时保留原选中时刻，即使多个时刻映射到同一横坐标。
- 距离轴会将静止期间的时间压到一个位置。若一个选区的两端映射到同一距离，保留时间和摘要，在距离轴上显示单一边界。缺失距离时仍保留游标时间和选区摘要。无法投影的边界或游标先隐藏，恢复时间轴时重新显示。

### 4.3 状态和缺口

```ts
type TimelineRange = {
  startElapsedMs: number;
  endElapsedMs: number;
  lapId?: number;
};

type TimelineState = {
  axis: "time" | "distance";
  pinnedElapsedMs: number | null;
  hoveredElapsedMs: number | null;
  range: TimelineRange | null;
};
```

活动时间是交互状态的唯一坐标。临时拖选边界只存在于当前手势内。切换活动、关闭视图或切换回专项分析时清理时间线状态和地图覆盖层。游标与缩放限定在当前活动视图。图表的指标、颜色、高度、平滑、顺序和横轴偏好按运动类型存储在本机；分析分段按活动保存在服务端，使用独立的版本化布局键。已保存的空布局表示用户主动移除了所有图表，可通过底部添加入口恢复。

读取某指标时从按时间排序的原始序列二分查找。只有最近采样落在当前连续段和允许的采样间隔内才展示数值，禁止跨停顿、无数据段或轨迹分段找最近点。渲染时显式输出断点。时间索引、渲染序列和区间统计共享同一归一化输入，分别按各自用途读取。

## 5. 地图数据与接口

### 5.1 现有能力和差异

[轨迹定位逻辑](../../apps/client/src/components/MapBoxMap/activity-route-focus.ts) 按解码 polyline 的地理累计距离计算标记及路线切片。现有指标上的累计距离来自设备或导入数据，遇到停顿、GPS 缺失、绕行和传感器误差时可能与几何距离不同。现有最佳区间分析继续使用其原有定位方式。时间线按真实采样时间定位，同一位置经过两次时仍能区分两个时刻。

[现有单活动地图接口](../../apps/server/src/api/activity/activity.controller.ts) 主要返回 polyline 和视野信息，缓存后的 polyline 没有逐点时间。通用指标读取还会对指标值保留两位小数，不适合读取定位坐标。

### 5.2 拟新增只读接口

建议使用 `GET /activities/:hashId/timeline-track`。现有地图预览继续用原接口，时间线激活且地图可用时才请求带时间的轨迹。服务端在现有 Activity 模块中校验活动归属和就绪状态，通过 [SensorDataService](../../apps/server/src/sensor/sensor-data.service.ts) 从对应 record Parquet 读取 UTC 毫秒、GPS 经纬度及可用的分段标识。只查询所需字段，沿用原始坐标精度和现有活动访问规则，公开演示保持只读。

```ts
type TimelineTrackPoint = [
  epochMs: number,
  longitude: number,
  latitude: number,
];

type TimelineTrackResponse =
  | { status: "available"; segments: TimelineTrackPoint[][] }
  | { status: "unavailable"; reason: "NO_TRACK" | "TOO_FRAGMENTED" };
```

- 每段按时间升序排列，每点须有合法时间和坐标。分段首先沿用记录里的轨迹分组（如 `lapIndex`），再在明确的 GPS 缺口、时间中断或无法连续定位处切开。先在原始采样上识别缺口，再做抽样。单点段只在精确匹配时显示位置，绘线需要至少两个点。
- 初始预算为每项活动至多 6,000 个点。短轨迹保留原点，长轨迹分段均匀抽样并保留各段端点。采样覆盖完整活动，尽量在 DuckDB 查询侧完成分段和采样，再将结果返回 Node.js。若有效分段的端点本身已超预算，返回不可联动状态，保留已有静态路线。
- 每个分段的连续性由服务端在抽样前确定，客户端按分段做二分定位，仅在同一段的相邻点间插值。游标处于段间缺口时隐藏标记。区间跨越缺口时返回多个高亮线段，地图不能画一条直线跨过缺口。
- 就绪活动无 GPS 是正常空结果。服务不可用时客户端保留已有地图和可用图表，不额外增加底部错误工具区。越权及不存在沿用现有活动读取语义，日志避免包含轨迹坐标。
- 除分析分段保存的新表迁移外，不引入离线地图包、后台作业或新瓦片服务。地图 provider 继续使用 [Self-host 地图配置](../self-hosting/maps-and-elevation.zh.md)。

### 5.3 地图渲染

有效 GPS 返回后，时间线地图的全程线和选区线使用同一份分段坐标，避免在不同采样版本上叠加。复用现有 MapLibre 组件、地图样式和手势。选区内的线加粗，选区外的路线淡化，起终点仍可辨识。拖动游标只更新标记位置。提交或取消选区只更新覆盖层，不自动调用 `fitBounds`。退出时间线时恢复普通详情地图样式及交互。

## 6. 前端职责和性能

| 部分           | 职责                                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 活动详情入口   | 按运动类型和就绪状态决定可见性，复用活动数据。桌面接入 `common-activity.tsx`，移动接入 `MobileActivityDetailSheetContent.tsx` |
| 时间线数据准备 | 复用 React Query 的指标缓存和已有单位、来源口径。组装一次共用时间原点、距离索引、圈段和各指标的有效采样                       |
| 时间线视图     | 持有交互状态，处理共享横轴、图表定位、选区和摘要。复用 uPlot 的渲染和现有指标样式                                             |
| 地图适配       | 将当前时间及选区映射为标记、分段高亮坐标，复用地图实例。与既有 `ActivityPeakMetric` 区间保持不同语义                          |
| 服务端读取     | 在现有 Activity 权限边界内查询有限的 GPS 序列，返回连续分段。详细时序和既有地图 API 保持兼容                                  |

共用时间线单独负责绘图联动。总览里各独立图表的 tooltip、放大视图和个性化设置继续复用现有行为。时间线在标签激活时才加载图表和轨迹专有数据，重复进入同一活动时复用缓存。指标失败按行隔离。切换活动时不使用上一活动的 placeholder 或保留其路线覆盖层。

界面文案进入现有 `packages/messages/client-core`，用已有的单位制和时间格式化函数。超过一小时的时长显示为 `H:MM:SS`。

曲线仅在可见横向窗口内绘制，点数随可见绘图区宽度收敛。抽样保留局部极值、数据断点和首尾边界，游标读数仍从原始序列查找。共享横轴只计算一次。指针更新在一帧内合并，避免每张图分别触发查找、React 全树渲染或地图重新解码。用 4 小时以上的活动测量请求大小、首屏可交互时间和拖动表现，随结果附上测试机器和浏览器。交互阶段应无新增请求，桌面基准设备上游标更新的第 95 百分位耗时以 33 ms 为首轮目标。

## 7. 验收矩阵

| 场景                                            | 验收结果                                                                       |
| ----------------------------------------------- | ------------------------------------------------------------------------------ |
| 有完整 GPS 和 4 条时序的跑步                    | 点击任一图表后，所有曲线在同一横坐标读值，地图标记与原始时间点匹配             |
| 有功率和踏频的骑行                              | 速度与踏频使用骑行单位。滑行零值显示，估算功率的来源清楚                       |
| 心率晚 28 秒开始                                | 曲线从 `0:28` 开始。之前的游标仍可显示其他有效读数                             |
| 选中设备圈段后切换横轴                          | 选区起止时间和路线不变，绘图区位置跟随新坐标                                   |
| 暂停 90 秒，累计距离不变                        | 时间轴保留停顿，距离轴平台选择有确定结果。切换回来仍可恢复原始选区             |
| GPS 有中断，其他传感器持续                      | GPS 缺口内无定位点，心率等仍可读。跨缺口的选区不连线                           |
| 路线折返，两次经过同一位置                      | 两次定位的时间和指标独立，选区只覆盖所选的一次                                 |
| 室内骑行，有虚拟距离和功率                      | 可切换时间和距离，地图省略                                                     |
| 室内跑步，无累计距离                            | 使用时间轴，距离切换和地图省略                                                 |
| 旧活动缺时间戳、圈段或只有摘要                  | 可用部分可查看。无法对齐的序列和圈段省略，只有摘要的活动继续走现有详情         |
| GPS 查询失败，切换活动时有请求在途              | 可用图表照常工作，地图降级为静态路线。旧请求不会让新活动显示旧标记             |
| 无地图 provider、演示访问或跨用户请求           | 地图不可用时保留图表。演示模式只读且按既有权限返回，跨用户不可读取轨迹         |
| 超长活动和原始文件不规则采样                    | 轨迹点数受控且保留末端。曲线保留尖峰与断点，操作过程中没有新的数据请求         |
| 1440 px 桌面、390 px 和 320 px 窄屏，浅色和暗色 | 地图和图表同列，标签与刻度可读。触屏垂直滚动正常，键盘能完成轴切换、定位和选区 |

已有 `conversion-gps.fit`、`conversion-partial-gps.fit` 和 `conversion-indoor.fit` 可验证导入路径。用合成时序补充延迟采样、重复距离、分段定位和并发切换的确定性测试。预览时使用仓库样本或本地授权的测试活动，不把真实用户轨迹加入公开 fixture。

## 8. 实施顺序与交付

1. **验证数据契约。** 在独立开源 worktree 核对活动起止、圈段时间、距离单位、实际 GPS 分组及权限规则。先做时间和距离索引、缺口判定、GPS 切片的纯函数测试。记录样本覆盖和误差，以此确定缺口阈值。
2. **接入桌面时间线。** 完成共享横轴、游标、设备圈段与自定义分析分段、拖选缩放、图表配置与增删排序。用已有指标查询验证总览和专项分析仍可正常操作。
3. **接入真实路线。** 完成只读 GPS 接口和地图适配。对照 FIT 原始采样时间验证标记与路段，覆盖部分 GPS、跨圈选区和无地图配置。
4. **接入移动 Web。** 复用同一数据模型和图表组，验证活动详情与日历的入口、返回和触屏边界设置。
5. **验证并提交开源 PR。** 从开源仓库的 `origin/main` 核对基线，使用 `codex/activity-timeline` 工作树。检查改动仅进入 Public Core，跑消息键和边界检查、服务端和客户端测试及 Self-host 构建。PR 保留必需的 `core` 和 `docs` 检查，由维护者合并。

```bash
pnpm install --frozen-lockfile
pnpm prisma:generate
pnpm boundary:check
pnpm messages:check
pnpm selfhost:docs-contract
pnpm --dir apps/client typecheck
pnpm --dir apps/server test:core
pnpm test:selfhost
pnpm build:selfhost
```

首版通过的关键条件是，同一选区在时间、距离、各曲线和地图中指向同一段实际活动。任何一项缺少可靠数据时，其余视图仍能工作。
