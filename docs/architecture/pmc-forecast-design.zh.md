# /pmc 未来四周预测

本版在独立分支 `codex/pmc-forecast-design` 实现只读预测接口、`/pmc` 页面与 AI 教练上下文。已 rebase 到合并最大摄氧量预测 PR #43 后的 Public `main`（`714cc3a`）。PMC 与最大摄氧量预测共用指标详情和教练入口，分别使用各自的数据与算法。没有数据库迁移，也不把预测写入历史 PMC。

## 产品与页面

页面只保留标题、右上角运动筛选与“问教练”、三个当前指标卡，以及一组共享时间轴的图表。桌面和手机均将运动筛选与教练入口并排。

图表提供“状态 / 体能 / 疲劳”三个切换项，分别对应 TSB、CTL、ATL，默认显示状态。下方保留每日负荷，两部分使用各自的纵轴。历史为实线，未来为同色虚线并标为“预测”；今日边界和淡背景区分未来。切换时主图显示对应曲线，避免重复图表。保留产品语义色及共享组件。

图表下方没有常驻日期读数、依据、数据时间、周汇总或折叠说明。日期、每日负荷、三个指标以及该日来源放入图内提示，支持悬浮、点按及左右方向键，Escape 关闭。未知指标显示 `—` 和“暂无预测”。当前卡始终代表实际记录，不随光标改变，也不展示四周对照或增长箭头。

普通访问默认最近 60 天历史及未来 28 天，按已排训练与近期习惯自动取得未来负荷。不显示历史范围、预测方式和刷新控件。共享链接仍可保留 `scenario=AUTO|HABIT|REST`、`historyDays=60|90`，让教练讨论的情景与页面一致。

首次读取失败显示简短错误和重试；刷新失败保留已加载数据，只在图表标题旁提示，原结果时间可从提示查看。没有训练记录时显示空态。历史不足、计划缺负荷时保留历史，未来曲线只画有依据的连续部分。

## 首页指标详情

首页的疲劳、体能、状态详情使用同一个只读预测接口及共享图表。仅在弹窗打开时查询，7/14/30/60 天控件同时裁剪历史与预测，分别展示未来 7/14/30/30 天。详情请求 30 天的实际递推结果，主 `/pmc` 页面保留 28 天默认范围。标题下的大数字来自同一范围的实际当前值，不使用未来终值。冷启动、缺负荷及未知日期仍按主页面规则断线；首次失败可重试，缓存失败保留原结果。其他指标的历史弹窗保持原有数据路径。

体能使用 `--sky-500`，疲劳使用 `--violet-500`，与首页进度条一致。状态曲线使用前景色保持对比，背景沿用首页状态条的六段阈值与主题颜色，以低透明度绘制当前纵轴范围内的区间，并在色块右侧显示现有状态名称与阈值；不改变已有阈值。卡片、弹窗标题、图例及提示统一使用这些主题变量。图表使用浅中性背景，暗色使用对应主题表面，取消弹窗里的重复卡片背景、图表 Logo 以及标题下重复的指标图例，保留已记录/预测的线型说明。

## 统一公式

复用 `pmc-formula.ts` 中的指数递推，默认时间常数为 CTL 42 天、ATL 7 天：

```text
CTL[d] = CTL[d-1] × exp(-1/42) + L[d] × (1-exp(-1/42))
ATL[d] = ATL[d-1] × exp(-1/7)  + L[d] × (1-exp(-1/7))
TSB[d] = CTL[d] - ATL[d]
```

中间值不四舍五入。TSB 从同一路径派生，不能独立预测。没有训练机器学习模型，没有经过校准的概率区间。这些值表示给定负荷安排下的变化，不保证用户完成训练，也不代表最大摄氧量、FTP、比赛成绩或健康状况的变化。

`banister.ts` 的成绩响应拟合不承担本版 PMC 预测。保留本产品同日 CTL−ATL 口径，不切换为 TrainingPeaks 的昨日差值。

## 每日负荷

- **AUTO**：有有效已排训练的日期采用计划负荷；无安排的日期，在历史合格时用习惯基线补齐。同日不相加整日习惯和计划。明确估计为零的安排保留零。
- **HABIT**：最近四个完整 ISO 周的同星期记录负荷中位数，重复四周，不加增长率。
- **REST**：从现在起新增负荷为零，保留今日已经完成的实际负荷。

习惯基线要求四个完整周、最近 14 天内有训练且窗口内没有已知负荷缺口。四周同星期中位数全部为零、但确有近期训练时，返回 `IRREGULAR_HISTORY`，避免把不规律训练错误解释为停止训练。没有记录的日期按零记录负荷处理，这不证明用户实际休息。

未排课不等于休息。没有可用习惯时，该日保持未知；计划无法估算也保持未知，不用习惯覆盖。首个未知日后停止所有 CTL/ATL/TSB 数值，后续已知每日负荷仍可单独显示。

已排训练仅包含属于当前用户、处于 `PLANNED`/`IN_PROGRESS`、父计划为 `ACTIVE`/`SCHEDULED` 或独立安排的日期。完成、跳过、暂停、草稿和移动后的旧安排不进入未来。优先使用既有负荷快照；缺少快照时通过现有 `PlanLoadEstimatorService` 只读估计，不持久化。多个有效安排按日相加，任一个未知则当日未知。

## 当前、日界线和基线

日期按用户时区的自然日组织，日期加减采用 UTC 日期键计算，避免夏令时造成一天偏移。`asOf` 是读取截止时刻，未结束活动不纳入实际负荷。优先使用活动冻结的 `pmcLocalDate`，缺少时使用活动时区及用户时区的既有解析逻辑。

从昨日终值推进今日一次：

- 当前值只加入截至 `asOf` 的实际负荷。
- 今日日终预测加入实际负荷及剩余计划；关联活动去重并抵扣对应安排。
- 习惯情景的今日总负荷取 `max(今日实际, 习惯目标)`。
- 未来 28 个日期从明天开始，不在今日当前值上重复推进同一天。

实际负荷通过 `ActivityReadService` 的可读活动边界及 `LoadReadoutService` 取得；未知、负数和非有限数不当成零。重放固定最近 90 天，展示 60/90 天不会改变当前状态。全运动采用更早的权威 PMC 种子；单运动从更早的每日运动分量重放，不能使用全运动种子再改筛选标签。运动范围同时作用于实际、历史、种子、计划和习惯。

未来指标要求至少 42 天的记录基线。旧公式版本种子返回 `BASELINE_VERSION_MISMATCH`，缺失实际负荷返回 `ACTUAL_LOAD_MISSING`，均不展示精确未来指标。接口保留原因及来源供教练读取。单次读取超过活动 10,000、安排 2,000 或单运动早期行 8,000 的上限时返回稳定的 503 错误，而不截断后假装完整。

## API 与模块边界

`GET /pmc/projection` 接受严格的 `scope=ALL|RUN|CYCLING|SWIM`、`scenario=AUTO|HABIT|REST`、`historyDays=60|90`、可选的 `forecastDays=28|30`（默认 28）。身份来自认证上下文。新增接口消费运动范围；旧 `GET /pmc/data` 的兼容行为没有在本次修改。

共享契约通过声明的 `@shared/pmc-projection` 导出，包含实际历史、当前值、今日日终预测、未来 28 天、基线、模型版本、来源、覆盖、问题码及 `asOf`。结果内容计算 SHA-256 引用；单纯读取时间变化不改变引用。

`PlanProjectionReadModule` 提供窄的只读计划端口，避免 PMC 导入完整 PlanModule 形成循环依赖。API 查询不执行历史重算或写入计划、PMC。活动或计划变更会使预测查询失效；切换运动使用独立查询键，避免短暂显示另一运动的数据。

## AI 教练

“问教练”预填当前训练负荷、历史变化、未来四周及恢复建议的问题，保留用户已有草稿，不自动发送。显式发送后附带范围、情景、历史窗口与结果引用，不接受客户端提供的身份、预测事实或额外指令。

服务端 `pmc.projection` 工具重新读取当前认证用户的权威结果，引用变化时返回 `contextChanged`。模型摘要保留所有未来日期，历史摘要限最近 14 天。训练分析、指标解读和状态检查技能指引教练结合问题读取训练、恢复和计划，不能只凭 TSB 建议加量，也不能把暂停训练后的高 TSB 解释为体能提高。

## 验证与限制

单元测试覆盖指数衰减、常量负荷收敛、TSB 恒等式、日历/DST、今日推进去重、计划覆盖习惯、零与未知、暂停训练、历史不足、活动范围、截止时间、关联去重、只读估算及客户端上下文过滤。

Playwright 使用明确的合成数据和认证替身，覆盖桌面/手机的正常、有习惯、暂停、部分预测、冷启动、实际负荷缺失、空态、首次网络失败和缓存刷新失败，并验证暗色、运动筛选、键盘、教练上下文、没有浏览触发写入及横向溢出。截图是界面验收证据，不是模型准确性或真实账户联调证据。

后续统计建模应在未来负荷层进行，按历史截止点还原当时可见的数据与计划版本，比较重复上周、四周中位数等基线，滚动评估 7/14/28 天误差。经过校准前不展示概率区间，也不把 PMC 拟合误差称为生理预测准确性。
